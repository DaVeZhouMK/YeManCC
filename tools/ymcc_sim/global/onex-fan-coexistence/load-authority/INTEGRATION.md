# Producer loading integration

This source integrates the explicit-loader candidate, Factory expected-absence contract, and Default TPA/cache pre-load review. It does not approve a complete Host run.

`build-tools.ps1` compiles Harness, JoinedFactoryProbe, BootstrapFixture, STA and MTA using explicit FixtureSource, BootstrapSource and CecilPath inputs. It never starts a producer. The canonical ScopedLoadAuthority and its copy-local outputs must have identical bytes. STA/MTA deliberately set GenerateDependencyFile=false: the independent TraceEntryDependencyContext source requires the tracer deps sidecar to be absent before substituting the exact producer deps file. Do not copy a producer deps file next to a tracer or keep a stale tracer deps sidecar.

The existing global front door forwards `-FanToolLoadPlan` and `-FanToolLoadPlanSha256` through the global CLI, candidate options and the OneX adapter. The direct module equivalents are `--tool-load-plan` and `--tool-load-plan-sha256`. With no plan, run.mjs returns BLOCKED/ONEX_TOOL_LOAD_PLAN_REQUIRED before reading the HC/Host baseline or building a business chain. Starting a producer directly returns 253 before invoking its business Main; the actual entry shims have no static HC/SDK type references and put the business call behind NoInlining. Starting an SDK-free tracer without its policy arguments returns 252.

## Reviewed plan

The JSON schema consumed by tool-policy-runtime.mjs has these fields:

- schemaVersion: 1; repoRoot: the exact absolute integration checkout.
- sources: the exact path/SHA list returned by toolSourceInputs(repoRoot). This includes the current producer/project/helper sources and the three global forwarding files. It excludes bin/obj/Build/deps/fixtures/node_modules directories. A project explicitly importing an excluded or dynamic source, an omitted member, a duplicate Compile item, and subsequent source changes all reject.
- buildInputs: explicit absolute path/SHA pins for generated FixtureSource, BootstrapSource and CecilPath as used in each real build command. They are verified at that build call; no new generated bytes are automatically approved.
- sharedAuthority: canonical absolute ScopedLoadAuthority.dll path/SHA.
- tools: exactly one record for each Harness, JoinedFactoryProbe, BootstrapFixture, STA and MTA. Each has kind and entry path/SHA. Producers and BootstrapFixture have deps path/SHA. Executables have runtimeconfig and helper path/SHA. STA/MTA instead have depsAbsent naming their exact absent .deps.json path. Core and Desktop are fixed to 10.0.11, RollForward=Disable. Relevant assets are checked when that producer invocation is reached, so later Bootstrap output is not falsely required before it is built.
- calls: a nonempty list of {kind, argvSha256, policy:{path,sha256}}. argvSha256 is SHA256(JSON.stringify(originalProducerArgsWithoutDll)). Each exact invocation consumes one unique policy file. Ambiguous/missing/reused invocation declarations reject. The policy is existing ScopedEntryPolicy schemaVersion=2 and must bind the producer entry, exact producer deps metadata, all actually needed managed pins, and concrete ALC registrations. Duplicate metadata paths reject. A partial TPA/static dependency list is not a complete runtime policy.

`installToolPolicyPlan` validates source identity before any ordinary run work. Its route method intercepts the existing shared run callback, including callbacks passed to factory/bootstrap/joined/lifecycle proofs. Harness routes through MTA and JoinedFactoryProbe through STA. The original producer argv, expected business exit and assertions are retained. Each launcher receipt is included in the ordinary protected evidence; consumed policy/producer/launcher pins and source identity are checked again. Every declared invocation must be consumed before the aggregate result can pass.

The plan is an explicit reviewed input, not an auto-whitelist generator. The two finite sample plans in this delivery refer exclusively to self-owned synthetic producer classes. They are not full-run policies. Parent integration must regenerate source and build pins for the final immutable checkout, bind fresh per-invocation artifacts, and review the remaining real terminal boundaries before any full run.
