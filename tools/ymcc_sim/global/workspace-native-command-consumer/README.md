# Native workspace command consumer

Canonical ID: `game-library.workspace-native-command-consumer`. Select the original consumer explicitly; ordinary exports do not add this suite. The original 240000 ms parent limit, 90000 ms compile limit, and 30000 ms link/native execution limits remain.

The suite runs the original 31 host-artwork assertions and 13 command cases on owned files. It exercises the real `executeWorkspaceCommand`, worker plan/commit functions, VDF parser/serializer, staged activation, backup and completion, owned sharing failures, and VDF restoration after localconfig activation failure. Four separately compiled semantic mutations must each trigger their exact original single failure: stale video token, artwork cancellation response, stale plan, and activation rollback. A mutation failure is evidence of detection, not another positive business case.

Current product inputs are copied directly from the selected repository version into a fresh owned compiler tree. Every dynamically discovered product include must match a declared source SHA256 before compilation. Compiler-reported headers and linker libraries must match the exact declared tool inputs. Test terminal changes are reversed and compared with the selected original sources; production command and transaction logic remain intact.

Process, registry, shell and network terminals stay denied. Three exact configuration names (`YEMAN_GAME_WHITELIST_PATH`, `YEMAN_PLAYER_BLACKLIST_PATH`, `YEMAN_SYSTEM_BLACKLIST_PATH`) receive paths under the owned `pid-rules` directory, preventing installed-default fallback. Identity corpus is controlled absent; every other environment name is refused with a named diagnostic. The report records which permitted variables were actually queried; an unqueried port is not runtime coverage. An empty managed rule set need not create a whitelist destination.

Failure reports are written before the original terminal and thread safety assertions, so rejected environment calls and incomplete cleanup remain visible as failures. Both translation units use the existing test-only storage mutex isolation. Owned threads must return; real product Main, Steam/user library, actual worker children, GUI/WebView transport, provider/network, process enumeration and physical hardware acceptance remain outside this scope. Other transaction variants and failed-rollback/manual recovery remain untested.

Retain original failures, before/after source and tool identities, exact fault reports, output hashes and total owned cost. A later owner handoff with identical tested source bytes can bind to those results without rerunning. Cached references, plans and source binding do not count as fresh execution. This direct consumer result does not refresh the global index or accept the whole library/full release.
