# Host game-output raw observation consumer

This case executes the current Host parser, dispatch, preparation/release/stop wrappers, serializer and actual bounded observation class through the existing shared offline consumer fixture. The SDK event surface is an inert test boundary matching the locked Core contract. It does not construct HMContext or HMController from that SDK, start the product Host, read PnP or write a device.

Release and Debug each retain 23 observation groups, 19 current lifecycle groups and the original 57 legacy cases, including the three historical persona/profile rejection-expectation failures. Ten reviewed source faults compile in Release and must exit 1 at their designated actual business assertion. Compilation errors, crashes, stale source, missing results or failures in an unrelated group do not count as a caught fault. The first pre-fix missing-observation, candidate JSON failure, initial revocation-fixture miss and concurrent-source-change receipts are separately retained in the task outputs; historical receipts are never presented as execution of this case.

The callback copies at most 256 bytes into one coalesced raw observation. Wrong sender, stale binding, old generation, QUIESCE, release, failed admission, failed subscription/detachment, source overwrite, packet oversize, failed response and exact tuple fields are covered. A separate helper concurrency scenario exercises a copied callback after revocation. No-event response and callback allocation/cost observations are recorded locally; the case never derives whole-process CPU savings.

A coalesced raw observation is not a complete protocol transcript or a motor queue. protocolDecoded, gameFeedbackForwardingProven and physicalAcceptance remain false. The three personas have different locked output contracts; no generic decoded event is assumed. CPU/GPU metadata and current CPU/TDP consumers are unchanged. User-excluded wake-password settings UI is outside this module and is not a remaining capability gap.

The source and tool snapshots are verified before and after execution. The Core DLL is hashed as a pinned artifact only; the separate compile-only evidence is not claimed as runtime SDK or hardware proof. Global ownership and process completion use the existing runner/Job path. Shared registration belongs to the coordinator; this leaf does not import itself into extra-adapters.
