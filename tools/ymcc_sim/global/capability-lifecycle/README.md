# 能力退出与持续类恢复验收

2026-10-22 用户要求：退出时必须销毁功能；AI 根据实际资源所有权和跨事件存活行为判断功能是否持续运行，持续类只有在可自愈时才可放行。首批针对监控通知与 Decky。

`index.mjs` 是现有全局模拟器的证据验收门，不新建产品模拟器。实际消费者适配器声明 `lifecycleContract`：功能 ID、`persistent` / `one-shot` / `unknown`、具体分类理由、产品源码、资源种类和必需结果文件。不能把未判断项默认为一次性功能。拥有常驻窗口、订阅、定时回放、采样、后台会话或跨睡眠连接的功能应按持续类审查；函数名为 start/stop 或保存 ON 本身不是证据。

所有功能需证明：

- 正常退出后，自有窗口、定时器、订阅、工作线程/子进程等对应资源确已清零，所有权已撤销，退出有时间上限。
- 正常关闭失败或挂起时，已实际走过只针对自有资源的有界兜底销毁，并再次观察资源清零。发出 close/stop、隐藏窗口、取消引用或父测试进程退出不能代替销毁证据。
- 停止后实际投递晚到回调，功能不得重新创建。重复关闭应幂等。
- 用户主动 OFF 后，即使收到恢复/连接/电源回调，也不得重新开启。

持续类另需证明：

- 用户仍希望 ON 时，睡眠恢复在正式 Ready/当前代次准入后达到可观察的健康终点。requested、connected、保存 ON 或旧 ready 回执不等于恢复。
- 暂时故障可在原有限次数与预算内自愈，不重放未确认的写入。恢复失败应保留明确错误，不能永久等待某节点。
- 用户/致命故障 OFF、崩溃预算上限、会话身份与资源/版本校验仍优先；自愈不授权无限重启、重装或操作非自有进程。

每一项由实际消费者的具名业务 case 对应一条 `lifecycleEvidence.features[].observations`，并记录实际测量。公共门重新读取原 case 内 JSON，核对已登记的结果 SHA、合同指纹、产品与工具当前源码 SHA、case 通过状态及资源/健康测量。没有实际覆盖的要求应缺行或 false，保持未验收，禁止为满足格式捏造测量。

全局 CLI 在 run/log-check 写 `lifecycle-acceptance.json`；full/require-all 还有未分类入口或未验收功能时不能得到成功退出码。带生命周期合同的定向场景也必须过门。无合同的旧定向测试仍只报告原范围的结果，同时明确生命周期未验收。注册回执 audit 同样重新审查；旧 PASS 不会自动获得新增证明。所有原有非零结果、超时、UNKNOWN、覆盖缺口及业务失败原样保留。

软件窗口/进程边界被替换时，只能证明本轮执行过的消费者范围；真实原生销毁、安装程序和物理睡眠需要相应独立证据。该门不授权运行安装版、真实睡眠、设备写入、杀无关进程或部署。桌面执行复用现有环境，现场仍采用普通日志，不生成独立掌机验证包。

验收门单元控制命令（仅验证拒绝伪绿/缺证逻辑，不代表产品通过）：

```powershell
node --test tools/ymcc_sim/global/capability-lifecycle/lifecycle.test.mjs
```

保留第一轮验收门自身的失败与后续修正回执；实际消费者回归另列，不合并成覆盖率。

## 持续功能与原生组件的归属

`lifecycleComponent` 明确声明实际所属 `featureId`、父适配器 `parentAdapterId`、父功能的持续性、组件职责、资源类别、评审理由、真实产品源码与结果文件，并始终保留 `fullPersistentAcceptance=false`。门会核验原执行、当前源码、原始结果SHA、消费者回报的组件身份及产品源码；仅声明或单个进程 exit0 不会得到组件通过。

父功能只有在 `lifecycleContract.features[].requiredComponents` 显式列出组件、原七项退出/恢复要求继续通过、每个组件也有当前源实际通过回执时，才能获得相应的父功能结论。组件不能补造父功能缺失的健康恢复、OFF或故障预算观测。父级未执行、未明确接入组件、源码改变或组件缺证时，保留 `componentIntegrationGaps`，完整验收仍为 INCOMPLETE。新增 requiredComponents 会改变合同指纹；未使用该字段的旧合同指纹形状保持不变。

当前监控通知native lease与Decky owned Runtime按持续父功能的原生组件登记，不再在已真实物化的适配器中误列为“未分类功能”。这不是两个新的一次性功能，也没有自动宣布其父功能完整通过。51项有限控制包含原有门及组件缺证、错误归属、源码漂移、旧合同、误标一次性和用组件掩盖父级恢复缺口等拒绝路径；产品场景回执另记。

## 源码归属导航的换行格式

ownership catalog 仅对经过完整片段审查、显式声明 `lineEndings: "lf"` 的 braced/between 绑定，将实际 CRLF 转成 LF 后核对片段与锚点；未声明的绑定继续核对原字节，整文件绑定不能启用该模式。输出同时记录 `observedRawFileSha256` 和 `sourceNormalization`，因此实际保存格式变化仍有记录。只有换行格式可以等价处理，代码、空白、结构和资源归属改变仍须重新审查；未知规范化选项会拒绝。

这只稳定 inventory/plan 的源码分类与能力导航。正式消费者、编译工具、产物、执行回执及 lifecycle audit 的原始字节身份门没有改变，现有 FAIL/STALE/UNKNOWN 不会因此成为执行通过。回归覆盖换行转换、真实 owner 代码变化拒绝、整文件模式拒绝和未知选项拒绝。
