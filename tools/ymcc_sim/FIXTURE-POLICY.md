# YMCC 测试夹具执行与新增规范

本规范来自 2026-10-23 用户要求，适用于现有夹具维护及后续 AI 协作。当前旧扩建与自动整轮重跑已暂停。产品修复、测试扩建、导出分别按用户明确任务执行。

## 一个入口、一个用例身份

- 项目入口为 `G:\YeManCC-Work\Testing\YMCC\Run.ps1`，正式夹具仍登记在 `tools/ymcc_sim/global`；成本入口复用原登记和原执行器。
- 每个场景只有一个 canonical test ID。追加边界场景优先参数化原用例；不能为同一失败逐轮复制测试器、再包一层父门，或把轮次路径写成正式源码依赖。
- 新增模块或夹具前先查已有 ID、入口、覆盖范围和历史失败。没有新增行为或边界，就复用现有夹具。
- 临时诊断只写核心层 `Evidence/` 或 `Workspace/`，完成后不自动晋升为永久发布门。原失败保留，不批量删除历史。

## 原始结果与交接记录分别保存（2026-11-04）

- 运行器生成的 raw、stdout/stderr、进程／Job 回执和固定任务书一旦被路径、大小、SHA 引用，就作为只读原件保存。新建结果用独占创建（`wx`／`CreateNew`），发现同名文件明确拒绝；收尾不能用 `write_text`、普通覆盖写或后处理摘要替换原运行结果。
- 交接、核收、纠正和当前进度写不同文件，例如 `HANDOFF.json`、`INTAKE.json`、`CORRECTION.json` 或共享状态；不要把它们写回原 `RESULT.json`／`TASK.json`。需要新来源修复时保留前一原件，记录新来源和新运行的独立原件，禁止倒填旧证据。
- 消费端核收必须检查每个关键引用的实际路径、字节数与 SHA，并读取对应原结果；摘要中的逐项 PASS、退出 0 或 stdout 汇总不能代替缺失的原 raw。任一关键引用不匹配时登记 `EVIDENCE_INCOMPLETE`，保留已独立观察的有限终态，不授完整覆盖通过。
- 已发生覆盖时保留事故、现存原件与原费用，不从摘要拼造旧 raw，也不为登记自动重跑。只有确实存在且与原记录身份完全相同的副本才能恢复对应原路径。纠正记录前向追加，不覆盖原 FAIL／UNKNOWN 或已封存交付。

## 最小入口与完整验收

- 日常先按模块生成计划，默认最小集；只运行与改动有关的用例。最小集的覆盖说明必须随报告展示，不能宣称整机或完整模块通过。
- 每个模块在 `optimization/modules.json` 登记最小 ID，通常一至两个现有消费者。需要更多时说明额外覆盖和预计成本；不让最小集随历史失败无界膨胀。
- 完整验收独立显式运行。普通导出默认不跑夹具；导出的构建、来源、包内容和产物身份完整性仍需校验，测试字段必须写 `NOT_RUN` 或原证据引用。
- 禁止通过放宽预算、删除有效断言/负例、把源合同当实际消费、把缓存/跳过当本轮通过来节省时间。


## 精确选择与实际执行范围

- `CaseFilter`、可选宏或定向模式须先确定选中的原场景集合，再执行；未知名称、空选择或不支持的组合沿原入口明确失败。默认整组和显式定向的分支必须互斥，不能先执行默认组再追加所选组。
- 消费端以原始结果核对实际场景名、所属组和数量；存在已声明精确集合时须逐项相等。退出0、`directed`标签、最少数量或汇总PASS都不能证明选择正确。结果混入未选组或漏掉所选项，保存原raw和实际耗时并判失败，停止自动追加执行。
- 复用原回执中的场景列表/计数/选择标记，不创建第二份永久用例表或默认父门；没有精确列表的旧回执保留其原范围，不能补写成当时已经执行了选择核对。新/受影响选择器在本来需要的小入口执行中证明范围即可，不为登记另跑整套。
- 发现夹带重复场景时，原实际执行次数、总墙钟和源码epoch全额保留；误重复不增加唯一覆盖、不退款或重置预算。修正选择器后只在原余量内执行受影响的最小场景，原正常组不因封存或收录再次执行。

本条来自输入C040-C01夹具的真实选择偏差：原Apply28在五次不同选择中执行，四次属于误重复；具体raw和源码epoch由原任务封存。规则不表示全库选择器已自动通过此项，也不新增ID、minimum或发布前置。

## 持续开发与普通导出的来源隔离

- 普通导出使用项目既有的固定主线快照入口，记录本次实际源码、依赖和工具身份。快照冻结后的开发改动属于后继来源，不要求为了追齐导航、测试工具或其它未完成能力再产一个包，也不能把后继修正倒填进旧包。
- 能力接入的源码、生成合同、固定程序集 Pin 和对应消费者是同一交付集合。尚未配套的改动保留在私有候选；交回 `SOURCE_READY` 时列齐这组输入与原最小用例证据。不能只把新消费者接入公共构建，却把必需 Pin／合同留给发布任务临时猜测或盲填。
- 构建失败先按原回执区分编译失败、来源或产物身份拒绝，以及测试失败。某组件两次 publish 均成功而固定 SHA 不符时，保留这次 FAIL，由该组件负责人核实并交回配套来源；不跳过原身份门，不把未完成候选发布为已验收能力，也不自动重复整轮 Build。
- 已完成的 Web、Native 或组件产物保留。仅当原实际源码、工具、参数、依赖与环境仍有可核对身份时，才沿原入口复用对应层；部分编译成功不等于完整 Build 成功，也不能直接获得 Package 准入。发生真实输入变化时重建受影响层，并保留旧来源与耗时。
- 本条不增加默认测试、父门、模块 minimum、全局等待锁或新的发布器。若优化失败发现时机，优先复用同一候选的准备结果，并保留原提升、回读及失败副作用边界；不能为前置发现再执行一遍相同组件构建。

本条依据 2026-11-04 的 `LIGHTING_CANDIDATE_CORE_PIN` 实际失败：Web／主原生已成功，helper 与独立 Core 的 publish 均自然退出 0，但新 Core 与旧 Pin 不符，候选未提升。它不表示当前未完成的机型扩展已通过，也不授权新 Full、部署或真实设备操作。

## 生产器成功后的消费端修复

- 生产器已完整执行且原始回执、实际源码/工具/参数闭包仍可核对，而后置消费者仅因来源声明或派生输入登记遗漏拒绝时，先定位**所有实际消费端**，修正同一合同，不逐层重跑生产器碰下一个验证器。
- 编译进来的派生片段必须从已绑定原源码独立重建，校验精确适配、字节和来源元数据后进入原编译图；不得按文件名豁免未知输入，也不接受任意超集。源码清单按真实闭包补齐，严格集合/逐文件哈希要求保持。
- 修正后置验证器优先读取同一份已完成原始回执，执行受影响的正反控制；这属于本轮验证器实跑、对既有业务证据的引用，不是本轮重新执行业务，也不能倒填旧父门为PASS。历史失败、来源epoch与耗时保持，当前整父仍需相应资格证明。
- 把独立诊断误当必需前置之前，先核当前父门真实消费逻辑与最近实际回执。诊断FAIL/UNKNOWN原样保留，不能因此无界追加发布前置；也不能借诊断标签隐藏实际必需断言失败。
- 真实并行必须先证明可写根/peer资源独立、单producer完整子树可取消并有界等待归还、原始日志与真实进程身份不混淆。外层整个Job的最终兜底或杀root进程不是单producer归还证明。原预算包含启动、取消和封存，不以改名重开同范围预算。

编译工具收尾也须与产品退出分列：仅在实际归属证据确认是已声明、完整路径与SHA匹配的工具驻留进程时，才可沿显式策略回收本方Job，并实际等待活动进程为零。原业务根退出码、强制回收、实际工具身份及收尾结果分别保留，不能冒称自然退出，也不能把按名称匹配、未知残留或产品资源作为工具豁免。普通模式保持原残留拒绝；对应反例必须继续拒绝未知子孙、错误身份和伪造自然退出。已有真实回执与工具假设失败不倒填为绿。

## 身份与缓存

- 身份须包含实际源码、声明依赖及执行时发现的依赖、原参数、运行配置、候选载荷、工具实文件 SHA256，以及执行器/验收器身份。不能只看 mtime、文件名或 Git HEAD。
- 未审清的动态依赖、外部命令或候选目录使缓存不适用。缺失、漂移或坏证据不可命中；报告列出原因。改变共享依赖只失效真正使用该依赖的用例。
- 有效命中写 `CACHED_REFERENCE`、`executedThisRun=false`，保留原回执路径和 SHA256。本轮实际通过数只统计本轮进程真实执行并通过的用例。
- 相同身份的旧 FAIL/UNKNOWN 保留原判定和证据；不自动无限重跑。需要复现时显式要求重跑，修复导致身份变化后再执行对应用例。
- 完整验收需要独立当轮证据时不用日常缓存。缓存不是发布、实机、退出销毁或持续功能恢复的豁免。

## 父子门去重

- 同一执行计划内，相同用例身份只执行一次，其他引用写 `SHARED_REFERENCE` 并关联唯一实际回执。
- 父门已消费的子门，只有入口、参数、源码/工具/载荷身份、作用域和必需负例完全一致，且父门有实际子回执时才能共享。不能按名称相似或一句“父门已通过”省略子门。
- 子门负责自己的行为断言；父门保留编排、预算、真实消费与资源归属断言。父门不能先独立跑一遍孩子，再让孩子内部完整跑第二遍相同测试。
- 工具构建与测试执行分开登记。同身份编译产物可以复用，实际执行与编译缓存分别计数。
- 原生 health 共用统一的冻结源码、显式 x64/console recipe、固定工具环境和原编译/运行回执。外层仅在同次完整父/global 的源码、工具、时窗及原件证明核验后记 SHARED_REFERENCE，并在 Package 再核；缺证或漂移明确失败，不自动另起一次生产器求绿。当前源码/元数据控制不等同于真实完整父链已运行。
- 先后且不重叠的调用允许操作系统复用 PID；用调用原件、程序 SHA 和时序识别，不用跨调用 PID 必须不同的假设。子进程是否超时服从真实终止回执，写日志/哈希使 elapsedMs 多出的收尾不能伪装为子超时；收尾仍计入外层累计预算。
- 完整父验证已核过的整套工具身份不在 health 叶层重复全扫；叶层继续核自身编译器、链接器和依赖图中实际消费的工具/源码。共享原件、缓存引用和本轮实际执行的计数保持分开。

## 失败后的后续执行（2026-11-03）

必需组发生原消费者判定的非预期异常或实际断言失败，验收路径应停止其后续启动，保存原错误、已执行回执与来源元数据，将未运行部分记为NOT_RUN；完整通过仍需原有全部覆盖。不能仅因原合同允许的非零退出或已正确处理的负例就停止。确需收集其余诊断时使用原显式收集入口，保持失败结果和原共享预算，不重试或刷新额度。当前该控制已接原Decky persistent父链；不宣称所有旧父链已自动完成，也不把局部控制通过当完整父链通过。

## 耗时、覆盖及协作

- 可选整组启动前先核已有同入口实跑耗时、源码/工具 epoch、当前累计余量和启动/清理成本。若余量连已有完整实跑成本都容不下，不因定向项刚通过就顺带启动整组；明确记录未启动/未验收，保留已发生费用。历史耗时只作计划参考，不作当前 PASS 或严格性能下界；新的整组执行仍须原授权与足够原预算，不放宽、退款或重开已封存会话。
- 每轮记录计划、身份检查、构建、用例执行、证据校验和总耗时；父耗时包含子段时不能再相加成“总成本”。优化前后比较必须说明相同/不同源身份和覆盖范围。
- 新夹具提交说明：复用检索、唯一 ID、模块、源码/依赖/工具闭包、最小调用、父子关系、输出原件、超时、实际耗时及新增覆盖。没有这些信息不接入自动门。
- 每个 AI 领有界写集合及明确结束条件；不要派重复诊断，不因一个失败自动创建整套新环境或启动新一轮全局验收。
- 广播暂停必须落状态文件并发送给实际协作者；发出消息和已收到停手确认分别记。独立人类授权的现有任务由对应聊天管理。

## 避免过紧与无关重跑（2026-10-30）

- 新增定向入口必须沿实际编译配方估时。只选择一个运行场景并不会缩小完整原生翻译单元；不得把既有300秒完整编译配方未经测量设成60秒，再通过反复超时消耗整份源准备。C01已实测完整三翻译单元编译约98.643秒；恢复原配方上限时仍受该次父级余量和全局最多1800秒约束，不能借此延长已封存的失败会话。
- 编译进程须保存实际elapsed、有效timeout、exitCode、signal、spawn error及ETIMEDOUT；null退出不能只写泛化“compile failed”，也不能判为业务负例。编译成功与场景通过分别登记，未生成完整EXE的对象不作成功构建复用。
- 冻结源码发现编译缺陷时保留旧FAIL、原时间与清单，只取确切依赖修正形成新源码身份；不要为取一个修正同步当前主线的其它独立改动。新源码身份的准备与失败成本累计报告；不改旧manifest、不退款或重置原Full／原关闭组，登记不再重跑已通过控制。


- 行为结果与来源说明分开登记。来源、覆盖及历史记录按存在、身份、内容关联和原判定核验；不得要求保留历史 FAIL 的说明文件报 PASS，也不得省去这些文件的完整性检查。
- 生成切片按名称、原源文件、位置、字节和实际编译引用校验；新切片接入时同步原父合同，避免沿用过时数量误拦。完整生产者的用例数来自实际登记和原始结果，局部汇总不能隐藏新增用例的失败。
- 提取源与实际编译输入分别登记。只取片段的文件保留原文件身份，依赖闭包覆盖片段实际使用的输入；不得递归未参与编译的整份宿主 include 后要求无关模块重跑。实际编译器发现的未声明输入必须拒绝。
- 正常组完整执行一次；mutation 子进程只执行能证明该负例语义的原断言及必要前置，明确报告选择范围和数量。不得每个负例再跑整套无关正常组，不得把定向负例称为全量通过；原时间预算和负例的失败条件保持。

## 2026-10-30 用户授权的持续优化

用户授权在下次发布前尽量完成夹具整改，非紧急，优先服务当前bug任务；CPU优化与HC升级继续保留专项，不阻塞发布。默认发布不展开优化／HC整轮；必要缺陷回归按具体原ID与实际影响选择。所有新证据仍在G项目核心层，不恢复D根轮次。

当前 `Run.ps1 -Optimized` 的统一墙钟上限1800秒，预算在父子、变体和重试间不重置，原用例超时不放宽。源码漂移、超时、缺依赖及未执行分别记录，不能用旧PASS或缓存引用冒充本轮通过。经核心Run.ps1调用的旧域也共享同一预算；绕过核心直接调用底层脚本不能宣称享有该预算。旧域退出码和参数保留，进程退出0不是全部行为验收。

优化只更改原选择、准备和执行机制，复用原有效断言／负例；每项改动用有界定向回归验证，不为测试优化再默认运行完整产品门。模块最小入口必须确实属于所指能力，不能用壁纸覆盖标成Decky生命周期。

先收紧原消费者的实际场景集合和原结果一致性，再补有证据的行为缺口。核收按原场景名/唯一性/语义终态，不只看数量或总PASS；合法顺序变化不单独判失败。保留原断言、负例、时限及全部原件；不得新增重复父门、无限扩大全局ID/minimum或自动发布前置。纯回执校验控制只证明消费者拒绝缺项/重复/错名，不能代签原native/managed实跑或设备释放。独立任务明确互不重叠的写集与预算；不重开已封存的执行账。


## 原生消费者缓存准入与证据完整性（2026-11-05）

大型父夹具的源码提取锚点、实际生成include成员及明显接口形态先在首个重型producer前准入，避免跑完已知长子组才发现静态断线。生产者新增生成include时，原编译图、父层消费图与来源证明必须同步补齐，按精确路径/字节核对，不加入任意生成文件白名单。产品已统一入口时，应编译实际统一函数并保留原生命周期断言，不把旧源码布局当能力合同。

失败后优先只续测失败及尚未到达的阶段，复用前核清原正例来源、工具、原件和隔离边界；这类定向续测单独标记，原父FAIL与原时限保留，不能拼写成一次新的完整父PASS。不得为取绿关闭/WX、减真实观察窗口或从头重跑已证且来源未变的长子组。


证据收集只把原测试声明的源码、编译产物、原始结果和回执纳入证明。对明确隔离的子进程USERPROFILE根，未被业务断言消费的Windows AppData临时状态单独记录排除；不得按任意目录的AppData名称全局跳过。源码、回执、编译输出和profile根本身的重定向继续拒绝，排除记录随原输出固定。

原FAIL/UNKNOWN等非成功终态可在完整输入身份不变时引用，不要求失败运行生成成功专用清单；已有输出仍须固定并复核。PASS继续要求原完整成功清单、原断言和负例。使用main来源投影时，失败引用另须原完整main哈希一致，不能借成功投影证明跨来源沿用失败，也不得因缺成功清单而无条件重新编译失败组。


原生夹具不得只填`closureComplete`/`toolClosureComplete`，也不得加入纯Node白名单。先固定实际编译器/SDK选择和子进程有效环境，或将全部动态选择与脚本链纳入可重算身份；继承环境与未声明的默认版本不得改变实际执行。输出路径需在编译前校验原生工具已验证的长度/所有权类别；不把每轮随机目录名塞入身份而令所有缓存失效。

缓存沿用原identity/selection机制与原ID，只为已审阅消费者刷新只读描述符；不唤醒其它延期工厂、不扩张minimum。存在嵌套原始结果的消费者必须声明原输出清单并核对其全部raw、日志、编译产物身份；缺失、改变、越界或未声明输入均拒绝引用。原FAIL和UNKNOWN不可用父层PASS掩盖。

闭包实现变化后，取得一次对应新来源的原正反基线；再次同身份调用须实证`CACHED_REFERENCE`、零producer/编译、`executedThisRun=0`及`actualPassedThisRun=0`。不能把旧来源回执重新盖成本轮执行。普通导出默认NOT_RUN、完整验收原覆盖/生命周期/单份总预算保持。分别记录执行累计与分析/协作的端到端耗时，不以短子进程耗时代替整个任务时长。

涉及多模块单文件（例如`native/main.cpp`）时，先用原消费者的实际提取／生成代码核对受影响范围；正例和原语义负例的完整编译输入、模板及非主源工具／依赖都须比较。逐字相同只登记原覆盖范围的来源等价证据，不冒充本轮实际执行、正式缓存命中或完整新主线通过。尚未接通并验证源码投影合同前，原整文件身份门保持；不能通过忽略main变化、替换旧raw哈希或复制PASS省时间。对移动中的主线限定观测快照次数，达到限额后保留各来源与未验收项，不为整理记录持续重编译追赶。
