# OneX X2 Windows boundary regression

Run `node tools/hc_onex_x2_windows_selftest.mjs` from the source root. Output is restricted to a fresh child of `Build/Validation/HC-ModelCapabilities-20261017/OneXRuntime/WindowsTests` (the default) or `Testing/YMCC/Evidence` in the outer workspace. `--no-mutations` runs the initial Release/Checked scenarios only; the default also runs the original and completion-specific semantic fault controls. `--vcvars` overrides the discovered local MSVC batch.

The production WindowsTransport, Session, protocol headers are copied byte-for-byte and hash-bound before compilation. The real Windows SDK headers are included before macro substitution. Every production Win32/HID/setup API token maps to a memory-only mock. Fake handles, enumeration sets, buffers, preparsed records, events and pending operations are owned by `mock::World`; no mock forwards to Windows. `OVERLAPPED` is the real SDK type; its Internal field models pending/terminal status and the real HasOverlappedIoCompleted macro remains active. Every wait and GetOverlappedResult blocking argument is asserted. Object symbols and executable imports are checked for escaped device calls. No application, HC binary, Host, hardware, real sleep or driver operation is executed.

Each scenario runs in its own process so one production defect does not hide later boundary results. Mocks retain exact OVERLAPPED/buffer/event/device identities through cancellation until both terminal results are observed. Cancellation never implies completion. End-of-scenario cleanup checks all fake resources. Release uses /O2; Checked uses /Od /RTC1 /MDd and checked iterators; assertions remain enabled in both configurations.

This is transport-contract evidence only, not hardware compatibility, producer publication, Steam consumption or physical sleep/wake acceptance. The parent task owns the independent input-framing source audit and production scope review. A failed production case must be fixed in the header by the parent, not weakened here.

The valid-layout-change regression keeps model/context fixed, checks synchronous revocation and late read/write rejection, then rebinds and distinguishes general versus strict-zero ID handling. Stop regressions explicitly check resource release before any subsequent tick when quiescent, and retention when either read-only or read-plus-write IO is pending. Two additional fault controls independently remove layout retirement or immediate stop finalization to prove those cases fail at their intended semantic checks.

The initialization/status regressions use the actual Windows tick ordering (read service, write service, advance, submit). Initial write terminals occur at 4000/4050/4100ms and, for Mini, 4150ms; input capacity and output length remain independent. An exact-due B8/20 read at 4150ms must schedule the next first page at 4350ms, with no write at 4349ms. Both immediate and pending/observed initial-write completions are exercised. Mini's immediate zero-delay final page leaves initialization unsettled at the end of its submit tick, so the next read at the same 4150ms timestamp must settle it locally. Separate defect controls delete only the status settle call and fail for X2/OXP3 and Mini independently. A further ordering regression and fault control distinguish a write already terminal at the 250ms watchdog boundary from a genuinely pending write: replacing the local settle with full advance in the read callback must be rejected.

Application R3 adds closed-write-gate / permission changing before submission / prepared-ticket withdrawal / bound-path lifetime cases. Read servicing remains independent of write permission. Permission is sampled before submission; this test does not claim atomic exclusion against a concurrent gate change after the final check.

Binding guard regression checks permission before opening the actual owner handle and again after validating it, before event allocation or I/O. A rejected candidate is closed without reads/writes/events; a later stable bind can recover. Two semantic fault variants independently omit each guard. Application tests own the notification journal and epoch behavior.

Resource completion regressions execute the actual WindowsTransport `stop`, `pollRetirement` and const/noexcept `stopped` consumers, and capture a typed exit receipt in the harness. Every API is an explicit memory port. Close failures are configured on owned Object instances, never OS handles. Cases cover quiescent stop; pending read, write and both with cancellation success/failure; elapsed cancellation notice and zero-time waits; one-at-a-time terminal drain (including an unsignaled terminal); device/read-event/write-event/all close failures; retrying the same owner; retained probe close; event-only rebind exclusion; repeated stop, observation and late ticks. Polling a live or unbound requested session performs no I/O or binding. Successful normal ticks retain the existing supported-session recovery policy. A resource-complete observation may be true on an unbound requested session; stop still owns withdrawing the request.

Per-call bounds are API call counts with controlled memory ports, not a wall-clock bound for arbitrary hardware/driver/CloseHandle behavior. A permanently pending operation or permanently failing close must keep completion false and preserve its owner. This suite does not certify an application exit receipt, global lifecycle acceptance, hardware sleep recovery, ROG/GPD/OEM behavior or deployment. Existing failures and UNKNOWN evidence remain unchanged.
