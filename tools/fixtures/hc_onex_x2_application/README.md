# OneX X2 application composition regression

Run `node tools/hc_onex_x2_application_selftest.mjs`. All generated output stays in a fresh child of outer-workspace `Build/Validation/HC-ModelCapabilities-20261017/OneXApplication/Tests`.

The runner extracts byte-exact production functions/data from native/main.cpp and records their ranges/hashes. Real WindowsTransport/Session/protocol headers and the existing Windows mock fixture are copied without edits into the validation snapshot. Windows device APIs, PostMessageW and GetTickCount64 are memory mocks. Fake power/topology/backend readiness is an explicit boundary; no real hardware, input injection, process, app or Host is run.

The actual owner, source ledger, canonical/authority consumers, Mini keyboard profiles/evaluator/recompute, new Home dispatcher, UI drain, shortcut routing, the actual ordinary rear shortcut evaluator, and queued serial-action guards execute together. Backend actions only reach observation sinks. The old ROG dispatcher is an observation stub after byte-exact comparison against main.before-application.cpp. Refresh and unrelated keyboard maintenance/consumption publication are explicit no-op boundaries. The ordinary rear evaluator is now the byte-exact production function; a forwarding wrapper records receipt arguments and invokes it. Saved-setting refresh, MSI mirror/consumption publication, real keyboard/mouse interception and backend action effects remain outside this test.

Release and Checked are compiled. Each scenario runs separately; semantic controls must compile then fail their intended assertion. Production static unused-local/function warnings are suppressed (/wd4189 /wd4505); semantic checks remain enabled in both builds. Both object symbols and EXE imports are audited for escaped device/action APIs. Every old Win32 mock wait asserts timeout zero.

Lifecycle emergency/shutdown/worker wiring is checked from production source and hashed; those hardware-heavy lifecycle functions are not executed. Pending stop drain uses the real owner and transport instead. Evidence proves finite offline integration contracts, not physical buttons, driver takeover, firmware initialization success, sleep/wake or downstream virtual/game consumption.

A memory GetOverlappedResult wrapper observes (then forwards only to the old memory mock) that the real owner has revoked both new source generations, context readiness and queued receipts before servicing an old-context late completion. Additional queue tests cover failed PostMessage retention, preserving other producers through Home overflow cancellation, and recording/exit cancellation at UI and deferred serial boundaries. The original Windows fixture remains hash-bound and unmodified.

The current application uses a dedicated physical-device epoch rather than generic XInput topology. RegisterDeviceNotificationW, UnregisterDeviceNotification and CompareStringOrdinal are also memory mocks; the Windows DBT structs and the exact production HID GUID are retained. Tests execute actual notification registration/retry and exact bound-path observer logic, immediate device-epoch source/token fencing, and continued input across unrelated XInput changes. Notification path comparison fixtures use ASCII paths; this does not certify Windows Unicode collation. No real device notification registration is performed.

The backend hardware-write permission callback is explicitly fake (as permitted for backend readiness), with production WindowsTransport permission checks intact. A denied gate performs no vendor write while preserving the independent read; a gate revoked between preparation and actual write discards only the prepared write, and restored permission can retry it. This is not a test of the global hardware gate implementation or fan isolation state.

Cross-generation hold tests preserve the actual owner's release fence through a real context retirement, pending read drain and rebind. An inherited L4 DOWN cannot create a fresh action, its physical evidence remains separate, and actual UP then DOWN re-arms it. A first-UP-after-rebind path exercises the real Session RearObserved event. Prepare resets the fence only when starting an independent test world; this cross-generation scenario does not reset it between retirement and rebind. The ordinary configured rear shortcut evaluator is covered by the later real-evaluator scenarios, including source-qualified deferred actions.

Real rear-evaluator regressions establish neutral through an actual idle evaluation rather than manually setting rule flags. They cover first L4/R4 actions for X2/OXP3, first new actions after a released reconnect with/without a UI tick in the gap, held-across-rebind with both repeated-DOWN and first-UP paths, rule edits while held, edits before a fresh source, and legacy OneX/GPD/Legion neutral behavior. Four additional compiled controls remove the fresh-edge neutral exception, bypass edited-rule UP, ignore the held release fence, or skip the second actual write-permission check. Fake readiness, refresh, keyboard policy side effects and action sinks do not replace those tested production decisions.

Both exact bound HID arrival and removal are exercised positively, including case-insensitive matching. Wrong path/GUID/event, null payload, wrong device type, too-short/too-large header size and missing in-bounds NUL are rejected without a device-epoch change. Both positive callbacks are memory-only and perform no HID enumeration or IO.

R1/R2 review regressions use current production bodies. R1 is symmetric for X2/OXP3: an old held side survives a generation change, receives opposite UP/DOWN, and still cannot act or form a composite until its own actual UP. R2 injects notifications after enumeration while the candidate is unknown, immediately after the owner open, and after the first synchronous ReadFile returns its memory data but before the owner can publish it. The actual bind-permission callbacks, atomic candidate path and bind-scoped journal are executed. Tests cover 64 unrelated notices (valid), 65 (new bind denied), unrelated overflow during an existing live read (source preserved), and the actual catch clearing observation state. Added controls reintroduce synthetic opposite-side UP arming, drop the unknown-candidate journal, omit candidate path publication, omit the second owner-open recheck, or admit journal overflow. Wrappers only call the original memory mocks; no real Windows notification, open or read is executed.

The posttick generation-change regression completes the first Home read synchronously, then injects a matching removal immediately after the actual source-revoke call for that new Live session. A forwarding wrapper executes the real revoke first; it does not substitute its behavior. Candidate path must survive action-only revocation, the device epoch changes immediately, and the decoded old Home cannot act. A compiled control changes the unique production call revoke(state.phase != Phase::Live) to revoke(true) and must fail because it loses the removal and admits the stale action. Candidate path publication remains exclusively in the real bind callback.
