# Bounded read-only PnP absence proof (127)

`ymcc::targetReturn::pnpAbsence::verify(const std::vector<std::string>& knownExactIds)` returns `Result { State state, Reason reason, unsigned scannedNodes, DWORD win32Error, CONFIGRET configurationReturn }`. `State` is `Unknown`, `Present`, or `Absent`; `absent()` is true only for Absent. A template overload accepts a read-only Reader for deterministic tests. The helper grants no device removal, unhide, ownership, origin, recovery, or parent-chain authority and has no timers, threads, retries, or persistent state.

Absent requires an actual `ERROR_NO_MORE_ITEMS` end after every inspected node was valid and none matched the caller's exact historical IDs or a supported target family. Empty known IDs still require family scanning. Persisted exact IDs still use the existing strict record instance alphabet. IDs returned by the OS census are bounded, well-formed opaque UTF-16 identifiers and use ordinal case-insensitive duplicate detection; they are not parsed as persisted write targets. HardwareIds is still read for every unrelated node, including software devices containing punctuation or non-ASCII characters. Case-insensitive exact matching covers old roots and HIDs. Duplicate historical IDs, repeated devinst or folded instance ID, zero devinst, read/enum/type/size/termination errors, exceptions, and exceeding the node cap return Unknown. The cap is 1024 read nodes with at most one extra end query; a 1025th successful item is Unknown without reading it. At most 1024 known IDs are admitted.

HardwareIds is queried read-only with `CM_Get_DevNode_PropertyW(DEVPKEY_Device_HardwareIds)` into a fixed 16 KiB buffer. `CR_NO_SUCH_VALUE` is a completely observed no-property node; other read failures do not become empty data. Success must be `DEVPROP_TYPE_STRING_LIST`, even bytes, within the buffer, and an entirely valid UTF-16 MULTI_SZ with double NUL for nonempty lists, no hidden junk after the end, no unpaired surrogate or empty interior member. A family in the first member cannot conceal a malformed later member. A canonical empty list is allowed, including the single UTF-16 NUL returned by CM on real Windows LampArray nodes. Empty lists do not terminate the census: later targets and later errors remain significant. Unknown property shapes carry bounded node/type/byte/head/tail diagnostics. Exact instance-ID presence can return Present before an unnecessary hardware-property query; incomplete unrelated nodes cannot yield Absent.

Family matching follows the read-only `InputHost/Program.cs` predicates recorded in the evidence: `ROOT\HIDMAESTRO` and `ROOT\HIDMAESTROXUSB` exact case-insensitive HardwareIds; Steam Deck `USB\VID_28DE&PID_1205` or its `&...` extension after trimming, excluding any `&MI_` interface form. It does not use friendly names, just the observed HardwareIds. The broad family check intentionally blocks even a new epoch or another matching device, without asserting that it is virtual or owned by this caller.

`ProductionReader` is only SetupDiGetClassDevsW with PRESENT|ALLCLASSES, SetupDiEnumDeviceInfo, SetupDiDestroyDeviceInfoList, CM_Get_Device_IDW, CM_Get_DevNode_PropertyW and GetLastError. Consumers supply the usual SetupAPI/CM linkage and DEVPKEY definitions (main already includes initguid before devpkey; the standalone fixture follows that layout). A failed set cleanup also returns Unknown. The helper is one present-set observation, not atomic protection against a later hotplug; lifecycle/writer fencing remains the caller's responsibility.
