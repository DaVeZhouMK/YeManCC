# HC UI dependency reduction

This tool creates two headless-only replacement DLLs. It never writes product runtime/profile/consumer files and never starts Host, hardware, drivers, installed YMCC, Steam, a window or a real sleep cycle.

Inputs are local manifest-pinned runtime files plus the existing YMCC development signing key. Build offline using the installed .NET 10 SDK and the frozen local package directory. The existing `hc-devicecore-trim` utilities are linked read-only, not edited.

`build-and-verify.ps1` is the complete desktop build and validation entry. All generated outputs must go to a new directory outside this source tree:

```powershell
& G:/YeManCC-Work/Mainline/YeManCC-source/YeManCC/tools/hc-ui-dependency-trim/build-and-verify.ps1 `
  -RuntimeRoot D:/Codex/2026-10-18/kai-s/work/hc-followup-trim/ui/input `
  -SigningKeyPath D:/Codex/2026-10-18/kai-s/work/hc-large-strip/binary-trim/keys/YMCC-DeviceCore-Development.private.pem `
  -OfflinePackageRoot D:/Codex/2026-10-18/kai-s/work/hc-large-strip/binary-trim/packages `
  -CallbackGoldenPath D:/Codex/2026-10-18/kai-s/work/hc-large-strip/binary-trim/callback-original-path-golden.json `
  -OutputDirectory D:/Codex/2026-10-18/kai-s/work/hc-followup-trim/ui/repro-another
```

The script freezes and verifies every manifest input, builds the two DLLs, creates an isolated runtime for probes, verifies type/member/body/resource equivalence, runs full HC GetTypes and seven pure constructions, compares the original and replacement SettingsCard glyph, compares 74 actual immutable table values, executes the existing 22 software callbacks, rejects each missing/denied UI dependency even when originals exist in the default load context, and rejects a wrong Modern signing token. `verification.json` records the complete result; `logs` retains failures and normal output.

Only `replacements/iNKORE.UI.WPF.Modern.dll` and `replacements/iNKORE.UI.WPF.Modern.Controls.dll` are integration inputs. The owner updates the normal product profile/manifest/pins and rechecks the combined runtime. Do not copy any staged runtime wholesale; it intentionally contains the older full frozen dependency layout for isolated testing.

The tool supports `resources`, `types`, `folded` and `tables` build modes. The final `tables` mode combines resource/type closure, the exact F2AF glyph fold, and immutable field initialization slicing. `audit` independently verifies the original and candidate, including all retained method bodies. `inventory` and `detail` provide bounded metadata/IL evidence without executing code.

The final candidate keeps HC byte-identical and all of its 1768 runtime types. Modern/Controls remain real assemblies with their original needed implementations; no hardware success or fake UI implementation is returned. All retained method bodies match their originals except exactly three approved static constructors:

- SettingsCard: four instructions reading a giant icon table become the exact original U+F2AF glyph and three no-ops. A real original initialization/getter and real candidate DependencyProperty default value are compared.
- ThemeKeys: retain the exact literal initializer blocks for eight required immutable fields, removing 2662 unused fields/blocks.
- SegoeFluentIcons: retain the exact pure integer/false icon initializer blocks for 66 required immutable fields, removing 1337 unused fields/blocks. The actual glyph and FontFamily.Source values match the original.

All other neutral resources are byte-identical. Only the two UI `.g.resources` containers become valid empty containers. Original HC UI windows/templates/rendering are outside the approved device-host profile. No actual device construction/lifecycle or CPU/power improvement is claimed. RSA mathematical strong-name verification and strict .NET identity binding pass; the raw Windows mscoree signature API result is retained separately and is not misreported as successful.

Compared with the two pinned source files, the saving is 3036160 B. The standalone reproduction run generated byte-identical files.
