# 触摸板首次清理失败回执

独立输入线程最终清理原来有多处只保留 `cleaned=false`，未记录原始错误和具体操作；此时 `lastError()` 可能仍为成功，现有状态无法解释为何严格复位被拒绝。

本次只记录该线程首次清理失败的 HRESULT、固定阶段与触摸源编号。在现有 `nativeInputChannelFailure.cleanup` 中按需带出，同时报告 stopping/complete。原错误保留；无原错误时仅该诊断对象使用首次清理错误，界面总体 error 和实际退出/恢复决定保持原语义。队列未 Completed 时的 E_ABORT/E_FAIL 是状态分类值，不冒充其未读取的底层 ErrorCode。

记录没有计时器、线程、轮询、锁或动态字符串。正常状态读取增加一次原子错误读取；固定阶段标记发生于原来的 Close 路径。它不是零成本，也不声明实际 CPU 降低。

原清理顺序、三次源 Close 尝试、线程等待与确认条件保持。原通道未确认清理成功时仍拒绝替换，鼠标穿透、SD 光标策略与其它控制逻辑保持。

原生配套新增 `channel-cleanup` 显式选择，复用原 manual-channel 消费者和私有桌面。仅冻结副本注入两次受控原线程 Close 错误，以验证首次回执不被第二次覆盖、正常状态不生成该对象、原拒绝保持。私有清理端口须在实际线程结束且 COM/HWND 全空后才归还故障夹具的保留句柄，不能作为产品自愈证明。

此改动帮助下一次现场定位，不证明 Win5 原始全屏故障已找到或解决。
