# YeManCC v0.0.38

[简体中文](v0.0.38.md)

This update focuses on controller shortcuts and touch/mouse controls, Steam and Decky recovery, performance controls, and configuration and update reliability.

## Controller, touch and mouse controls

- **Keyboard combinations and action sequences** support 1–4 keys per combination, key/combo and wait steps, copying and reordering, a fixed repeat count, and loops stopped by triggering the same input again. Cancellation, target changes and shutdown handle keys owned by the sequence.
- Replacing or deleting a default summon shortcut no longer leaves a hidden shoulder-button shortcut active.
- A dedicated **Touch & Mouse** page brings mouse and screen touchpad controls together, with revised status icons, layout and controller navigation.
- Automatic mouse mode allows ordinary foreground applications by default, respects the mouse allow/block lists, and pauses for the identified foreground game. A background game or temporarily unavailable game classification no longer disables ordinary applications by itself.
- Controller calibration improves raw-versus-adjusted stick and trigger previews. Shortcut editors reduce drawing behind covered menus and improve navigation at different display sizes.

## Motion and device integration

- Explicitly enabling gyro now carries the selected preset's trigger and output parameters, addressing cases that previously required selecting the preset again.
- ROG “百式” recovery improves sample observation, cancellation and recovery decisions. This recovery remains limited to ROG devices; other devices retain their own input paths.
- OneX sensor discovery adds gyro/accelerometer type queries when ordinary enumeration returns no devices, alongside model-specific axis and source checks.
- OneX X1-family input integration and X2 endpoint checks are refined. X2 Mini Pro lighting gains the integrated path for separate zone colors, solid/breathing effects, brightness and off.
- OneXPlayer Mini AMD fan duty-range handling is corrected, with device-session checks for returning fan control.
- MSI/ROG zone-color controls and OneXPlayer 3 preset, secondary-color and fixed-speed presentation are corrected. “Ambilight” on these paths means zone coloring.

## Performance controls

- The refreshed **TS performance simulation workbench** uses the actual performance panel, with comparisons at equal wattage, temporary edits, restore/reset and explicit save. Its curves are estimates, not hardware benchmark or FPS measurements.
- Manual voltage controls distinguish AMD all-core Curve Optimizer from Intel core/cache domains and report capabilities and results. Opening the page does not apply an offset.
- Windows L3-domain process-affinity controls distinguish the request, application and readback states. They do not physically power off a CCD.
- Repeated process queries, virtual-input diagnostic cleanup, UI measurements and monitoring reads are reduced. Unconfirmed facts remain unknown.

## Steam, Decky and game tools

- Steam appearance recovery improves bounded follow-up after resume, document changes and busy helpers. Manual edits take priority, and stale power-state completions cannot replace current state.
- Decky improves staged recovery and invalid-context cleanup while preserving user settings, and separates connection health from failed feature reads.
- Custom-library video wallpaper selection and weak-network downloads retain the requested selection and existing preview until new media is ready, with corrected selection receipts and targeted refreshes.
- The top Lossless Scaling panel adds **Unlink this game** and consistent toggle behavior. Unlinking removes the current game's configuration association while preserving its executable.
- Monitoring read failures preserve the saved template and scale. Enabled network-acceleration tasks also receive a one-time post-resume restart check.

## Sleep and resume

- The new sleep-timeout option attempts another sleep request if the device remains running 240 seconds after a power-button sleep request. Manual wake takes priority. It defaults on when unset and preserves an explicitly saved off setting.
- Power-button settings add **Turn off display**. Screen, sleep and hibernation timeout controls improve feedback when saving succeeds but a subsequent read fails.
- Game suspend/resume improves process-identity checks and diagnostics, distinguishing a new suspend operation from reuse of prior state.

## Configuration and updates

- Configuration validation, save verification and recovery are strengthened. Supported damaged files are preserved before repair; newer formats, locked files and permission problems are reported.
- Background downloads retain game-pause, successor-version and resume policies, with fewer checks while disabled, offline or idle with no work.
- Update completion relies on the protected installation transaction rather than progress or handshake files alone.
- USB/IP maintenance checks the installed program and driver separately and improves continuation after reboot. Unknown identities or busy components do not trigger repeated removal and installation.
- Battery management moves into the YMCC process. Upgrade cleanup targets only the identified retired battery executable and preserves unknown files and user settings.
- The approved compact HC layout, single HIDMaestro.Core.dll and absence of the retired nested ymcc-input-payload.zip remain part of delivery.

## Installation and validation

Use the complete **YeManCC.zip**, keeping `YeManCC/` and `PowerControl/` as siblings. Users of 0.0.37 retain the existing update entry. Save game progress and close games before installation; reboot Windows when driver or HIDM/BUS maintenance requests it.

Attachments: `YeManCC.zip`, `YeManCC-source-v0.0.38.zip`, `version.json` and `SHA256SUMS.txt`.

Fast releases keep full fixtures outside the default path and record `fixtureValidation=NOT_RUN` when they were not executed. Availability depends on the device, firmware, input source and installed modules. Software checks do not establish physical compatibility with every device, game or reboot scenario.
