# GPU 名称分类：正常新采样路径减少重复扫描

日期：2026-10-16。承接生产者时间边界修复与 HWiNFO 静态采集优化。本轮不减少数据显示项，改为减少统一原生解析器在每次新生产者采样上的重复名称比较。

## 改动

`native/monitor_gpu_selection.h` 原先对每个 GPU 标签依次尝试显存、电压、温度、功耗、频率和负载列表。改为在原入口已经接受 GPU 前缀或 Total Graphics Power 别名之后，用有界字节提示缩小候选家族，再对剩余部分做原有精确匹配。`native/monitor_text_fold.h` 增加有界 `asciiAt` 和借用只读后缀的 `after` 方法，避免每个别名反复折叠同一个 GPU 前缀。

提示本身不决定接纳：所有原精确标签、单位、数值范围、优先级、功耗子串别名和 limit/rated/maximum/capability/tgp/tbp 排除规则保留。子串功耗别名仍放在最终兜底，包含 GPU Memory/GPU Core 等前缀的非常规功耗标签不会因路由漏掉。保留大小写不敏感行为及非 ASCII 字节原样比较；原有字符串左值视图仍跟随字符串当前内容。

后缀视图只在本次分类函数内借用已有不可变 scratch 字节，没有保存跨采样的标签或值。没有新增字段、堆缓存、读取、线程、定时器或日志。GPU 设备身份、会话功耗优先锁存、AMD 专用/共享显存规则、FPS 主来源与救援规则都未改动。

## 真实解析器的处理量对照

使用本轮变更前固定的 parser/头文件作为前版，当前 parser/头文件作为后版，经过实际结构、分类、GPU 选择和发布。每组工作量夹具执行 200 次新的生产者时间，绕开“同一采样直接复用”的收益，只记录当前完整解析的操作。计数是进入 `monitorAsciiFold` 的字节次数，不是整个进程 CPU 百分比，也不是机器指令数或耗时。

这些计数包含当前提示所用的字符折叠，但不把视图构造、分支等其他机器工作当作零成本。因此只据此说明重复名称扫描减少，不能直接换算实际 CPU 降幅或断言所有可能输入都更快。
