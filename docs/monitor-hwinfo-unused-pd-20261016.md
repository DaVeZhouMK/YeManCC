# HWiNFO USB-C 端口遥测：减少未消费的上游访问

日期：2026-10-16。承接 `monitor-hwinfo-unused-disk-20261016.md`，继续同时优化 HWiNFO 生产者与 YMCC 唯一数据链，优先保持现有数据可见。

## 最终源码行为

`PowerControl/YeManHWiNFO.ps1` 的内部静态配置增加 `USBC_PD=0`，与 `PresentMon=1`、`NvClockMeasuring=0` 一起进入现有稳定基础模板和 INI 合并/备份/校验事务。原始稳定模板的 567 字节基础部分没有改变。AMD SnapshotPolling 不默认启用，界面没有新增技术开关，也没有 FPS 关闭入口。

该配置停用的是 HWiNFO 对 USB-C 端口电压、电流、供电功率和 PD/QC 状态的独立监测。当前 YMCC 和三个 RTSS 模板都没有消费这些端口读数。电池百分比、放电功率、剩余时间、CPU/GPU 核心电压，以及 Windows AC/DC 电源状态继续沿用原有来源。现有 HWiNFO FPS 主来源、RTSS 缺失救援和磁盘活动组裁剪保持原实现。

健康运行的启动路径不改写正在使用的 INI，也不主动重启 HWiNFO；新静态设置只随原有准备/恢复事务生效。未新增采集器、线程、刷新定时器、配置轮询或逐帧日志。实际节省取决于机器是否原本存在并轮询这些端口；不声称所有设备都有相同收益。

不仅读取历史选项报告：测试还检查研究镜像中选项描述符的原始字节，确认 `USBC_PD` 名称、整数类型、默认值 1 与实际开关变量映射。原始初始化函数在变量为零时直接返回不可用组，跳过端口对象分配、端口后端探测、总线寄存器查询。模拟器中的这些外部边界都是桩，不访问硬件。

6 组原始指令用例覆盖原生端口、第二后端、直接总线路径、不可用端口，以及其他实例。原生端口成功用例中，所测初始化加一次端口轮询的外部查询边界调用从 2 次变为 0 次；其他分支也验证零配置不进入这些查询。该数量不等于整个 HWiNFO 的调用总数或 CPU 降幅。测试不替代安装版真正加载 INI 后的运行验证，也没有证明其他版本完全一致的行为。

该配置已有独立上游监测入口；本轮没有修改 Windows 充电控制或执行任何端口协商命令。新配置在本机尚未应用，因此不报告实际充电/监测实机兼容结论。

## 数据与全 YMCC 依赖

从实际端口读取方法提取 10 个项目名称：PortA/PortB 的 Voltage、Current、Power、QC Charging、PD Charging。逐项核查三个现有 RTSS 模板的非空 ReadingName，没有这些项目依赖；只读核查 FanHost 当前 CPU 温度分类器，也没有端口标签依赖。没有修改或重建 FanHost。

9 组原生夹具构造 SM2 传感器表并移除这些端口组，覆盖四类已发现端口家族、最多 32 个端口组、最前/中间/最后位置、零值、NaN、用户重命名、空组及相邻家族。夹具实际重新编号传感器、经过同一个解析缓存所有者，再比较完整发布数据和 FPS/LOW/帧时间的来源身份。另断言目标组确实被移除，防止测试前后未变而误通过。

59 项原生检查通过。输入包含故意与核心电压范围重叠的 1.9 V 端口值、很大的端口功率；CPU/GPU 电压仍为各自真实夹具输入 1.1/1.05 V，功耗、内存、网络和帧率保持原值。电池夹具独立输入 -42 W 和 60 分钟，剩余时间通过现有实际 remainingTime 函数生成合法的 sensor-estimate 来源证明，没有把端口供电功率当电池放电。

22 项消费检查将前后原生输出经过实际唯一监控 hub、HUD model 和两个现有输出协议，比较完整结果并断言电池百分比 50%、功率 -42 W、时长 60 分钟及原有失效时间。两个协议的隔离验证不表示重新开放已隐藏的 Steam 输出选项。

## 另外三个候选的处理

- 内存时序组保留：RTSS 详细模板仍依赖 Memory Clock/Memory Clock Ratio，整组停采会破坏已存在的选项。
- WHEA 组保留：三个模板仍绑定 Total Errors；另核验了事件回调直接进入事件处理、未以组 Enabled 为门，不能把关显示或关组当作有效阻断证据。
- CPU C-state 组暂不裁剪：所读方法使用共享 CPU 状态，尚未证明禁用该组能让底层 CPU 获取一同停止。
