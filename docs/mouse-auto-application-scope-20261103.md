# 自动鼠标扩大为非游戏前台，并共享应用分类

本轮将自动鼠标从少数Windows外壳窗口扩大为未命中禁用规则的可识别前台应用。安装版未替换；没有操作真实Steam、游戏、手柄或JoyXoff配置。

| 自动模式当前前台 | 处理 |
|---|---|
| YMCC自身，包括同进程的内页／模拟页 | 关闭／暂停自动鼠标 |
| 顶部游戏识别对应的同一游戏进程实例，窗口或全屏 | 关闭 |
| 模拟器，含主界面、设置页和运行游戏时 | 关闭 |
| Steam、Epic等已分类游戏平台／库客户端 | 关闭 |
| 浏览器、办公、聊天、文件管理及其他未命中禁用规则的应用 | 开启，不等待游戏识别完成 |
| 游戏仍在后台，当前前台是普通应用 | 开启 |
| 共享游戏识别等待、不可用、没有快照或规则暂忙 | 普通应用默认开启；已确认的游戏身份和现有禁用类别继续关闭 |
| 前台临时为空、无法读取进程身份／EXE | 保留既有短暂过渡规则，无法匹配名单时暂停 |

手动开启／关闭优先级及SteamDeck由Steam管理的边界保留。分类只在自动模式消费；没有恢复此前已取消的普通手柄套用Steam布局。

## 共享来源

`native/game_application_catalog.h`直接复用现有自定义库的7系列模拟器资料：yuzu、Eden、Ryujinx、PCSX2、PPSSPP、RPCS3、RetroArch，含原有多个EXE别名与RPCS3前缀规则。原EmulatorProfile结构、资料和库侧查找逻辑逐字核对保持，仅将表改为共享inline定义。既有游戏黑名单的VMware／VirtualBox／QEMU宿主也归入模拟器禁用类别。未把这一组称为所有模拟器的100%覆盖。

`native/game_library_blacklist_entries.h`从现有system-blacklist游戏平台分段提取31条规则，原生游戏识别、自定义库及鼠标分类共用。随包system-blacklist.txt不再重复维护该分段，已安装用户文件不改动，旧文件中的同名行仍兼容。

游戏白名单／独立游戏配置命中的前台EXE按游戏处理，包括手动加入的改名模拟器。规则变更沿原game.rules.set和游戏阀门发布唤醒现有鼠标worker，按原规则代次重新读取；没有另起一个游戏识别器。游戏识别黑名单中的浏览器、聊天、办公等普通应用不自动加入鼠标黑名单，避免误停。game.rules.get额外返回applicationCategories用于同源分类；原有blacklist、whitelist字段和编辑流程保持。

## 前台与开销

鼠标只读取顶部游戏识别已有的阀门快照，匹配PID、创建时间及完整路径；后台游戏的存在本身不关闭鼠标。原发布入口提供不可变快照，鼠标无需争抢游戏扫描锁；名单代次未变时复用已确认规则，避免短暂规则锁竞争使普通应用误切OFF。白名单和独立配置沿相同来源识别前台，不把手动白名单替换成另一份鼠标名单。

没有新增线程、进程扫描、磁盘轮询或启动器操作。分类复用游戏识别已有的规则代次，稳定代次不重复解析；手动ON/OFF不加载应用分类。原有worker、WinEvent唤醒、180ms开启防抖、250ms前台为空宽限、晚到开启撤回、后端证据代次及退出销毁保持。

共享游戏快照在等待／不可用时，已有游戏的PID、创建时间、完整路径仍用于精确前台匹配；三者一致才继续关闭，不把后台游戏或复用PID的普通应用禁用。共享规则锁暂忙或读取失败时保留原缓存及正向游戏身份，普通应用不因此关闭；不新增进程枚举、识别线程、轮询或第三方配置写入。复用原 `controller.mouse-auto` 场景验证，现场和安装版状态另行记录。

## 2026-11-04 鼠标审计四项修复

按用户确认，唯一游戏身份只消费既有发布：未变就复用，允许短暂空档，不增加游戏扫描、催刷或常驻探活。前台、名单或挡位变化仍按原优先级决策。

本次修复四项：切挡的设置保存和Runtime接纳在同一短事务顺序内完成，后端等待在锁外，循环切挡也共用该顺序；切换后端只强制核对当前挡位，不重放提前读取的旧挡位。手柄引擎通过统一准入状态的同步观察器更新屏蔽，旧回执被拒后不再从App旁路派发；观察器退出时释放，无新增轮询。相同提供方、相同有效ON/OFF决策复用已有回执，保留原后端观测时间；显式切挡、切后端、SD交接、失败和未知状态仍执行必要IO。共享规则失败时只尝试该代次一次并保留旧有效规则，下一共享代次到达再加载，不由1秒观察反复读盘。
