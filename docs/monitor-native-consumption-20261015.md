# 监控调用与数据专项审计收尾 — 2026-10-15

目标为“挖穿监控 CPU 调用优化和数据 bug”。本轮接续 monitor-cpu-data-audit-20261015 的三个待查项，完成原生 HWiNFO 匹配、快照服务/推送和各展示消费者的调用预算复核。主线已有修复与本轮结果共同进入最终验收矩阵。这里的工作次数与分配次数不代表 CPU 百分比；按照用户要求，没有 CPU 实测、真实硬件/游戏采集或部署。

## 本轮生产改动

### HWiNFO 精确 1% Low 使用有界工作集

原解析器在确认最后一个有效 Presented(avg) 槽位后，再遍历全部读数匹配精确 1% Low。现在第一次遍历时，仅对合法 FPS 单位、有限且在范围内的两种精确 LOW 名称保存槽位、优先级和当前值。精确 Presented LOW 优先于旧名称，同优先级保留最后一条有效读数。

工作集为 16 个槽位的栈内固定存储；超过容量时完整回退原来的第二次扫描，不限制发布者的真实槽位数、不丢掉第 17 个或以后的数据。Displayed、0.1% Low、1st percentile、历史最大值/平均值都不作为精确 1% Low。

整个旧/新原生解析器执行 2,071 组对照，比较全部标量字段、传感器槽位、原生 top 载荷与完整 GPU 分组内容，包括乱序、重复名称、NaN/Infinity、非法单位、未知槽位、种子输出、截断/超大头和全部一致性印记的变化。常见单游戏槽位下：

| 读数行数 | 修改前读数表访问 | 修改后 |
| --- | ---: | ---: |
| 463 | 926 | 463 |
| 8,192 | 16,384 | 8,192 |
| 100,000 | 200,000 | 100,000 |

工作集没有增加解析堆分配，200 次热态解析两版均为 0 次。40 个 LOW 槽位的溢出场景仍执行原完整扫描并得到相同结果。

### 快照响应与推送减少重复复制

monitorSnapshotServeFn 继续在原互斥锁内复制完整一致快照，在锁外构造响应；其私有副本中的 top/fps 字符串直接移动到响应 JSON。发布者自己的缓存不被移动或暴露。快照字段、原生会话/代际/relay、实时 top/fps 闩锁、服务计数、独立返回值和最终 JSON 字节均保留。

原生 HUD 推送直接引用响应中的 FPS 字符串判断曲线来源，随后把响应树移动到事件，省去额外的 FPS 字符串和整棵 JSON 树复制。2,500 份完整快照响应及 24 条新鲜/静默/开关组合路径通过旧/新对照。

在 200 次约 24KiB 的合法测试载荷回放中，快照响应堆分配由 11,000 次降到 10,600 次；完整推送回放（包含相同的夹具构造、安装和事件记录成本）由 37,200 次降到 30,800 次。这是累计工作计数，不是峰值内存或实际使用率。具体累计字节见 RESULT.json。

### 采集停更后的旧曲线不再维持快速推送

原实现只要缓存文本仍有 RTSS 曲线来源标记，就会保持 200ms 推送。现在快速模式还必须有当前 FPS 需求和 6 秒内的既有采集时间戳；过期、未来时间或已停止的需求回到 1 秒。它只改变传输节奏，不改读数、观测时间、有效期或关闭条件。有效新发布到达后恢复原 200ms 节奏。

回放确认：在新鲜边界内与原行为一致；第 6 秒旧缓存由 5Hz 降到 1Hz，事件数据逐字段相同，真实新发布可恢复快速模式。没有另建采集器或读取硬件。

### RTSS 页面释放无用的预览订阅

RTSS 模式没有预览，但 Settings 仍持有数据和 TDP 订阅并执行完整预览投影。现在切换输出时协调这些展示订阅：RTSS 释放，自定义监控恢复一份数据/一份 TDP 绑定；自定义预览在输出总开关关闭时仍可编辑。图片选择、持久设置、输出协议、模板和 CSS 保留。

实际 Settings、SegButton 和 KeepAlive 的修改前/后浏览器回放共 8 个场景：200 包数据在 RTSS 模式的预览投影从 200 次降到 0 次；自定义模式两版均为 200 次；保存为 RTSS 后启动也遵守同一边界；停用和卸载均释放订阅。
