## 已落地的数据节拍 / 开销约束

1. 只复用 `monitorData.ts` 的 YMCC 统一快照；不加 HWiNFO / HAL 读者，不用轮询历史文件刷新 HUD。
2. 显示侧门限固定 1000ms：最多一个最新候选值、一个一次性定时器，不积累队列，不追赶历史帧。
3. 相同会话/代际/序号/健康状态/载荷时间不重复映射和广播。失效可以立即清空，但不能用失效事件重置恢复数据的 1Hz 预算。
4. 没有订阅者不启动刷新定时器；最后一个订阅者释放、页面停用、窗口释放均撤销自己的待发定时器。
5. 控制 / autofloat 的 `read()` 语义不变，显示节拍不得限制功率控制响应。已有共享在途请求合并保留。
6. 原生预览只做一次初始统一读取，后续被动订阅，不建第二采集循环。
7. 外观和数据分开消息。改大小/透明度/选项只发 preferences，不重新读取、映射或发送整份监控数据，也不延长过期读数寿命。
8. 数据包使用 shallowRef；格式化时间使用缓存的 Intl formatter，字段格式化用静态索引。
9. 保留 CPU 柱状图，但不加持续 rAF、CSS 数值动画、平滑补帧、模糊采样层。关闭图表项后不计算相应图表。
10. 接收数组有界：128 个核心负载、128 个核心频率、120 个帧时间点。柱状图超过 32 核分行而不向外溢出；绘制范围使用 CSS contain 隔离，不删掉任何核心。真实统一接口目前缺失的扩展字段继续显示“—”，不塞入示例。

当前 native 源码的 `nativeMonitorLoop` 末尾已按 top/有游戏 FPS 的情况等待 1000ms，只有 FPS 且无游戏时等待 5000ms。本轮不改原采集器。顶部前台读快照已有 1000ms 调度。本轮新增的是**显示数据通路的上限与去重**，不是凭空承诺硬件采集更省电。

## CPU 性能验收方法

工具：`tools/monitor_hud_cpu_benchmark.mjs`。

- 测静止基线、3 项、默认 14 项及 16 核柱状图、28 项及 16 核/120 帧点、28 项及 128 核/120 帧点、200Hz 突发输入。
- 使用自己的 headless Edge，两个同源离线页面，真实 BroadcastChannel 和生产 Vue HUD/显示门限/有界接收逻辑。
- 每档至少 20 秒，重复两次；必须真的收到约 1Hz 的动态数据。仅静态 fixture 不算动态性能验证。
- Node 测映射 / 有界接收 / 序列化 500000 次；CPU 和墙钟 p95 是 **100 个 5000 次样本批次的每样本耗时**，不是声称单次延迟 p95。
- 浏览器使用 SystemInfo.getProcessInfo 的累计 CPU 时间差，包含本次自有浏览器所有进程。按单核等效百分比报告，不除以整机核心数制造很小的占用。
- 浏览器进程集合改变的窗口计数不完整，丢弃并记录后重测；计数不可用绝不报 0。TaskDuration 仅作辅助，CPU 结论以进程计数为准。
- 当前离线门禁：映射/有界接收/序列化批次 p95 每样本 ≤1ms；每档所有浏览器进程 CPU ≤单核等效 1%。门禁失败必须如实标失败，不自动放宽预算。
- 本地合成数据测试不含真实 HWiNFO/native 采集、WebView2 宿主、Decky/Steam carrier、2077 游戏，**不等于实机端到端 CPU / 功耗通过**。

CPU 数值以隔离目录 `performance/CPU-PERFORMANCE.json` 为准；必须有 accepted=true 才能说离线门禁通过。

## 最新实测结论（修正 128 核绘制溢出后）

每档 20 秒，重复 2 次，动态档每次均实际发送/接收 20 份数据。下表包含自有 headless Edge 的 browser / renderer / GPU / utility 等所有进程，使用单核等效百分比，未除以整机核数，也未减去较大的启动基线。

| 档位 | CPU 单核等效范围 | ≤1% 门禁 |
|---|---:|---|
| 静止常用 HUD 基线 | 0.04%—0.57% | 通过 |
| 3 项数据 | 0.85%—0.88% | 通过 |
| 默认 14 项 + 16 核柱状图 | 0.85%—0.87% | 通过 |
| 28 项 + 16 核 + 120 帧点 | 1.00%—1.03% | 未通过 |
| 28 项 + 128 核/频率 + 120 帧点 | 1.42%—1.49% | 未通过 |
| 200Hz 人工事件输入，输出限 1Hz | 1.26%—1.34% | 未通过 |

**整体 accepted=false，未放宽门限，不能宣称产品低 CPU 已验收。** 普通/少量显示通过当前离线门禁，全字段档存在边界超限，128 核与 200Hz 人工压力档明确超限。200Hz 是离线压力源，不是生产 HWiNFO 或 YMCC 的真实采集速率；其计数包含产生高频事件的测试源开销，不能把该开销全归到硬件数据获取，也不能把输出去重当成源端唤醒免费的证明。

统一快照形状的纯映射/有界接收/序列化平均 CPU 约 0.00275ms/样本；128 核/120 帧点的大包约 0.01663ms/样本。Node 门禁通过。扩大到每档 500000 样本和 5000 次/批，是为减轻 Windows CPU 计数离散分辨率对短批次的影响，不把短批次 CPU=0 当成没有开销。

CSS contain 和核心分行修复的是绘制范围、视觉溢出；前后实测没有证明极限 CPU 明显下降，不把它描述成成功降占用。优化前数据保存在 performance/CPU-PERFORMANCE-pre-containment.json。

CPU 原始报告记录 2 个因浏览器启动过程退出而丢弃的不完整窗口；后来采用进程集合稳定的完整窗口。没有删除这些记录或按 0 计数。最初测试脚本将不同档位的初始发送时间混在一起的失败记录也单独保留，此后每档单独记录间隔。
