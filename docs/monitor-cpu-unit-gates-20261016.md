## 源头问题与修改

原CPU频率解析先计算cpuClock，然后无条件计算包含16个排除词的badClock。温度、硬盘、电池等非MHz行，以及不属于CPU频率的行，仍会进入这组子串扫描。原功耗和温度规则也先扫描名称，再核对单位/数值。

本轮只修改native/main.cpp现有monitorParseHWiNFOView中的CPU规则：

- CPU功耗先判断W或既有watt单位，再执行原来的CPU/package/pkg与排除词判断。仍在名称/单位匹配后消费该行，保留无效值也continue的语义；没有把数值有效性提前到会改变后续规则的位置。
- CPU频率先核对MHz、可读且有限的非负数值、10000上界，再检查core/cpu和clock。只有这一候选成立时才扫描原16个排除词；实际写入和continue条件不变。
- CPU温度先核对有限非负数值、150上界和原有摄氏单位编码，再执行原Tctl/Tdie或精确CPU Package名称及排除词。Tctl优先和各来源取较大值不变。
- 剩余时间原表达式为“estimated且remaining且time，或remaining且time”。移除被后一分支完全包含的estimated分支，保留remaining/time子串语义、来源组记录和单位换算。

电池规则不能一概按单位提前返回：无效单位/数值的命名电池行仍可能是多电池歧义证据。本轮保留batteryGroup调用及原有分组处理，没有为省扫描而改变它。GPU、内存/网络、虚拟内存、FPS和历史温控路径的规则没有改动。

数值覆盖50、0、负值、NaN、Infinity、150/151、1999/2000、10000/10001及5000。名称还包含大小写、嵌入零字节及非ASCII前缀。每组对比完整发布输出、结构体中解析提取的全部基本数值/标志字段、原始RAM/显存字段、有效GPU全部字段、D3D证据及来源。该有限语料不能声称穷尽所有任意输入。

另有9组跨规则优先级/多行组合，尤其验证：

- MHz候选不成立后，剩余时间规则仍记录来源组，多个组时保持未知。
- 名称和W单位匹配的CPU功耗，即使数值无效，也像旧版一样消费该行，不让同名的battery power片段干扰后续有效电池组。
- 错误功耗单位则仍可继续进入电池规则，保留歧义。
- 合法CPU Clock Remaining Time仍先被频率规则消费；越过10000时像旧版一样继续匹配剩余时间名称，但不能把MHz数值变成时长。
- CPU Package和Tctl并存时，保留Tctl优先；温度失效后的后续规则行为不变。

旧/当前各44项检查通过，16560组完整包、9组优先级包、12组D3D需求/组号门保持一致；继承的15组命名发布结果、13组GPU字段及既有初始化工作量也一致。
