# 监控 CPU 消费链优化 — 2026-10-14

本轮已修改主线监控的数据消费和绘制代码。按照用户要求，只进行离线回放、合成数据的浏览器单元验证和前端编译，没有启动已安装 YMCC、Steam 或游戏，没有采集真实硬件，也没有测量实际 CPU 百分比或耗时。

## 改动

1. 输出渲染器用固定字段比较已持有的规范化外观。外观与开关相同时，避免在每个数据包上再次重建整套预设；外观、开关或旧版本输入有变化时仍走原规范化逻辑。协议入口的数据校验保留，渲染器也继续校验每份数据。
2. 预设字段和显示开关改为直接填充，避免为每个指标建立临时键值数组。原有预设库、显式关闭选择、版本迁移、持久化和重置逻辑保持一致。
3. 数据老化改为仅在实际清空字段时复制读数；新鲜数据与已清空数据无需重复复制。所有独立数据有效期、估算标记与数组清空语义逐项和修改前代码比较。
4. 判断帧时间曲线有效性只检查相邻有效点，不再为了判断有无曲线先生成整条路径。绘制使用每个组件独有的 120 点有界缓存，相同内容复用路径，原数组被原地修改也能识别。
5. 图片字符串校验保留原 45,000 字符与栅格类型限制，仅记忆两份已验证的不可变字符串，减少自定义图片和游戏 LOGO 随包重复扫描。变化、非法和超长数据仍按原规则处理。
6. 渲染器初始化只做一次数据整理；Steam 内部转发复用入口已经规范化且内部持有的设置。没有修改原生程序或增加接口。

本轮没有更改数据采集入口、已有刷新频率、FPS 连续有效 3 秒的入场条件、FPS<1 时隐藏整个帧率家族、5 秒缺失容忍、温度/电池/风扇来源或鼠标穿透行为。

## 可复现验证

在主线源码目录运行：

    node tools/monitor_hud_cpu_consumption_selftest.mjs

默认修改前基线在本任务 before/ 目录。可通过 YMCC_MONITOR_CONSUMPTION_BASELINE 指定显式基线目录，通过 YMCC_MONITOR_CONSUMPTION_OUT 指定独立输出目录。源码插桩仅在离线打包内存中进行，不改生产文件，不新增生产计数器。

自测对比完整修改前/当前函数与 Vue 渲染器：

- 500 组随机设置加默认、旧版、非法输入；全部预设与显式 false 保持一致。
- 1,000 组有效期/电池标记/数组/缺失字段组合；结果与修改前完全一致，且输入未被修改。
- 1,000 组随机曲线历史加空值、间断、异常和超长历史；生成的坐标及分段和修改前一致。
- 300 组开关、自动隐藏、FPS 值与就绪条件，共 1,200 组显示选择对照。
- 13 个布局分别使用简约和详细字段，另含 1280 宽度、80 次数值更新、外观修改；共 30 个浏览器场景。
- 详细电路面板 140% 缩放下的修改前/当前截图 SHA256 相同。
