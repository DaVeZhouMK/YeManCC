## 本次确认和修复的缺口

1. **忙碌助手耗尽补查名额。** 原 take() 在检查 idleHelper 前消费名额；旧助手超过10/30/60秒，三次都可能空耗。原消费者扩展后在该断言真实失败，记录保留在 busy-before。现在首次到期仍通过原撤销边界处理旧工作；本轮新助手在执行时暂停补查预算，失败后用剩余间隔续接，不叠加助手、不出现0超时忙循环。
2. **助手未取得执行权就永久停住。** confirmIdle 返回空或异常曾先设置 idleRequested 并暂停预算。现在保留原因 appearance-helper-unavailable，沿原最多三个启动尝试续接；异常在边界内转换为未确认，不退出 worker。重试前关闭旧观察句柄，避免覆盖句柄泄漏。
3. **旧电源代次租约/成功回执。** Runtime 将租约和确认绑定原电源代次；非Ready或旧代次不能 Begin/Ensure/接受迟到成功。已接收的 Ready 只撤销一次旧临时工作，常驻 CSS 保留。guard 完成回调还重核开关和生命周期，不凭迟到结果发 Ready。
4. **恢复覆盖唤醒后的新手动修改。** 当前代次的手动租约优先，自动刷新返回 resume-use-manual-busy；完成的手动编辑走原只读 DOM 接续并取消同轮延迟补查。明确 OFF、目标变化或真实后台退出仍可以撤销临时工作，不给手动租约留下绕过 OFF 的权限。
5. **撤销旧 DOM 不能误伤异常退出恢复。** 当前 readiness 过睡眠即失效，但旧后台确实曾成功这一事实仍能用于有预算的崩溃准入。guard 只保存已确认后台的精确 PID+birth，并在同一 Steam 实例中匹配实际退出句柄；它不能发 Ready，只能进入原30秒延迟、鲜模式验证和最多两波的 CSS-only 恢复。正常/console-close/未知退出、不同 PID/birth、编辑器和所有权冲突仍不创建替代后台。
6. **原手动验证器源码边界失效。** initializer 加入生命周期参数后，旧固定 `});` 截取把后续接线一起编译进夹具。已在原提取器按真实 lambda 括号边界、字符串和注释匹配，保留完整回调和原断言，不用添加未知全局桩掩盖截取错误。旧编译FAIL保留。

## 当前恢复与停止节点

| 节点 | 当前行为与主要证据 |
|---|---|
| 外部或YMCC手动启动后进入大屏 | 原共享 Steam observer/mode 事件进入有限启动窗口，原生 use 确认；CSS 没有 Steam 启动命令 |
| 实际 Ready | 当前 Steam、开关、电源代次一致才排队；默认10秒首次检查，未阻塞时后续约+30/+60秒，确认后取消余量 |
| 旧助手仍在跑 | 首次检查走旧临时工作撤销；不能空耗全部检查；原 resume 忙碌场景 |
| 本轮助手较慢或 DOM 暂未确认 | 当前 bounded helper 自己有硬期限；执行期间不叠加，实际失败后续接剩余20/30秒间隔，不以命令成功代替DOM |
| 新 Steam UI 文档/用户再次进入大屏 | 原精确模式/文档代次事件补一次，重复同文档回调合并；不切模式 |
| 手动 Apply/Refresh/Reset 完成 | 原 begin/end-use +只读接续，成功才重绑退出句柄；延迟恢复服从新的手动租约 |
| ON/OFF/目录变化 | 原目录事件与操作边界核验；OFF/目标变化撤销对应临时工作，CSS常驻家族不被销毁 |
| 后台已知异常退出 | 精确历史后台身份、当前同一Steam/ON和原预算；30秒后重新确认大屏、唯一后台，最多两波 |
| 正常关闭/未知退出/预算耗尽 | 保留停止原因、事件等待；不因Ready/模式风暴重开 |
| CSSLoader Desktop/权限不明/端口冲突 | 保守保护编辑器和后台；Unknown不当Absent，不创建第二家族 |
| 再次睡眠/换实例/旧结果/退出 | 原代次和当前状态重核；迟到回执不报Ready，不授予旧租约新动作 |
| 正常静置 | 原句柄/目录/共享事件等待，主题不新增常驻线程、扫描timer或独立全局进程枚举 |
