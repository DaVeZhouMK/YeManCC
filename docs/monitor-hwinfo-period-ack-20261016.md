# HWiNFO 上游周期控制的生产者确认（2026-10-16）

接续 monitor-hwinfo-upstream-control-20261016.md。既有入口已经支持显式请求 1000/1500/2000/3000ms，并保留配置合并、原始/上次备份、写入校验和失败回退。本轮修复“配置写入完成、共享内存可读就报告周期已应用”的确认漏洞，没有添加新的采集器或常驻检查。

## 已复现的问题与改动

冻结旧版请求 1000ms、模拟 HWiNFO 持续报告 3000ms，实际恢复函数仍返回 0。新版在原有启动健康检查内传递 ExpectedIntervalMs，并用现有原生读取器已经采用的格式条件读取生产者周期：版本 2，sensorOffset>=48，且扩展字段不越入 readings 区。

显式请求只有在共享内存布局/reading 区可读、生产者时间已初始化、报告周期相符且同次读取的关键头字段没有变化时才返回成功。未知格式、未初始化时间、周期不一致、坏 reading 区和读中变化不能获得“已应用”回执。

- 默认参数 0 继续保持原有可读性判定，不强迫历史布局提供周期确认。
- 健康运行时显式 start 仍返回 12（未应用），不覆盖活跃 INI、不自动重启、不把请求排队。
- 显式请求沿用原有最多 120 次、每次间隔 250ms 的启动等待。到期仍不能同时确认可读性和请求周期，返回 13；不因这一失败自动重复启动进程。
- 未请求周期的共享内存初始化超时仍为 7，启动进程退出仍为 6。INI 写入成功和 HWiNFO 采用配置分别验证。

当前确认的是生产者头报告的配置周期；它不证明硬件每次读取耗时、实际帧统计连续性或 CPU 消耗。真实采用结果仍需安装/重启后的统一采集证据。

- 新版 48 项：4 个周期及全部互不相等组合、未知版本、扩展边界、时间未初始化、非法请求、reading 区异常、稳定头及 8 类同次读取变化、恢复传参、120 次有界失败、第三次检查才采用周期、兼容回执与进程退出。
