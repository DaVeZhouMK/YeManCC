# 顶层监控核心数组所有权交接优化

日期：2026-10-17。已合入主线源码，未链接/制包/部署，没有重启 YMCC、HWiNFO 或游戏，也没有改用户设置。

## 改动与边界

Windows CPU 采样器已经直接填入最终 JSON 核心数组，但普通监控顶层载荷仍会把该数组再复制一次。现在唯一采集循环在构建顶层载荷时，明确交出本地数组的所有权；发布函数仅在可转移对象与传入数组为同一对象、数组非空且源时间有效时将它移动进 topJson。

原有 const-reference/default 调用继续保留复制语义与原来的分配量。空数组、无效源时间或非数组不会被消耗，也不会为省略的数据新增复制。传入另一个可转移对象不会错误消耗它。最初按值传参的候选已放弃，因为它会让本来省略的数组或旧调用方支付不必要的复制成本。

这只改三个生产点：内部函数新增一个有默认值的可转移对象参数、核心数组字段赋值、唯一采集循环的调用。监控对外统一接口和所有 JSON 字段、时间、单位保持。Windows 采样 API、频率、核心数上限、健康判定、GPU 来源和电池/风扇/网络/文件系统收据均没有修改。

## 真实函数对照

新增 `tools/monitor_top_payload_core_move_selftest.mjs/.cpp` 与精确旧函数 `tools/fixtures/monitor_top_payload_core_move_before_20261017.inc`。基线/当前均编译完整生产发布函数，使用同一份实际 NativeMonitorHw 与现有收据类型。

- 8,857 个断言，1,093 组完整载荷比较通过。
- 覆盖 0/1/2/16/32/64/128 个核心槽位、null/0/100 数值、非数组输入、空/无效源时间、旧式/默认调用、明确交出所有权、指向不同对象的参数，以及 CPU/HWiNFO 健康、电池、GPU、内存、网络、风扇等独立字段。
- 对比完整序列化字节和递归 JSON 类型；使用所有权的调用只消耗明确传入且被包含的核心数组。
- 300 份每组，分别测量实际顶层载荷构造与序列化；输入生成、输出 JSON 解析不计入分配计数。对普通旧调用和空/省略数组也断言分配量无增加。

- 帧输出回归 15,978 项检查、2,080 组包比较通过。
- 完整 native/main.cpp 翻译单元编译成功；合入后 main.cpp 与已编译的冻结候选字节相同。

## 分配收益

每份实际包含核心数组的生产载荷减少两次分配：JSON array 容器和它的数值存储。不降低刷新频率。

| 核心槽位 | 每次减少分配 | 每次减少分配请求字节 | 300 份累计减少字节 |
| --- | ---: | ---: | ---: |
| 1 | 2 | 40 | 12,000 |
| 16 | 2 | 280 | 84,000 |
| 32 | 2 | 536 | 160,800 |
| 64 | 2 | 1,048 | 314,400 |
| 128 | 2 | 2,072 | 621,600 |

空数组、无效源时间、被省略的数据和旧式 const-reference 调用：分配量与基线完全一致。这是局部分配/复制工作量，不能推算成整进程 CPU 百分比或驻留内存下降。
