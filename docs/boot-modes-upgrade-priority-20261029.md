## 本次修复

`native/input_startup_policy.h` 的 `initializeBootModeInputStartup` 在原生首次消费启动输入之前，通过纯函数 `bootModeInputStartupPreferences` 从已保存的四模式文档解析输入和陀螺仪启动偏好。有文档时，`startupDesired` 是该文档的下次启动缓存，不能以旧缓存覆盖新版预设决策。

原生解析与当前前端版本 2 的规则一致：版本 1／无版本中精确匹配旧出厂 SD 推荐的独立 input 模块不再优先；修改过的独立模块、已保存的全局输入以及版本 2 之后的明确 SD 配置仍然有效。仅同步启动缓存，不提前给文档盖上已完成触摸迁移的版本号。完整触摸预设迁移继续由原模型处理。

同 Windows boot／当前进程／未知启动标识的既有保护保持有效；解析启动偏好不代表立即切换当前输入。没有四模式文档时，继续使用普通 `startupDesired` 默认，不从运行中的临时 SD 开关生成持久化启动偏好。纯函数没有资源、计时器或重试循环。

此前 `BootMode-LogReview-20261029` 中 `UNCONFIGURED-SAME-BOOT-RESET` 的复现本身成立，但在用户确认虚拟手柄临时开关默认不记忆后，该现象按设计处理，不再单独认定为 bug。本次没有修改该路径。`GLOBAL-SNAPSHOT-STALE` 中以临时 SD 开关推断应当持久化的部分也不再作为问题依据。
