## TDP 上限的准确含义

- 不读取 `settings.tdp.tdpMax` 作为正在起效的上限；已删除本轮最初的配置快照订阅。
- 不读取 HWiNFO 包功耗作为 TDP 上限，也不建立第二路硬件采集。
- `setTdp` 的共同硬件下发路径在成功后发布运行时回执；手动、浮动临时值、计划、开机/唤醒、手柄共用。配置保存成功但硬件失败，不能发布所请求的值。
- 运行时绑定已有 `powerSource` 观测到的**物理电源侧**及其 epoch，不把旧 UI 的 `setTdp('ac', ...)` 配置键当作机器当前电源侧。硬件是一套共享寄存器，成功写入时记录当前观察侧；跨电源/睡眠 epoch 的迟到 ACK 无效。
- 插拔电源立即清空旧侧数据，不回放历史 AC/DC 缓存。睡眠/恢复清空电源侧知识；重新观测电源并成功下发之前显示 `—`。启动无回执时也显示 `—`，不从磁盘恢复旧值。
- 成功值经共用 1000ms latest-only gate；失效立即清空。多个显示消费者共用一个被动事件绑定，关闭最后消费者时解除绑定及单个待发送计时器。

**不能混淆：回执 proof 是 `write-ack`，不是持续硬件寄存器回读。** 现有后端缺少覆盖所有 CPU 的通用当前上限回读能力；此版本不能识别外部工具随后改写、固件覆盖或无人通知的变化。因此准确产品口径是“当前电源侧，YMCC 后端最近确认下发的 TDP 上限”，不是“实时硬件回读”。这次没有做硬件写入、启动 daemon 或替换已安装程序，不能宣布真机验收。
