## 两处源头修改

native/monitor_gpu_selection.h 原来每行都先计算显存、电压、温度、功率、频率和负载的六个布尔量，再按此顺序选用首个类别。已识别为显存的行仍会执行温度/功率名称及排除词检查。

现在把同一顺序、同一表达式整理为 private static classify，返回首个匹配的枚举类别。数值/单位校验、优先级、有效零、分组、候选查找、显卡固定选择及实际字段写入保持原规则。未知名称仍会经过全部候选规则，不能声称所有行均有相同收益。

native/monitor_memory_network.h 原来对进入模块的每行都计算 RAM、GPU、网络和 D3D 名称集合，包括已明确属于 CPU/core/drive 的行。现在先按已有、互不重叠的 physical / gpu / current 名称前缀进入对应集合，再执行完全相同的精确名称判断。D3D 的 collect/include 需求开关、组号上限、单位换算及后续数值处理保持原规则。

本轮没有改 MonitorFoldedText、新增缓存或字符串所有权，仍借用本轮有界 scratch 快照。没有修改主线 main.cpp。固定包体积保持 NativeMonitorHw=15840、GPU Readings=15400 字节；源映射、复制、其余 CPU/FPS 等解析和发布仍有既有成本。
