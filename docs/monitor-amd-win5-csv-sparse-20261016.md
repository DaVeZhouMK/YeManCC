## 当前 AMD 规则

- 明确 AMD/Radeon 的同一所选 GPU，有合法 D3D 专用读数则优先使用，包括真实 0。来源 hwinfo-d3d-dedicated。
- 专用缺失、非有限数或单位无效，且同组共享计数有效时，回退共享。来源 hwinfo-d3d-shared。真实共享 0 同样有效。
- 只选择其中一个，不求和、不跨设备，不与泛驱动计数的容量/占比混用。来源在原生 top、消费端校验和高频证据中可区分。
- 两项都没有时，保留既有可用的完整容量元组或直接占比；仅有不完整驱动用量则继续未知。
- NVIDIA、Intel、未知及互相矛盾的厂商名称沿用原规则；GPU 功耗优先和会话固定不改。
- D3D-only 行继续不创建候选显卡。

用户本轮要求“专用有的话用专用，AMD 家族规则”，因此相较上一轮，不再只对缺容量/占比的 AMD 启用 D3D：即使驱动提供完整元组，只要当前有 D3D 专用数值，也优先专用，并清除不能证明同池的旧容量/占比。这一行为变化有明确测试，未作为等价优化处理。

## 同时修正的索引缺陷及成本

之前把 D3D 传感器编号当作 256 项数组下标；合法编号 256、300、4095 的计数被忽略。现改为固定上限 256 个“实际出现的组”，键保留原始编号，有效编号范围沿用 GPU 身份解析的 0–4095。只初始化新增的条目，不逐次初始化完整 D3D 数组；不引入动态容器或采集器。

超过 256 个不同 D3D 组时置溢出标志。只有确实需要保留当前 GPU 载荷时，对本次已经复制的原始行进行一次额外遍历，恢复最多 64 个现有 GPU 候选的计数，保持最后一个合法值语义。这个恢复没有重新读取映射或硬件，也没有逐设备进行多次全表遍历。

稀疏条目由编号和两个 double 组成，MSVC x64 固定槽区 6144 字节，另有计数/标志；此前 D3D 数值数组为 4096 字节。增加约 2 KiB 固定栈空间以支持稀疏编号和避免无效初始化。极端溢出时，另有可选 64 项、1024 字节恢复暂存。GPU Device 布局不变，现有大型双 GPU 夹具通过默认栈测试。未把少量初始化成本的减少宣传为整机 CPU 百分比下降。

实际完整 NVIDIA 包重复解析 200 次，测试副本仅计数构造/条目初始化：

| 指标 | 冻结旧版本 | 当前版本 |
| --- | ---: | ---: |
| 全数组默认 D3D 值初始化 | 51200 | 0 |
| 按实际出现的 D3D 组初始化 | 0 | 200 |

这组输入含一个 D3D 组，当前每次只初始化该组。与此前“相同值载荷复用”的优化不同，这里减少的是解析暂存初始化。原有不可变 64 项载荷缓存继续工作：200 次相同 AMD 数据仍只产生一次载荷分配；无缓存反事实为 200 次。没有 CPU 占用率测量。

## 容量路线继续保持未完成

已检查 native/gpu_dedicated_memory_runtime.h、设置页调用和原生日志入口。现有容量探测由设置页请求触发，设置页在有效显示期间每 15 秒请求，没有监控可直接持续复用的原生容量缓存。直接让监控调用该接口会新增较重的枚举/验证开销，本轮没有这样接入。

需要区分：设置通道整体 available=false 并不证明每个适配器的容量读取失败；诊断数组中 capacityRead=true 的 DXGI 描述仍可能有效。阻止直接拼接的是缺少与所选 HWiNFO GPU/同一专用或共享内存池的可信配对，以及设备更换后的有效期证据。仍需解决该关联，不能靠否定设置通道或拿独立诊断数字相除来代替。
