# YMCC 控制台 Mainline22 — 下拉、防抖、专属边界与统一宽度

日期：2026-10-09（香港时间）。源码仍在主线；未替换安装版、未关闭/重启 Steam、未接管真实硬件。

## 用户需求与实现

1. **核心调度**改为下拉；`big-small`（大核为主）置顶，`only-small`（仅小核）置底。沿用原核心策略值，不发明第二套 CPU 策略。
2. **游戏变速**新增下拉：0.5、0.8、1、1.2、1.5、2、4、8 倍。通过原 `speedhack.ts` 的游戏阀门、进程身份检查和 OpenSpeedy owner；1 倍走原恢复入口。这是原有会话动作，不新增 EXE 变速配置或第二套注入器。兼容性禁止目标仍拒绝，安全回退不显示为已应用。
3. **电源档位**增加 trailing-edge 3000ms 防抖。每次新的选择重等完整 3 秒；显示待应用项，最终只提交一次。回到原已保存值取消待执行项；隐藏 QAM、断线、切换游戏/会话/电源代际/AC-DC、源修订改变会取消，不重试到另一游戏。只影响控制台的用户档位选择，不拖延系统自身 AC/DC 切换及原恢复流程。
4. 用户界面改为 **LosslessScaling 插帧**。已有 owner、XML 路径、原 API 名不改；没有操作本机 LS。
5. **全局方案不可选，风扇除外**。默认状态只显示不可执行的全局占位；控制台服务端也拒绝写回 `padPersona=follow`、`gyroOverride=follow`。首次专属写入同时记忆 AC/DC、核心/线程与当前手柄人格/陀螺仪开关/预设。旧继承字段只在下次明确修改时固化，不在读取中自动迁移。风扇没有 EXE 专属，仍走原全局 owner。
6. **统一宽度**：所有下拉使用同一标签列/控件列；菜单宽度与触发器一致，左右边缘对齐，继续向下展开。

### 原模型的澄清

原 AC/DC 保存按完整方案记录；但原手柄/陀螺仪模型确实允许 `follow`，旧 `on` 还会沿用全局预设。因此“已有专属必然完全不继承全局”不是旧模型已经保证的事实。本轮把控制台明确写入时的选项固化，并取消返回全局选项；没有静默改所有旧文件，也没有擅自重写原主面板的存储契约。

AC/DC 记忆的是所选档位键；原 `resolveGameCustomProfiles` 仍从该档位的原方案库取参数，修改同名预设内容仍会影响引用它的专属。这不是把专属档位重新选回“全局方案”。本轮没有擅自把原方案库改为每游戏参数永久冻结。

所记忆的陀螺仪是开关和四个原预设的选择，不复制原预设参数为第二套配置。`Windows 默认` 是原 OS 核心/线程策略，不等于返回 YMCC 全局方案。LosslessScaling、风扇、变速继续分别由原 owner 管理，不制造控制台的专属存储。

## 延续前轮问题

- Steam 大屏的 gamepad `DropDownMenu` 会用自己的居中呈现；桌面原生 `PositionMenu` 参数契约通过，不能证明大屏真的向下。现在保留原 Steam 下拉触发控件，使用同一 QAM 内的原 `Focusable` 选项列，避免居中菜单、跨窗口 popup 和额外焦点树。
- 取消使用 Escape / Steam Focusable 的取消回调，返回原控件。实际测试用了鼠标和 Escape；未冒充实体手柄 B 实测。
- 修复 native TabsHook 重复使用可变数组时累积多个控制台面板；只去重自己的控制台条目，保留其他原标签和有限清理边界。
- 修复浏览器 timer 函数被当成依赖对象方法调用时的非法 Window 接收者；与已有 MirrorClient 一样以闭包调用原 timer API。
- QAM 隐藏或菜单快照失效会释放未提交的菜单；已经提交的事务保持原身份，按真实 ACK 结束，不把完成中的保存偷偷改目标。
