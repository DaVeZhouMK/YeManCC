# 监控快速快照数据与重复开销修复（2026-10-16）

本轮沿 YMCC 唯一数据层检查原生采集、快速帧更新与统一快照发布，修复已复现的时间戳误更新并去掉重复硬件文本复制。持续优化目标仍然进行中，本报告只对应这一轮。

## 问题与修正

原 nativeMonitorLoop 在约一秒的硬件分支构造 top 文本后，再保存 cachedTopText；在 100 ms RTSS 分支中，每次把该字符串复制给完整 monitorSnapshotPublish。完整发布器同时写入 hwinfoOkAt=frameNow，因此没有新 HWiNFO 读取的快速帧更新也会推进硬件健康时间。

新增 monitorSnapshotPublishFrames，在原有快照互斥锁内校验采集代际与缓存有效性，只移动 FPS 文本、推进序号、collectedAt 与 FPS 心跳。硬件 top 文本、hwDown 和 hwinfoOkAt 保留原值。完整硬件分支继续使用原发布器，停止/重启、关闭任一路及缓存失效后的迟到帧仍受代际保护；帧发布不能自行复活无效缓存。

hwinfoOkAt 是最近一次硬件采集分支健康检查时间，不等于 HWiNFO 原始生产者 poll 时间；原始载荷与生产者时间均未被替换。界面仍从各字段自己的有效期判断数据。

## 开销证据

实际提取修复前/后的生产发布函数，在相同 8 KiB 合成硬件文本与连续 10 次帧发布下计数堆分配：硬件文本相关分配从 10 次降为 0 次，硬件文本的存储地址保持不变。这个结果只证明该重复复制被移除，不能换算成整机 CPU 百分比或 FPS 提升；没有运行 CPU 占用压测。
