# 自动后台预下载与监控通知

更新：2026-10-18。设置入口：设置 → 更新 → 版本和更新 → 自动后台预下载。

实现已经接入主线应用生命周期。`updatePredownload.ts` 继续作为 UI 契约，`updatePredownloadService.ts` 在主窗口启动后注册唯一 Provider，`updatePredownloadScheduler.ts` 调度，`updateManager.ts` 继续独占检查、下载、校验、缓存与用户确认的安装。打开设置页不会另建下载器；编辑器子窗口与 H5 预览不会启动后台任务。

默认开启，主窗口初始化完成后安排 15 秒延迟，游戏状态、网络或恢复事件可以提前唤醒，正常每 6 小时检查一次。在线/睡眠恢复事件可提前触发恢复；关闭开关会原子保存真实策略并取消本进程的后台下载，保留断点。后台任务只在 YMCC 运行期间执行，不注册计划任务或系统服务。

完整包按版本号、固定 Release URL 与 SHA-256 绑定。已下载且校验相同的包无需再次传输；同一版本更换 SHA-256 时按新的包身份校验。继续使用原生 `%LOCALAPPDATA%\YeManCC\update` 下的 `package.zip`、`.part` 和续传元数据，不为历史版本建立无限增长的缓存目录。遇到新版本会由原下载所有者替换缓存；关闭自动下载保留缓存。

后台每轮最多 3 次原生请求尝试，轮内沿用 5 秒续传间隔；失败后按 1 分钟、5 分钟、15 分钟、60 分钟逐步退避，此后最多每小时再试。退避次数与下次检查时刻保存在 `predownload-policy.json`，应用重启也保留。断网时等待；恢复后重新获取正式清单，避免一直追逐已撤回或已替换的包身份。后台连接的每次 IO 使用 30 秒超时，有持续进度的慢速下载不设置总时长上限。

保留现有 Range/强 ETag/Content-Range/SHA-256 校验。服务器忽略 Range、响应实体改变或完整包哈希不符时，原生所有者清理无效断点再尝试。后台新下载包限制 2 GiB，按服务器已知剩余大小预检至少 64 MiB 余量；实际写入/元数据/磁盘错误仍会进入退避。缓存损坏、丢失、残留进度与失败回执不会成为永久失败状态。完整 `.part` 即使在最后重命名前崩溃，也可按 SHA-256 离线恢复。

前端和原生共同维护单一下载所有权。手动安装可等待现有下载完成；后台禁用和生命周期清理不能取消用户主动发起的手动更新。WebView 重建会采用仍在运行的原生下载；每 15 秒读取原生状态可补回丢失的完成回执。读取失败不会擅自释放下载锁、创建竞争下载。

安装与下载分开。后台完成后停留在 `downloaded`；更新页显示“安装并重启”，只有用户明确点击才调用安装器。安装前仍由现有原生链检查哈希、ZIP 安全、目录布局、风扇载荷及版本。后台调度器没有安装依赖。

就绪提醒复用现有监控弹窗：标题“YMCC 更新已就绪”，正文带版本号与设置路径，显示 8 秒。用 Windows 启动 GUID 与 loader boot sequence 组成的现有只读身份去重，跨应用/WebView 重启保持同次开机只提醒一次，睡眠恢复不视为新开机。首次下载完成可在当次开机提醒；以后只要待安装包仍有效，每次开机再次提醒一次。本次开机有多个新版本也只消费一次提醒。

监控弹窗未启用、尚未准备好、正显示其他操作回执或原生拒绝时，保留待提醒，稍后再试，不会强行启用常驻 HUD。只有原生监控载体接收成功才保存本次开机回执；保存失败在当前进程只重试保存，不重播已接收的提醒。无法取得可靠启动身份时不作每次启动都提醒的降级。关闭自动下载不会删除已就绪包，也不抹掉其开机提醒资格。

状态仍为 idle / waiting / downloading / ready / paused / failed；失败信息说明会自动重试。Provider 的 epoch 隔离与真实开关回读契约保持不变。测试覆盖假时钟调度、真实 manager/monitor host 的内存 IPC、抽取正式 C++ 的 WinHTTP/实际临时文件/SHA 校验，以及实际设置组件与正式手柄引擎的浏览器回放；这些不构成物理设备或真实在线升级验收。

游戏运行是自动更新的硬暂停条件。复用现有共享游戏识别与退出迟滞，不创建第二套扫描。第一次识别尚未确认、游戏仍在运行或原生游戏观察超过 15 秒未更新时，拒绝后台检查、下载与缓存校验。检测到游戏后，前端禁止晚到任务继续，原生识别发布点直接取消后台所有者；正在进行的一次网络读取安全返回后不再追加该块，文件 SHA 校验每 64 KiB 检查取消。原生短时 IO 仍受 30 秒超时保护。监控就绪提醒在游戏期间也延后。游戏退出沿用共享 owner 的 10 秒迟滞并要求成功复读确认，再恢复自动工作。

暂停保留有效断点，不记作下载失败，不推高失败退避；用户开关状态不会被游戏自动改写。关闭开关、游戏进入、睡眠和生命周期销毁均禁止取消回执之后另起晚到的自动任务；显式手动操作保留原有确认边界。

旧版本未下完而新版本发布时，每 60 秒做一次只读新版本探测。只在已确认无游戏、后台开关开启时探测，不修改正在显示的旧任务，也不与旧任务并发写缓存。发现严格更高版本（或同版本不同 SHA 修订包），先把目标身份原子保存到策略文件，再请求取消旧任务，等待真实完成/取消回执释放所有权后，直接下载最新目标。A → B → C 连续发布可在 A 的退出期间合并到 C，B 无需下载；旧断点不能作为 C 的 Range 前缀，原生仍按 URL/版本/SHA 身份检查并重置。旧版晚到进度、成功或失败回执由 operationId 隔离。

游戏进入、断网或重启发生在切换中时，先暂停；保存的新目标在重新启动/确认空闲后恢复，再重新读取正式清单，避免复活已知过时的旧包或通知旧版本。探测失败不打断健康传输，较旧清单不使正在下载的后台目标倒退；已安装版本始终受原生严格“只允许更新版本”的校验。源码测试覆盖这些版本跳跃与暂停竞争，真实在线发布时序仍需安装版实测。

## 2026-10-20 卡住恢复与缓存清理

下载和 SHA-256 校验继续在原生后台工作线程执行。后台下载每次网络读写有空闲超时，单轮重试次数有限；没有对持续推进的慢速下载设置整包总时限。前端每 15 秒核对原生实际所有权；下载完成回执丢失时，可以通过同一次 operationId 的原生已完成状态恢复。

新增后台无进展恢复：未观察到本次任务开始约 45 秒、已开始下载约 3 分钟没有字节/阶段/尝试变化，或校验阶段约 10 分钟没有变化时，向原生请求退休该 operationId。`app.retireUpdateDownload` 只做内存中的所有权操作，退出共享 IO 工作队列；它既请求活动后台任务停止，也阻止已排队的同名旧请求重新启动。只有 `retired: true`、`active: false` 且活动身份不属于该请求的有效回执才能释放不确定任务。回执缺失则保留所有权并继续复查；不按前端超时直接并发重放下载。正在退出的原生任务仍持有原有下载/安装互斥锁，直到真正退出。WebView 连接恢复导致 IPC 提前拒绝时也采用此规则；原生明确返回的错误回执按正常失败处理。

已确认退出的后台请求会撤销其 IPC 等待项；旧回执和旧进度不能覆盖新状态。清理期间会隔离晚到的启动状态、版本清单和新版本探测；即使旧包完成后仍在等待下一版探测，清理也能结束这段前端等待，不必等探测网络超时。失败仍进入既有有限退避重试，不自动安装。

设置 → 更新 → 版本和更新新增 **清理更新缓存**。后台下载期间可用，先停止并围栏旧后台任务，再由原生与下载/安装共用的互斥锁进行删除。手动下载、安装及未结束的安装恢复事务会拒绝清理。停止确认的等待上限约 45 秒，无法确认会返回可重试提示，不强杀任务；原生删除请求另有 45 秒的界面等待期限。

删除范围固定为更新目录中的 `package.zip`、`package.zip.part`、`package.zip.part.json`。不接受界面传入的删除路径、不递归删除，不删除用户设置、开关、每次开机通知记录、安装 staging、rollback 或事务日志。目录和叶节点都拒绝重解析点，叶节点按已检查的文件句柄删除；删除期间固定缓存根目录以防其被替换。文件占用、只读或权限失败会报告部分未完成，仍允许再次点击。界面显示已删除文件的逻辑大小，不宣称磁盘实际可用空间一定增加相同数值。

清理使旧目标和“已核验可安装”记录失效，保留后台开关偏好，持久化约 10 分钟的自动检查静默期。网络恢复、活动状态复查、晚到的下一版提示不能跳过静默期；到期且确认空闲后恢复自动检查。用户仍可手动检查更新；希望长期不再下载时可关闭自动后台预下载。清理失败时页面也会退出忙碌状态，并保留明确错误。

游戏规则保持：游戏运行时暂停自动清单探测、下载、缓存校验及就绪通知，显式手动下载保留。短暂检测缺失不当作退出；共享游戏策略在约 10 秒后取得新的成功观察才放行。首次检测失败会继续重试初始化；原生放行回执失败后，周期复查会重新握手，避免一次失败永久暂停。原生独立检查游戏事实的新鲜度，不依赖界面单方面放行。

回归入口仍为 `tools/ymcc_sim/ymcc_sim.ps1 -Domain global -Mode run -Tests network.update-predownload-signals`。保留原有 57 条断言及 23 条消费者场景，新增 15 组、35 条故障与游戏恢复断言；执行真实 manager、scheduler、service、IPC，游戏恢复额外执行真实共享游戏策略和迟滞逻辑，仅底层游戏/原生 IO 与时间使用内存夹具。原生缓存/退休逻辑由 `tools/updater_resume_native_selftest.ps1` 提取正式处理器验证，使用独立临时文件、真实文件占用/只读/目录联接与 SHA-256；网络为注入传输。界面按正式全页手柄导航入口验证两种比例。这些证据不等同于真实网络、安装版、真实游戏或实物手柄验收。

清理后的静默期限也在原生清单/下载入口检查。因此，旧界面丢失任务编号但请求仍在队列里的情况，也不能在成功清理后立即重新下载；手动下载及手动校验不受这项静默期限限制。
