# HWiNFO 恢复配置解析减少无关对象构建 — 2026-10-17

已合入主线 native/monitor_hwinfo_manager.h 的 acquisition 函数。本轮没有修改本机 HWiNFO INI/注册表、终止或拉起 HWiNFO、安装新 EXE 或更新本机产品。

## 改动

恢复配置原先先读取同一份、最多 16 MiB 的 yeman-settings.json，再为整份统一设置构建 JSON DOM。此处只使用 rtss.monitorAcquisition 的 version/enabled/snapshotPolling 三项。

现在对不超过 4 KiB 的小文档仍使用原始 Json::parse；更大文档使用库本身的解析回调，所有字节/token 均正常解析校验，但 DOM 只保留本处需要的策略。不是提前找到字段就结束，也不是用字符串搜索截取 JSON。根对象、相关父对象、版本类型、布尔类型、重复键 last-wins、非法无关语法/数字和错误码语义继续与原实现一致。

文件仍只读一次，不再复制/平移 BOM 后的全设置字符串；没有永久设置缓存、轮询、采集或线程。用户其他设置仍在原仓库中，未被这个读取投影修改。

## 取舍与性能范围

始终采用回调的第一版在极小策略文档中约慢 34%，未采用。最终小文档保留原解析路径，极小样例的九轮配对约慢 0.7%，两轮更快，不宣称该路径有改善；额外分配数量和字节与旧实现相同。

对本次只读取得、12,270 字节的本机设置，解析完整调用的配对中位 cycles 约减少 15.6%，9/9 轮改善；243,786 字节的结构化测试设置约减少 21.1%，9/9 轮改善。以超长字符串为主的 1 MiB 文档基本持平，不宣称优化了词法扫描成本。测试未保存或展示本机设置内容。

在结构化测试设置中，完整调用的分配从 20,084 次/1,686,962 字节变为 15,274 次/922,622 字节。回调仍需读完/校验无关字段，长字符串的解析缓冲不一定减少。

这些都是配置启用/恢复时的解析开销，不是 HWiNFO 常驻或 YMCC 整体 CPU 降幅。没有调整硬件扫描范围、Presented FPS、RTSS 救援、采集刷新率或共享内存超时处理。
