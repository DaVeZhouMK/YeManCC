# 显存数据初始化与复制优化（2026-10-17）

已在 YMCC 唯一 HWiNFO 解析路径中，消除显存诊断／AMD D3D 兜底数据的整块默认初始化和非必要复制。只有本轮实际识别的 GPU 项被初始化及复制，原有 64 项容量上限、不可变共享缓存、GPU 对应关系与数值规则保留。本机已小更新。

## 改动与收益范围

原 `Readings::retainMemoryEvidence()` 即使只识别一两张卡，也先创建 64 个 D3D 记录，写入 128 个默认 double 字段；缓存未命中时又将整张表复制到共享对象。

`native/monitor_gpu_selection.h` 改为固定容量、逐项开始生命周期的内部存储。临时记录与共享对象只构造已识别的项；未使用项不会被读取。相同数值继续共享同一个不可变对象，数据变化时仍只需一次有界共享对象分配。外层 `Readings` 大小保持 15400 字节，显存证据容量保持 1024 字节，没有通过增加持久对象或缓存历史来换取结果。

确定性检查覆盖 0、1、2、64 张卡：

| 路径 | 原实现 | 新实现 |
| --- | --- | --- |
| 有 GPU 时单次默认字段初始化 | 128 | 0 |
| 连续 300 次相同记录的默认字段初始化 | 38400 | 0 |
| 连续 300 次相同记录的堆分配 | 0 | 0 |
| 有效数据变化时共享对象分配 | 1 | 1 |
| 共享对象内容复制 | 64 项 | 已识别项数 |

初始化计数通过仅注入 D3D 默认字段的计数器获得，不是 CPU 百分比或耗时测试。另编译未加计数器的 MSVC `/O2` 隔离实例，确认旧函数确有固定 64 次、每次两个默认字段写入的循环；新函数中该循环消失，新共享内容构造按实际项数执行。汇编只证明这个生产头文件实例的工作变化，不据此宣称整个应用的精确指令数或 CPU 降幅。

这条优化作用于显存证据准备路径；完整解析缓存命中的轮次本来就不会走到这里。因此不会把“每次显存记录调用”的计数冒称为每个实际监控刷新都必然发生的工作。
