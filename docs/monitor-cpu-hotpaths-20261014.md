# 监控高频消费路径优化 — 2026-10-14

本轮在上一轮监控消费优化之后，继续修改主线的数据解析、核心图块和独立输出窗口。全部证据来自离线合成数据回放及浏览器验证，没有测量实际 CPU 占用，没有启动或更新已安装 YMCC、Steam、游戏或硬件采集器。

## 已完成的改动

1. **重复数据包只解析一次。** 每个既有 YMCC 数据 hub 为硬件和帧率各保留一份已成功解析的、完全相同的字符串。曲线更新而硬件包不变时复用硬件解析结果。每次返回仍复制对象及数组，消费端修改、停止清空、会话切换不会污染模板。非法包不记忆；长度超过 65,536 个 JavaScript 字符的包与带嵌套旧版元数据的帧率包继续按原流程解析。缓存只省解析，不刷新观测时间、不延长传感器有效期。
2. **只处理实际显示的 16 个核心图块。** 统一层仍可接收最多 128 项，完整数据整理保留；图块绘制只检查前 16 项，避免每次先整理 128 项再截取。完整核心数据整理直接填充结果，减少一个 slice 临时数组。稀疏项、非法值、缺失及过期时的中性图块行为与修改前一致。
3. **输出传输超时复用计时器。** 新包延长截止时间时保留已经排定的较早唤醒，到点后按最新已准入截止时间决定续排或关闭；缩短截止时间立即重排。始终只有一个传输超时计时器。已取消回调和退出后的迟到回调不能触发关闭或重新启动计时器。传输期限与数据有效期分别处理。
4. **布局直接比较字段。** 比较位置、准星、模板、缩放、间距和显示开关，替代每个输出包的 JSON.stringify 及 DOM dataset 字符串。需要改变位置或组成时仍触发原布局流程，普通数据更新省去该签名工作。

新增 monitorPayloadDecoder.ts 和 monitorHudTransportLease.ts 都是纯处理函数；无采集、文件读写、轮询或独立服务。生产改动仅涉及前端消费代码，没有修改原生文件。
