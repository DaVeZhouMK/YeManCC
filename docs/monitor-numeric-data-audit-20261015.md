## 确认并修正的数值问题

1. **旧格式字段的空值被转成真实零。** `Number(null)`、空字符串、布尔值等可进入原有 `Number(value) || 0` 兼容分支，缺失的 CPU 功耗、频率、温度、使用率及 GPU 数值会被显示成 0；部分有限但越界的值也没有被挡住。现在保留正常旧版数值和非空数值字符串的兼容性，严格区分缺失与真实 0。CPU 必须保留数字类型的存储位置，因此使用明确无效标记阻止把默认值当实测；可空的 GPU 字段直接为 null。现代明确的有效性证明继续要求真实数值类型。
2. **容量与使用率矛盾。** 例如已用 8 GiB、可用 24 GiB、总计 32 GiB，却带有 99% Load，原先仍显示 99%。在容量元组完整且自洽时，现在使用率可由已用/总计换算；与直接 Load 的差异不超过 1 个百分点时仍保留直接 Load 的舍入精度，明显冲突时才放弃该 Load。容量本身冲突时，不据此生成一个看似正常的百分比。另修正可用量大于总量时，前端会保留已用量再重新算比例、原生层却执行不同处理的问题。原生唯一发布者与前端现在一致，内存与显存规则相同。
3. **旧格式电池时长缺少功率约束。** 原先空时长可变成 0，或者没有有效放电功率仍展示旧的 90 分钟。现在旧格式也要求明确有电池、有有效百分比、处于 DC 且功率为有效负值，才展示有效范围内的时长。现代功率或时长元数据不完整时明确无效，不能降格进入较宽松的旧格式分支。无百分比、无有效功率、充电及零功率均不能支撑放电时长。两个输出入口还会再次清除没有有效负功率支撑的时长。真实功率与估算功率原有区别和独立有效期保留。
4. **输出边界允许越界数值。** GPU 温度曾沿用容量字段的宽范围，151°C 甚至极大温度能够进入模型；输出协议的通用有限数值分支还会保留负功耗、超限频率、负 FPS、0 帧时间等。现在模型入口及两个共用输出协议按原生发布者的测量范围验证，越界视为无数据，不把错误数值钳成一个貌似真实的边界值。

这些问题由故障注入确证，并不是宣称此前本机日志一定出现过全部异常。也不把它们等同于已经证明本机跳动的唯一原因。
