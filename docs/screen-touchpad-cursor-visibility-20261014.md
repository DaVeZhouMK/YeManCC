# SteamDeck 光标显隐接管：policy 7（2026-10-14）

## 实际链路与范围

屏幕触摸进入 YMCC 的 Touch/Pen 输入面，经虚拟 Deck HID 报告交给 Steam 当前布局合成鼠标。这里处理的是 Windows 系统光标与 YMCC 补画光标的显示交接；不是另一个独立的 Mode::Mouse/SendInput 模式。

保留触摸坐标、点击分类、震动、鼠标穿透、Steam 布局、焦点和驱动行为。先前导致快速滑动更闪的坐标平滑没有恢复。policy 6 的纯位置更新、位图缓存校正和首次显示前重查继续保留。

## 主线实现

- native/screen_touchpad_cursor_visibility.h：在现有 UI 线程注册 scoped WinEvent SHOW/HIDE 观察器，只处理 OBJID_CURSOR/child 0。不按窗口或进程过滤光标对象。回调只累计计数并合并投递消息，收到后重新读取当前 CURSORINFO；不按旧事件的 SHOW/HIDE 值重放显示。
- native/screen_touchpad_cursor.h：新消息只参与纯 Deck 活动触点及抬指后的保留阶段。系统已显示有效光标或明确隐藏时，及时撤下补画；补画已经显示且仍处于 SUPPRESSED 时，事件路径不移动、不重绘。
- 隐藏到显示需要新的位置时，与原有 24ms 周期共用同一个位置截止时间。预算未到则等待既有 BUS 机会，不先显示旧位置。已排队的周期消息也检查这个截止时间，避免事件显示后紧接着再移动。
- 按下、抬起、取消以及直接 Mouse 路径仍沿用已有边沿处理。新增观察器不增加 BUS、HID 或周期位置刷新率，没有新增工作线程或计时器。
- 两块触摸板交替 MOVE 时保留本会话首次选定的消息接收窗口，不反复重装观察器。配置刷新及关闭在销毁窗口前停止观察。
- 消息携带 generation，拒绝旧消息时不清除新一代 pending。处理当前消息前清 pending，使处理过程中到达的新通知仍能保留下一次核对机会。
- 注册失败继续原有补读。卸载先关闭回调接受状态并核对安装线程；卸载失败保留一个待清理句柄并记录错误，新会话或退出时有限重试，清理完成前不注册第二个观察器。MOVE 不触发重试循环。
- native/screen_touchpads.h：接入消息、将 cursorPolicyVersion 标记为 7，并随原有 state/export 输出观察器计数及显隐记录。

## CPU 与诊断边界

显隐记录为 64 条固定容量环形数组，仅在状态、形状、所有权或采样有效性变化时写入。逐位置变化不会追加条目，热路径不为记录分配堆内存、不写日志文件，JSON 只在原有状态导出时构造。

显隐通知合并限制的是待处理消息数，不是所有事件的发生频率；收到通知后的当前状态查询可能增加。周期位置更新频率不变，尚未测量实际 CPU，因此不能宣称 CPU 已经降低某个百分比。

前一轮 InputHost 的低 CPU 改动仍在主线：raw Deck 报告使用 SteamDeckStateFields 共享值字段，避免为编码创建六轴字典；原 SDK SubmitState 分支继续创建独立字典。这轮没有再修改该链路。

## 后续只读核对：合成提交与当前现场

在 policy 7 交付后再次核对主线，三个生产头文件与交付哈希一致。cursorUpload 的完整位图上传成功后立即缓存已提交的位置，正常可见且坐标相同的路径不会再次做位置提交。首次显示需要额外显示窗口的动作，不能把它直接视为重复绘制缺陷。

微软 UpdateLayeredWindow 参数契约明确允许形状/内容不变时使用空源 DC，位置参数仍可有效；源 DC 为空时目标 DC、尺寸也必须为空，flags 应为 0。当前纯位置分支符合这些条件。原始官方文档与哈希保存于 ScreenTouchpad-Presentation-Audit-20261014/Sources。

DwmFlush 的保证局限于调用者已排队的 DirectX 改动，并不刷新整个会话；WaitForCommitCompletion 等待对应设备前一次 Commit 被处理。所核对资料没有提供把系统光标显隐与 YMCC 层叠窗口原子交接的保证，因此不在 UI 热路径加入阻塞等待，也不据此迁移输入系统或强制更改全局光标。
