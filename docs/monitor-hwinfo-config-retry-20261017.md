# HWiNFO 配置提交临时文件锁重试，2026-10-17

状态：主线源码修改和隔离测试已完成，尚未进行完整产品构建或本机部署。本机 94c0c0fe… 原生版本的四场景恢复实测见 `monitor-hwinfo-manual-recovery-20261017.md`；其中不包含本改动。

迁移复查发现旧 PS1 对复制提交有 5 次、200ms 间隔的重试，新原生 configure 曾只提交一次。使用旧 configure 的实际函数体及真实 Windows 删除共享锁复现：原生返回 5，Win32 32，等待 0 次，原文件保留。该复现不操作真实 HWiNFO。

新增 `native/monitor_hwinfo_config_commit.h`，只对不需要提权的 Win32 32/33 临时文件锁重试，最多 5 次提交、4 次 200ms 可取消等待；每次先确认生产者停止并核对原始文件字节。文件被其他操作更改、删除或生产者出现则停止，不能拿重试覆盖别人的内容。保留字节相同情况下的首次物理提交，不推断它对真实免费共享到期的影响。

`native/monitor_hwinfo_manager.h` 从同一份停止后的原始字节计算合并计划和回滚基线。识别明确的并发冲突，不误回滚为期望计划的外部内容；其他错误只在实际尝试过提交且当前内容仍为本次计划时执行原有回滚。提交后的短暂校验读锁可在下一次核对精确计划字节，避免重复提交。

`tools/monitor_hwinfo_config_retry_selftest.cpp/.mjs` 提取当前产品 configure 的完整实际函数体，执行隔离目录内的真实文件 IO 与真实 Windows 锁，生产者及等待用无害钩子替代。21 项通过，包括短暂锁恢复、永久锁严格 5 次/4 等待、权限/磁盘错误不重试、并发修改/删除/新建保护、取消、生产者出现、相同期望计划、备份和无残留临时文件。测试夹具命名空间缺少 alias 的编译问题已修正。

补跑原生 owner 配置/事务、entry/BAT、IPC 及停更恢复四组回归，均返回 0。没有进行 CPU 占比测试，没有触碰真实 HWiNFO 设置或注册表；隔离配置测试生成的 EXE 仅在任务证据目录内，不作为生产文件或新运行依赖。该改动只覆盖配置提交阶段，初次配置读取等预检仍按原规则报错，没有声称覆盖一切文件占用。
