# GPU 槽位按需初始化：统一采集源头优化（2026-10-16）

本轮继续处理“监控 CPU 消耗从源头优化”。启动时复核上一轮 hwinfo-source-reuse-20261016/ROUND-RESULT.json，上一目标轮分类为 progress；本轮在既有统一采集器内减少 GPU 候选的无效默认初始化，没有增加采集源、线程、定时器或 IO。

## 原因与修改

原 monitor_gpu_selection.h 的 Readings 持有 std::array<Device,64> devices_{}。Device 含传感器身份/名称、功率、频率、温度、负载、电压和显存字段。每次创建原生包时，64 个候选都会初始化，即使当前没有有效 GPU，或者只有一两张卡。上一轮相同源复用只跳过分类；构造新输出包仍会触发这部分工作。

改为固定容量的 union 槽位，每个空槽位不启动 Device 生命周期。仅当现有规则接纳一个新的有效 GPU 组时，用 placement new 初始化一个 Device，并在完成身份赋值后增加 count_。Readings 使用用户提供的默认构造函数，使 Readings{} / NativeMonitorHw{} 这样的值初始化也不会先清空全部空槽位。

容量仍为 64，既有 lastSlot 查找、候选顺序、各指标优先级、功耗优先/会话固定、AMD D3D 专用优先与共享兜底、有效零和未知值语义不变。读取只在 count_ 范围内访问已激活的成员；重新用一个槽位时完整初始化默认值，避免借用旧显卡的字段。

## 生命周期边界

- Device 必须可平凡复制、可平凡析构；Slot 必须可平凡复制，均由编译期断言约束。
- 默认 union 复制/赋值复制对象表示并保留对应激活成员的生命周期。空槽位不作为 Device 读取。
- 不增加堆容器；原 D3D 不可变证据继续使用原 shared_ptr 路径。
- 新/旧包 sizeof(NativeMonitorHw) 均为 15840；sizeof(Readings) 均为 15400。原有 nothrow 包复制要求仍可编译。
- **本轮减少默认初始化，不减少整个原生包的复制字节数，也不减少固定存储容量。** 源映射、快照复制、文本分类、数值解析、发布仍有原有成本。

## 可重复工作量

冻结旧 GPU 头与当前 GPU 头分别接入实际主线 parser/publisher。仅在 Device 已有默认值表达式中加入初始化计数，不改变其布局或复制类别；窗口内不构造发布 JSON，不写日志，不调用真实映射/硬件 API。

每组连续解析 200 个更新输入，周期为 1000ms，每次更改生产者时间、CPU 功率，以及存在时的首张 GPU 功率；源解析复用没有参与该计数窗口。

| --- | ---: | ---: | ---: |
| 0 | 12800 | 0 | 0 / 0 |
| 1 | 12800 | 200 | 0 / 0 |

每次核对候选数，数值校验和前后一致。这是源码工作量证据，不是实际 CPU 时间、整机占用或功耗降幅；满 64 张候选时没有这项减少。夹具还验证复用命中后的包构造不再初始化未用槽位。
