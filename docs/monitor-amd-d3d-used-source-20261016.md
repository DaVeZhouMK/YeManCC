# AMD 显存来源修正与有界复用（2026-10-16）

本轮已把部分 AMD 显存“已用量”的来源修正接入主线，并完成原生解析、统一消费与旧日志回放。**容量和百分比仍未补齐；Win5/ROG 的新版实机显示未验收。**

## 日志确认的问题

沿用上一轮对两个原始压缩包的只读归档结果，未重新采集硬件。

| 样本 | 健康快照 | 原包已用量（MiB） | 总量／剩余量／占比 |
| --- | ---: | ---: | --- |
| Win5 | 58 | 29803–30798 | 全部缺失 |
| ROG Xbox 2025 | 276 | 800–2291 | 全部缺失 |
| 本机 AMD 原始行 | 归档原始传感器行 | 驱动 GPU Memory Usage=100；D3D Dedicated=14.734375 | 缺失 |
| 本机 NVIDIA 原始行 | 归档原始传感器行 | Allocated=5723.859375 | 同组总量=16303，有效占比存在 |

ROG 原设置关闭了“已用显存”文字、选中了占比/图形；而占比为空，因此会像整项显存消失。原始 AMD 驱动读数与 D3D 专用用量不是可无条件互换的统计。不能据此声称 Win5 的 29–30 GiB 一定错误，也不能拿独立诊断的约 8 GiB 直接相除。

同进程其他诊断出现过 Win5 8403652608 bytes、ROG 6220378112 bytes 的适配器容量，但含重复适配器/LUID，整体设置能力验证未通过，尚未证明与 HWiNFO 计数池、选中设备同源。本轮没有把这些数拼接成监控占比。

## 主线实现

1. 在现有 HWiNFO 原始行解析的一次遍历中接收同组 D3D dedicated/dynamic 计数。没有新增采集源、硬件查询、线程或轮询时钟。
2. 对明确识别为 AMD/Radeon、且规范化后既无容量又无有效占比的设备，使用该设备所在传感器组的 D3D dedicated 作为已用量。真实 0 有效。无效或缺失时保持未知，不退回可疑驱动分配量。
3. 已有完整容量元组或有效直接占比的 AMD，保留原结果。NVIDIA、Intel、未知/矛盾厂商名称保持原规则。GPU 功耗优先及会话固定规则保持原实现，D3D-only 行仍不创建可选 GPU。
4. 统一 top 包增加 gpuMemorySource：hwinfo、hwinfo-d3d-dedicated、unavailable。消费端验证选中设备证明；D3D 专用“已用量”不能混入其他来源的总量、可用量或百分比。
5. 高频诊断同时记录 raw / normalized / effective 数值与 effectiveSource，便于下次真实日志验证选择结果。快照仍走已有高频记录队列和体积限制。
6. 完全没有该元数据的旧包保留原兼容形状。334 条远程旧快照没有注入 D3D 行、容量或新来源。

修改范围：native/main.cpp、native/monitor_gpu_selection.h、native/monitor_gpu_memory_evidence.h、native/monitor_memory_network.h（说明文字）、src/bridge/topmon.ts、src/bridge/monitorData.ts、src/bridge/monitorDisplayFeed.ts，以及本轮测试和报告。

## 成本与数据有效期

生产解析回调按当前候选顺序构造至多 64 项、每项两个 double 的不可变数值载荷（1024 字节，另有共享所有权开销）。同一现有解析线程/生产回调仅缓存一块最新值；相同计数复用，变化则换块，旧包的不可变载荷保持正确。缓存不存设备身份或时间，不生成“新观测”。

| 相同输入解析 200 次 | 新增 D3D 载荷分配次数 |
| --- | ---: |
| 修正前（仍使用原驱动读数） | 0 |
| 修正后的反事实版本，测试副本关闭复用 | 200 |
| 当前修正并复用 | 1 |

原版本没有这项来源修正，不能把 0→1 说成 CPU 优化。复用相对同功能无缓存版本减少了重复分配，未测量或换算整机 CPU 百分比。

现有 HWiNFO 解析暂存 D3D 数组仍为至多 256 项/4096 字节。本轮为了接收部分 AMD 的真实输出，在原始行遍历中启用这份暂存；因此不能再笼统宣称“详细日志关闭时完全不捕获 D3D”。完整 NVIDIA 单卡且关闭详细日志时不持有额外载荷；混合显卡中有部分 AMD 候选时，即使最终选择 NVIDIA，也可能保留一块载荷。每次计数变化仍会产生一块新载荷。

两个原生测试直接验证：相同数字复用时，当前观测的生产者时间和 GPU 身份仍属于本次解析；另一个较旧包和它的数据保持不变。消费端也验证生产者时间过期后，重复旧数字不能让显存复活。
