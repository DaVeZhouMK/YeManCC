# 触摸板独立输入通道的停止与命令投递

本补丁接续完整输入复位，只改独立通道的停止和同步命令通知。实际自有隐藏线程被有限暂停，再把该线程的 Win32 posted-message 队列填满：旧停止通知返回配额不足，原 shutdown 等待 1516ms 后失败；旧真实 source sync 也立即返回错误 1816。由夹具另发明确的 sent 通知才清理完旧对照，此清理不计旧产品成功。

通知现在先沿用 PostMessage，失败才调用异步 SendNotifyMessage。两条路径复用一个 helper，停止前置标记、启动超时、命令超时和正常关闭统一使用 requestStop；空 HWND 不再意外发成线程消息。没有新增定时巡检、输入频率或重试次数。

同样的真实队列压力下，候选停止 172ms、真实 source sync 172ms 归还。原消费者的 channel-stop 11 检查和 channel-command 12 检查通过，旧对照各有一项必要失败；四个原生进程的输入源、队列、线程和私有桌面均归还。两候选的产品头逐字相同，最终 stop 函数体等于实测版本，未重跑已通过组或把不同源码轮次拼成完整父门。

这不是 Win5 内部 ProcessEvents 故障的复现，也不证明安装版、实际游戏、睡眠或 CPU 百分比收益。完整 Native/部署未执行，下一自然导出带本头及两个原消费者文件。所有原始结果在 field-win5-191115-20261116 的 STOP-VALIDATION-INTAKE.json 中核收；此前过期的墙钟截止与工作间隔保持原样，后续核收不倒填为旧预算内。
