# 汇总需求停用时释放 FileSystem PDH — 2026-10-17

已修改主线 nativeMonitorLoop 的既有 !top 清理分支，增加 fileSystemReader.reset()。本轮没有部署、重启产品或更改 HWiNFO 配置。

## 发现与范围

之前全部汇总消费者停止、仅 FPS/autofloat 保持活动时，电池与锁帧上限读数器已重置，但 FileSystem Reader 未重置：PDH query 持续保持打开，旧 raw counter 基线也跨越停用间隔。它并未在 FPS-only 期间继续调用 PdhCollectQueryData；本报告不把“保留查询”误报成“继续高频采样”。

修复使查询和基线在全局 top 需求归零时同时释放，重新开启后先采一次基线，下一次真实采样产生新速率。停止期间的磁盘活动不会混入重新开启后的第一包速率。

此处 top 是唯一监控需求层汇总全部消费者之后的结果。只要 TopMonitor、预览或任一监控承载仍需要 top，就保留现有查询；不会因为某一个窗口关闭而中断其他消费者。当前需求协议仍按 top/fps 两族聚合，这不等于每一个显示开关都有独立的上游采集开关。

风扇路径已核实为 passive lock-free receipt cache，无新增设备读取；游戏 LOGO 仅选中并有消费者时订阅既有游戏识别，本轮未改这两条已按需工作的路径。
