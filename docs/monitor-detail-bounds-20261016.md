# 监控快照详细日志与体积限制（2026-10-16）

周期监控快照进入现有统一详细日志开关控制的 monitor-detail.log，不写入普通 native-lifecycle.log，也不向域日志重复镜像。详细日志关闭时，采集回调在复制快照、序列化 JSON 和文件路径访问前返回。

## 数据与执行路径

只消费 YMCC 已发布的统一监控缓存，复用原有采集环节，每秒最多入队一次。100 ms 帧时间刷新分支没有记录调用；不新增硬件读取、采集线程或计时器。原始 top/fps JSON 字符串与来源时间戳保留，另附本地记录时间及队列诊断计数。

文件操作交给现有 IPC 后台池。入队使用 try_lock；队列满、繁忙、调度拒绝或文件操作失败时放弃诊断记录并累计计数。队列限额包含当前正在写盘的记录和字符串 capacity；磁盘写入阻塞不会让生产端等待文件锁。门切换有代际隔离，关闭前的队列或编码结果不能在重新开启后回放。停止监控、关闭详细日志或导出时由后台完成尾批收尾，不加新的刷新线程。

## 硬上限

| 对象 | 限制 | 超限行为 |
|---|---|---|
| 记录频率 | 最多 1 条/秒 | 当前周期不复制/编码 |
| 原始 top+fps 负载 | 12 KiB | 写完整的省略说明与原字节数 |
| 单条序列化 JSON，含换行 | 32 KiB | 丢弃，不截断 JSON |
| 待写负载容量 | 256 KiB 且最多 16 条 | 丢弃新诊断，包含在途写入 |
| 活动文件 | 2 MiB | 写入前预检并轮转 |
| 备份文件 | 仅 1 份 .1 | 新生成文件对最多 4 MiB |
| 导出监控状态摘要，含换行 | 32 KiB | 完整的小型 JSON 说明 |

轮转失败时拒绝追加，不允许借错误继续增长文件。每 16 条或距上次刷新已达 5 秒后的下一次写入刷新，闲置/停止/关门/导出补齐尾批。4 MiB 仅限制新的监控快照文件对，不代表整个跨模块日志压缩包的大小。

## 导出

现有 logs.exportAll 收录活动文件与 .1，JSONL 检查器认识这两个文件，manifest 写入门值、体积限制及字段时间说明。monitor-export-state.json 改成有上限的元数据摘要，保留快照身份、时间、原负载大小、当前样式和字段开关；不重复写 top/fps 原始数据、导入图片或全部自定义预设。原始周期样本只在详细日志开启期间存在。所有异步模式（包括旧的 0/-1 模式）都将日志导出分派到已有后台池，避免在 UI 线程等待磁盘。
