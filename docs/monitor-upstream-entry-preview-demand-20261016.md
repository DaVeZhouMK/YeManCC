## 当前页面的实际问题与修复

调用点复核确认，当前设置页使用 MonitorOutputSettings.vue 内的嵌入式 MonitorHudPreview.vue，只被动订阅统一快照。createNativeHudPreviewOwner 是保留的独立子窗口接口，当前设置页没有调用它。早期把后者固定双通道说成会抵消当前页面的需求裁剪不够准确，不能计入当前本机页面收益。

当前页面存在另外两项实际额外工作：

1. 总开关关闭后，自定义预览被隐藏，但原被动快照/TDP 订阅与过期计时器继续存在，每次推送仍做完整投影。
2. 时间未勾选时，预览投影没有传入 includeClock=false，仍进行本地时间格式化。

现在开关关闭、页面停用或输出为 RTSS 时，嵌入预览不保持这些订阅/过期计时器。重新开启或从缓存页面回来只建立一组订阅。时间开关直接重投影已有快照，不创建新的读取、采集或调度器。浏览器示例模式不订阅真实游戏 LOGO。

新增 tools/monitor_settings_display_demand_selftest.mjs 编译冻结/当前真实 SFC setup，并使用真实 Vue watcher、KeepAlive 和生命周期。只有渲染输出置空、桥接读写/订阅和时钟端口模拟，另增加只读测试 expose 与投影/格式化调用计数。结果为 18 项通过：

- 可见状态的 50 次快照：新旧均做 50 次投影；未选时间的格式化从 50 次变为 0 次，其余 CPU 功耗显示保持正确。
- 总开关关闭后的 100 次模拟快照：旧版仍投影/格式化 100 次，并持有一组快照/TDP 订阅和一个计时器；新版均为 0。
- 时间开关立即显示/清空、重新启用、KeepAlive 离开/返回、切 RTSS、示例页 LOGO 隔离及卸载均验证。

这是操作次数验证，不是 CPU 百分比测试，也没有像素验收结论。

## HWiNFO 正式 BAT 入口

前两轮 PowerControl/YeManHWiNFO.ps1 已支持周期控制和生产者确认，但 BAT 丢弃第二个参数，正式入口无法传递显式周期。本轮在原 BAT 增加可选第二个数字参数，只选择固定值 0/1000/1500/2000/3000。遗漏参数仍完全按原 start/restart 语义运行。不接受的值在启动 PowerShell 前返回 8。

省略和显式 0 都表示保留脚本的既有周期策略。周期请求经原有 PowerShell 参数验证、配置事务和生产者确认处理。原脚本退出码原样返回，包含 12（健康运行但未应用请求）和 13（启动后未能确认请求周期）。没有增加新的 UI、IPC、常驻进程或自动重启。

新增 tools/hwinfo_entry_interval_selftest.mjs 使用真实 Windows cmd 与本轮 BAT；在独立工作目录中以惰性 powershell.exe 替身记录参数/返回指定退出码。路径包含空格、& 和 !。实际 PowerShell/HWiNFO 均不会被该测试启动。40 项验证覆盖旧版丢参数、start/restart/大小写与原未知模式回退、默认和全部支持周期、非法值不启动、6/7/8/11/12/13 回执透传。

本测试初次因 Node 自动 cmd 引号处理失败，已使用 Windows 原样参数拼接，保留固定引号并重新执行真实 BAT；此前失败没有当作通过。

此处是正式入口传输能力，不是已经自动按用户预设/所有消费者选择上游周期。原生恢复仍只调用 restart，不传第二参数，保持用户先前指定的恢复入口与时序。
