## 安装位置

保留运行中进程路径、标准安装目录及现有卸载信息发现逻辑。新增 PowerShell 可选 `ExecutablePath`，用于未登记的便携 HWiNFO64；目标必须是存在的 HWiNFO64.exe 文件，非法显式路径不会自动回落到另一份安装。

按解析到的实际 EXE 目录生成 HWiNFO64.INI。需要提权时，完整事务在释放父互斥锁后重试，传递采样周期和带引号的 EXE 路径。新路径功能验证了包含空格、&、! 的测试路径，不依赖真实注册表写入。实际 BAT 的原调用方式不变；本轮未增加应用 UI 入口，也未承诺其他架构或所有历史版本。

## 避免“可读但停更”的假成功

冻结旧代码复现：陈旧时间戳的可读映射被当成健康 start；新启动后的单份静止样本也被报为恢复成功。这意味着 INI 写入成功或共享内存仍存在，都不能单独证明恢复有效。

新健康检查使用同一共享内存头的生产者时间与已有周期预算拒绝过期样本。启动确认要求两次有效、一致布局的观察中，生产者时间戳向前推进；无效观察会清除前次证明，布局变化后重新确认。使用原生读取器已有的周期扩展头门限、头部一致性复查与新鲜度预算，不要求任何传感器值非零。

继续支持未请求精确周期的旧布局兼容读取，但恢复确认也要求新鲜且推进的时间戳。显式周期只有在已知扩展头与期望值相符时才可确认。时间戳无效、超前超预算、过期、倒退、布局变化与间断均有隔离测试。

启动后的检查改为最多 30 次、每秒一次，复用 Start-Process 返回进程对象的 HasExited；进程已退出时先返回 6，不再先读映射并误报健康。无映射/新鲜数据仍返回 7；显式周期未确认返回 13；见过新鲜样本但未确认持续推进返回 14。健康 start 的显式周期请求仍返回 12，表示未应用。BAT 对新增 14 的传递已有实际 cmd/惰性替身 EXE 测试。

## 操作量与边界

确定性无映射场景：旧代码 120 次共享内存探测、启动后 240 次 Get-Process 枚举；新代码 30 次探测、启动后 0 次 Get-Process 枚举。这里仅描述本恢复函数启动后的等待阶段；退出前防重入与配置事务仍执行必要进程检查，其他旧脚本也未在本轮修改。不是整机 CPU 百分比测量，不是 HWiNFO 稳态采集 CPU 下降证明。

未新增常驻定时器、采集进程、硬件入口或周期日志流。所有操作量测试用独立映射和虚拟时间，未读取真实传感器。
