# 升级器旧数据处理优先级（2026-11-05）

依据用户明确要求：允许放弃旧数据、覆盖或清空，旧数据不能挡住新升级。本规则取代旧“必须保留所有旧记录/未知字段、旧副本校验不通过就阻断新升级”的默认处理。

## 新基准与边界

1. 已授权、版本准入通过、SHA256 和目录/清单验证通过的新完整包，是本次安装基准。新包损坏、越界路径、父目录重解析、真实活动安装互斥仍阻断；不能拿旧数据自愈绕过这些检查。
2. 旧升级记录、可写进度/策略/断点元数据、模块收据、YMCC bootstrap/回滚阶段记录可丢弃。坏 JSON、旧/未来 schema、过大字段、旧注解或旧版本标记不再成为新升级的放行条件。
3. 旧恢复根或元数据路径为目录/链接等异常项时，在已核对的父目录中隔离字面项，再新建正常记录。不跟随链接递归清理外部目标；系统权限/磁盘故障和真正活动句柄无法用“允许清空”凭空绕过。
4. 新安装授权明确创建管理员/SYSTEM受保护记录，不合并旧字段，不要求旧记录备份。当前安装内部的 operation/version/hash、状态迁移及源变化仍核对；不能把仍在运行的另一个安装当旧数据清空。
5. 已验证的新模块/Loader+插件组合整体覆盖旧组合，旧记录版本不阻止安装。HIDM BUS/内核驱动的安装/重启仍由原 setup 链处理，本规则不私自卸载驱动。
6. 只清理 YMCC 自有输入模块两个目录内允许管理的旧文件、YMCC 侧边栏 dist 旧资源；不清空其它 Decky 插件或无关程序目录。损坏收据和同名目录可隔离重建，只读自有目标可解除只读后原子替换。
7. UI进度写入失败不是安装失败。记录诊断并有界返回，后续写入自愈；受保护提交记录仍是完成依据。失败且未完成回滚时保留本次新源暂存，以便修复，不清理到无源可修。
8. EXE .old 只有本次实际核验后才可用于回滚；陈旧/损坏/他人改动的 .old 不能覆盖尚未开始替换的主程序，也不能让回滚误报成功。

9. 每次安装使用新的 staging 目录和本次 rollback 目录内的 EXE preimage，旧 staging 清不掉、旧 .old 被占用/同名目录均不再是新安装前提。旧缓存的物理清理由原清缓存入口处理，失败不循环重试到卡死。
10. 模块新清单文件已经全量匹配时，也必须通过原事务计划收口旧自有 DLL 和旧收据；不为清理旧状态强制要求再次取得完整 ZIP。InstalledPayload 模式只允许同一安全目标与已经匹配的新文件，不能放行坏新源。
11. 可选的 Decky settings 迁移收据不能阻断新 canonical 收据；异常父链接不读、不跟随、不清理。新插件身份与新文件哈希须先于旧状态重建核对。
12. 维护互斥覆盖本次安装收尾，清理异常也必须释放；不删除已不使用的固定 EXE.new，避免影响其它来源。

## 验证范围

本轮只运行实际原生存储函数和已生成安装脚本的定向诊断、原 journal storage 选择用例；模块使用真实文件事务的合成文本载荷，不启动真实应用/Loader/驱动。非提权ACL诊断把管理员身份映射为当前所有者SID，ACL保护位与文件读写为真实系统行为；不冒充管理员实际整包升级。

普通导出/FastRelease仍默认夹具NOT_RUN，不因本规则新增minimum或发布父门。完整产品编译、整包、管理员现场升级、安装及硬件验收须分别说明。旧已发布/已导出0.0.38附件不重标为包含本次修复。
