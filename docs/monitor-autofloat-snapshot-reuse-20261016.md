# 自动调节同轮统一快照复用（2026-10-16）

本轮优化自动调节控制周期对统一监控快照的重复消费。保持 YMCC 原有唯一采集者和统一入口，没有增加 HWiNFO、Windows、文件或硬件读取来源，没有新增轮询、线程或定时器。

## 修改前证据

真实 `autofloat.ts::tick` 先通过 `readStatus()` 调用 `readMonitorSnapshot()`，健康检查到期时又异步进入 `ensureHwiNfo()` → `hwinfoStatus()` → `readMonitorSnapshot()`。第二次读取发生在第一次完成以后，在途请求合并不能消除它。

测试使用当前 `autofloat.ts` 和真实生产 `monitorData.ts` 单例，只有外部 IPC、文件系统、电源方法和时钟替换为隔离夹具。native 缓存返回同一轮已经发布的 seq 和文本，不在每次消费时伪造新的采集。

冻结修改前源码得到 `BASELINE-COST.json`：一次正常且健康检查到期的 tick 有 2 次物理快照调用、2 次完整控制副本。先复现后修改。

## 生产修正

- 将原状态映射抽为私有 `statusFromSnapshot`，控制 tick 直接保留本轮读取的快照。公开 `readStatus()` 仍每次通过统一入口读取，并使用同一原映射。
- `monitorData.ts` 仅增加 `monitorSnapshotEpoch()` 只读访问器，返回已经存在的 stop/session revision。没有新计数器、缓存或生命周期机制。stop 发出以及真实 native 会话替换会使其改变；常规 seq 前进不会使其改变。
- 在首次 read 的 await **之前**捕获自动调节运行批次、目录、既有 revision、单调时间和墙钟时间。
- 健康检查只接收本 tick 的私有观察。它先经过一个异步检查点，然后同步核验上下文并消费健康时间戳，保持通知不在调用当下触发。
- 只有单调年龄 `0 <= age < 1000 ms`、墙钟没有退回读取开始之前，且运行批次、当前目录、stop/session revision 一致时复用。
- 超时、时钟回退、运行/目录变更、停止或会话替换时，使用原独立读取；启动/独立健康检查始终独立读取。

复用的是同轮有界的观察值，不承诺它覆盖同一会话随后发布的每个新 seq。没有跨 tick TTL 缓存，HWiNFO 健康检查的原间隔和 30 秒错误宽限保持。

复用需要在健康检查到期时建立一个小的私有观察对象，另有时间和 revision 比较及一次异步检查点。这不是零开销；这里只用确定性计数证明减少了完整读取和复制，不将它换算成整机 CPU 百分比。

| 健康检查到期的一轮：快照调用 / 完整副本 | 2 / 2 | 1 / 1 |
| 健康检查未到期的一轮：快照调用 / 完整副本 | 1 / 1 | 1 / 1 |
| 旧 native 文件通路，协商后健康到期：文件读取 / 完整副本 | 8 / 2 | 4 / 1 |
| 120 个现有一秒节拍，正常持续状态：快照调用 / 完整副本 | 160 / 160 | 120 / 120 |

旧通路的四个文件仍并发读取，心跳夹具使用真实 `{ts: ...}` 形式；没有增加文件采样频率。2,000 次 revision 访问不产生读取、复制、需求或调度。
