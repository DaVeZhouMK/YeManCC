# 核心负载图块：消费边界与视觉上限（2026-10-11）

## 最新确认样式
- 只显示单排纯图块，最多 16 项；不画编号、百分比、数量、刻度或核心标题。
- 使用统一接口数组中的前 16 项，保持排序及 null 槽位；不是把多线程平均成 16 核，也不是虚构物理核拓扑。
- 少于 16 项不补齐；零占用为空底块，未知项为虚边框，无假填充。
- 统一数据包仍保留有界的 128 项给其它消费端；16 是本组件显示上限，不修改全局数据数量。
- 所有布局均使用约 1.2em 高的一行；无动画、无额外读数/定时采集。

## 唯一数据层接入契约
扩展的是现有 monitor.snapshot 的 top JSON，经 monitorData.ts 进入现有缓存。HUD、Steam 插件和预览不读取 HWiNFO、Windows CPU 计数器或 RTSS 传感器。

字段：
- coreUsage?: (number | null)[]：实际占用 0–100，缺失为 null，0 不得表示缺失。
- coreLabels?: string[]：与数组位置对应的真实核心/线程/处理器组标识；不在屏幕绘制，仅用于辅助技术身份描述。
- coreUsageTs?: number：该数组实际采集的 epoch 毫秒时间；若 Windows 源独立于 HWiNFO 必须给自己的时间戳。6 秒过期或未来/非法时间不展示，不可借用 FPS 或页面刷新时间复活旧值。
- 老版本无这些字段时保留旧对象形状，不加入任何模拟数据。

选择 Windows / HWiNFO、处理器组枚举、全核完整性以及采集成本均由 YMCC 既有唯一数据层负责。本次没有实现任何采集器，已精确撤回本轮未部署的 HWiNFO 专用核心解析；没有整文件恢复其它任务的 native/main.cpp 改动。
