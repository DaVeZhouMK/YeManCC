# 原生汇总字段查找减少临时字符串 — 2026-10-17

采用 std::string_view 版本，已合入主线 nativeMonitorTopPayloadText。本轮未部署、未重启产品、未改变采集/数据有效期或用户配置。

## 依据与实现

仓库固定版本 deps/json/json.hpp 的字符串指针 operator[] 会先构造 object_t::key_type。此前汇总对象虽已复用节点，长字段名每次更新仍会构造并释放临时 std::string。新版本使用一个局部字段访问函数：以带长度的 std::string_view 查找已有字段，只有缺失字段才插入。所有数值、字符串、数组和可选字段的赋值/清除表达式保留，不根据值相等跳过赋值。

新增明确的 <string_view> 依赖；没有第三方库更新、永久指针缓存、字段索引数组、采集入口、线程或定时器。源码只精确替换当前汇总函数并添加该 include，其余并行改动保留。

## 两个候选的取舍

第一版以 const char* 做透明查找：虽然分配从每包 46 降到 23 次，但九轮配对计时的完整构造 cycles 回退约 6.8%–8.0%，未合入。

带已知长度的 std::string_view 版本同样降到 23 次分配，三类工作负载九轮配对全部更快。配对中位 cycles 改善约 3.06%、2.73%、1.07%；这是完整汇总构造（包含等价核心输入准备和输出销毁）的局部计时，不是整进程 CPU 降幅。第一版和采用版的原始结果分别保留为 PERF-RESULT.json、VIEW-PERF-RESULT.json，不能仅拿分配数量证明速度收益。
