# 生产者时间溢出：数据有效性与异常路径开销修复

日期：2026-10-16。承接 HWiNFO 上游配置优化，本轮在现有唯一原生监控读取入口修复生产者时间的整数边界，避免异常时间让数据伪装为新鲜，并提前结束无效传感器解析。

## 复现证据

原生 HWiNFO SM2 头部的 `pollTime` 是 64 位秒值。原工作线程先计算 `pollTime * 1000ULL` 再与当前毫秒时间相减；乘法若溢出，结果可能绕回当前附近。原健康判定只有非零时间检查，因此没有阻止该输入。

使用本轮变更前冻结的实际 parser、freshness/header 和 publisher，构造 `pollTime=18446745773709552`、当前毫秒时间 `1700000000000`。旧乘法绕回 `now+384`，旧 age 路径归零，原健康结果为 true，展示时间被更新到当前。实际唯一 hub/model 也把夹具中的 CPU 30 W、65°C 作为新鲜数据显示。该复现使用合成异常输入，不是本机采样，不证明此前用户实机跳动由它引起。

## 修复范围

`native/monitor_freshness.h` 增加生产者时间可表示性检查：共享头虽存 U64 秒，YMCC 的 epoch 毫秒发布使用 signed 64-bit，只有能无损换算成该时间域的秒值才通过。统一 age 辅助函数在乘法前检查边界，不改变既有可表示时间的时钟回退策略。

`native/main.cpp` 只改两处：parser 读取初始头部后先检查时间边界，再进入布局、复制和分类；原工作线程使用上述安全 age 函数。不可用时间会让本次读取失败并清理现有复用缓存；已有外层读取对非不稳定失败不追加三次读内重试。健康/FPS 允许判定还独立检查同一边界，不能靠其他调用者传入 fresh=true 绕过。

保留 pollTime=0 的既有布局可读行为，但它仍不健康；保留真实 64 位秒值，不截断到 32 位；正常冻结失效、下一次真实更新恢复和可表示的系统时钟回退行为保留。没有新增采集器、时钟读取、线程、定时器、配置文件或运行日志。

## 异常路径工作量

同一 2,048 行夹具，旧 parser 在该溢出输入下仍从生产者复制 647,168 字节读数区并保存缓存；修复后在头部返回，复制量为 0，缓存不保留。计数器仅包围实际 parser 中从读数区来源指针的 memcpy，未把 header 小字段读取或之后的缓存复制混入该数字。

这项节省仅对应无效输入路径，不是正常运行的 CPU 百分比收益。正常数据的解析和发布保持原结果；本轮没有 CPU 百分比测试，也没有把前轮缓存/字符串分类的历史优化重新计为本轮收益。
