# 统一 TDP 回执观察者的有界通知修复（2026-10-16）

本轮修复 YMCC 统一 TDP 回执源的观察者登记与重入通知边界。生产仅修改 `src/bridge/tdpRuntimeState.ts` 的通知部分，没有改变写入请求、功率代际、AC/DC 归属、成功/失败确认、接受瓦数校验或实际下发。

## 修改前负例

实际编译修改前 store，以同步回调和合成回执复现：

- 一次 invalidate 通知中，观察者取消自己并重新登记。原来的 live Set 遍历会继续访问重新加入的条目。有限步夹具到第 8 次才停止重绑，使测试可结束；这不是生产中的 8 次上限，也没有运行挂死试验。
- 同一个函数由两位 owner 登记，第一位取消后第二位丢失后续 revision=2 更新。
- 旧 disposer 再次执行，能够删除后来使用同一个函数的新登记。
- 一个观察者在 30W 回执通知中完成新 45W 回执，另一个观察者会收到两次同 revision 的 45W：一次来自内层新发布，一次来自外层继续遍历。

以上瓦数和写入完成均为合成输入；本轮没有对本机执行功率写入。

## 修改

每次 observe 生成独立、递增的登记身份。每轮 publish 捕获开始时的登记序号和当前只读快照：

1. 只处理本轮开始前已经登记且仍存在的观察者。新登记已经在 observe 中收到当前初值，不再由旧循环补发。
2. 同一函数的多个登记可以分别释放，旧 disposer 只删除自己的登记。
3. 回调中若产生了新快照，内层发布拥有最新状态的通知；外层停止继续重复派发。

使用原有 Set 顺序遍历，没有新增 Array.from 或观察者数组快照。没有增加队列、历史缓存、线程、定时器、IPC 或硬件采集。

这是最新状态观察接口。重入发布时，仍然以新状态为准；没有把它改为完整事件日志，也不承诺每个观察者消费所有已经被后续状态取代的中间值。每份状态继续冻结，当前 get 与写入回执的所有权规则保持原样。
