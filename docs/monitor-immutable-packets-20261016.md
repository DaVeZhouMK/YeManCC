# 监控只读快照边界与重复比较优化（2026-10-16）

本轮修复已校验 HUD 数据对象仍可修改的问题，并利用真正不可变的数据减少重复比较。继续消费 YMCC 统一数据层；没有新增数据入口、硬件读取、轮询、采集线程或定时器，没有部署、重启或游戏操作。

## 已复现的数据问题

原 boundedHudData 用 WeakSet 识别自己返回的快照，后续相同对象直接返回；但该对象的 values、freshUntil、部分数组及外层仍然可写。在修改前冻结源码上，可以将已返回的 CPU 功耗改成 Infinity、核心负载改成 140、帧历史改成 -10，或修改有效期，再提交该对象时均绕过重新归一化。

另一个负例是外部冻结 getter：初次返回核心负载 20 并通过检查，之后 getter 返回 140，旧快照随之变化。外部冻结标签也有相同风险。这里是确定性边界复现，未对用户此前的实机跳动建立因果结论。

## 修复与工作减少

- boundedHudData 为自己创建的数值、白名单有效期、核心负载/标签、兼容核心频率、帧历史和外层对象完成冻结后，才标记为可复用。缺失、异常和空数组路径同样只读。
- 原始输入始终保留可修改性，不被入口冻结；用户/调用者修改原始输入后，再次提交仍正常产生新快照。结构化克隆和 JSON 序列化继续可用。
- 核心标签在原统一 JSON 入口创建普通、校验并冻结的自有数组；原 markCoreUsageLabels 兼容函数也改成生成/复用这种自有结果，无法给外部 getter 或可变数组直接打信任标记。相同 wire 文本的标签共享保留。
- 普通 HUD 帧历史与具备 Presented/RTSS 证明的历史使用不同私有标记。普通 HUD 仍保留前 120 项、非负数及稀疏空位规则；它不会绕过 Presented 历史的正值、上限和证明校验。
- 同一份不可变快照可以直接判等；不同不可变快照若共享同一只读数组，可跳过该数组逐项比较，仍比较各数值和原有 FPS 身份/截止时间条件。外部/可变对象继续检查。
- 曲线缓存只对自己生成的不可变历史按引用复用；外部冻结 getter 和可变历史仍重读，修改后重新绘制。每个 renderer 只持有上一份有界历史及曲线路径。
