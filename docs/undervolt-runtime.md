# CPU 降压：统一运行与延后保存

性能调度与设置页只消费 `src/bridge/undervoltRuntime.ts` 的单例状态和操作；没有页面私有开关、额外硬件消费者或页面保存定时器。设置页仍复用 `cpuctl.ts` 的能力探测、负偏移范围验证和严格接受回执校验。全局性能页显示快捷开关，游戏专属及独立场景编辑器不提供另一份降压配置。

调整完成即提交电压请求。仅取得匹配的接受回执后，才由原生 `cpu_undervolt_trial_native.h` 开始 30 秒试用窗口。接受回执不等于当前偏移已回读，也不证明硬件稳定性；界面保留此区别。未知、不支持及 ROG 掌机均不派发电压请求，快捷入口仍可点击显示灰色说明。

原生只在试用期间使用一个 Win32 窗口定时器，无新增常驻线程、无空闲轮询。隐藏、最小化、托盘关闭（隐藏）及路由切换均不撤销。设置页重新进入只读取同一原生状态，既不重置期限，也不重新派发硬件请求。页面计时不负责保存；后台页面定时器节流不会决定何时落盘。

新调整先撤销旧保存令牌，然后执行原有硬件请求；迟到旧回执不能重新布防。30 秒到期只更新统一配置中的 `cpu.undervolt`，与其他 CPU、手柄、场景数据无关。写入复用原配置锁、兼容检查、备份与原子提交，并核对该字段自试用开始没有被另一个配置操作改动。失败、超时、不确定回执、写盘失败均不自动重试保存。

真正退出、系统关机、睡眠或当前 WebView 进程失败会撤销未完成的保存。试用候选从不提前写进主配置、备份或旧 `cpu_autostart.json`。旧的自动启动实现继续关闭；新启动只恢复此通道已保存且与当前设备身份/单位/范围匹配的设置。不导入旧预设为新降压参数。页面刷新若原生试用仍在，则加入原期限；不套用旧值覆盖当前试用。

取消调整会通过同一执行通道提交上次保存的参数，再撤销新保存；恢复默认同样提交 0，然后按正常 30 秒规则保存。关闭以 0 恢复默认，但记住所选负偏移以供下次开启使用。

## 定向验证

- `cpu.undervolt-runtime`：`node tools/undervolt_runtime_selftest.mjs <全新证据目录>`。直接编译正式原生头；负例含越界、旧令牌、错误回执、ROG、退出/故障/睡眠中断、并发配置和写入失败。另用真实隐藏 Win32 消息窗口运行 30 秒，无网页或页面计时器，保存端为隔离内存。
- `cpu.undervolt-ui`：`node tools/undervolt_ui_browser_selftest.mjs <全新证据目录>`。复用原性能预览构建器，执行正式运行模块和两页组件；仅原生/硬件边界为内存端口。覆盖 720p/800p、组件卸载切页、隐藏状态、两边开关同步、失败请求、ROG、已保存开/关的启动恢复。
- 现有 `tools/performance_panel_navigation_browser_selftest.mjs` 继续检查性能调度原导航行及独立配置边界。

测试目录中的计时与文件端口不会访问真实硬件或用户配置。原生整文件编译、隔离行为验证、安装版和物理降压测试分别记录；本次接入不自动授予实机调压、部署或物理崩溃测试权限。上述入口显式运行，不添加到普通导出的默认完整夹具链。
