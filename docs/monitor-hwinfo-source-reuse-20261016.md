# HWiNFO 统一采集源：相同内容复用解析结果（2026-10-16）

本轮继续落实“CPU 消耗从源头优化”。已在现有 nativeMonitorLoop 的同一采集线程内接入有界解析结果复用；原始数据、布局、传感器身份及周期全部相同才跳过重复分类。日志用于核验，没有增加消费者采集、采样线程、轮询定时器或硬件来源。

上一目标轮完成了稀疏内存/网络和按需历史最大值读取，本轮启动时核对当前源码与上一轮 ROUND-RESULT.json，分类为 progress。本轮不代表整个长期目标完成，显存容量/百分比关联及不同机器的新版本实机验收仍未闭合。

## 源头接入

- 新 native/monitor_parse_reuse.h 提供仅由采集线程持有的一份 Reuse<NativeMonitorHw>。native/monitor_freshness.h 暴露类型，既有新鲜度函数保持原逻辑。
- monitorParseHWiNFOView 新增可选复用指针，默认关闭。原有纯解析调用、带初始值的离线夹具继续走原行为；生产 reader 总是提供新建的 candidate。
- 原有映射打开、映射区查询、读数有界复制仍执行。命中后减少的是文本标签/单位分类及内存、网络、GPU、FPS、温控等重复解析，不声称硬件查询已经停止。
- 完整布局印记的 10 个字段和采样周期组成显式 key；另核对详细诊断需求。使用字节比较验证读数快照和完整传感器表，避免仅凭秒级 pollTime 判定。
- 命中边界仍执行现有屏障后的布局、周期和完整传感器表核验。发生变化则标记不稳定，沿用原 reader 最多 3 次、每次 15ms 的有界重试。
- 读失败、映射/视图/区域查询失败、消费者全关、采集代际切换或映射名称变化均使旧复用失效。缓存局限在现有线程的生命周期，没有全局设备身份缓存。
- 每轮仍在原位置执行 GPU 功耗优先/会话固定选择及新鲜度判定。复用对象不提供新时间戳，保留原 producerPollTime；旧值无法因为复制而成为新观测。

## 启用范围与资源上限

仅格式已确认、原始周期 1500–60000ms、传感器范围可完整核验，且读数区与传感器区合计不超过 1 MiB 时启用。

源周期 1000ms 或更快、周期未知、区域重叠/未确认、超预算大表，继续完整解析并释放旧复用。这个门用于避免每轮都变化的数据还承担额外整块保存成本，不会修改用户的采样周期或输出刷新率。

长期最多保留 1 MiB 原始字节加一份固定原生包及少量元数据。本次 sizeof(NativeMonitorHw)=15840 字节；GPU 附属计数继续共享已有不可变载荷。容量增长时更换有界 vector，瞬间新旧原始块合计最多 2 MiB，之后只留一份；构造后也检查 capacity 上限。既有 parser 的 32 MiB scratch 上限保持原值，该缓冲不属于新增资源。

Packet 类型由编译期断言要求复制构造和赋值 noexcept，防止未来把会分配的容器悄悄加入热路径。输出对象独立于缓存，调用者修改输出不会改变缓存原包。

原生测试编译冻结旧解析器/reader 与当前真实解析器/reader，仅把 Windows 映射 API 替换为固定内存。窗口内不执行 JSON 构造、发布或日志写入。

复用仍有成本：现有映射/复制、字节比较、命中时固定原生包复制，数据更新后的额外保存。频繁变化、超大数据及失效恢复继续支付完整解析成本，因此不宣称所有输入都能获得相同比例收益。

## 正确性验证

- 冻结/当前真实 parser+reader 各 48 项，16 个完整发布包及补充原生字段逐项一致。
- 命中只跳分类；同秒数值、标签、单位、GPU 名称、sensor ID/instance、完整传感器表、生产者时间或周期变化均使其失效。
- 诊断需求开关、代际切换、映射名称切换、空闲释放；字节/周期边界、未确认布局、超预算表、容量增长以及缓存分配失败后的正常采集/恢复。
- 真实 reader 函数在伪映射环境下验证打开/映射/关闭配对不变、三类读取失败清空，以及命中期间布局变化的原有有界重试。
- 原始时间超过既有停更阈值后，真实 monitorFreshnessTick 判陈旧，原生发布不再提供有效硬件数值。
- 双 GPU 命中仍选择高功耗 NVIDIA；已固定的 GPU 拔出后，不从仍在的 AMD 借用显存或伪造 0。
- 额外比对原生 FPS/FPS1/帧时间/槽位、温控历史、虚拟内存、电池功率/剩余时间与有效性证明；复用不会遗漏这些未直接出现在 top 内的字段。
- 消费端 18 项，实际统一 hub、现有两种 HUD 协议与边界归一化，验证源复用没有改变数据及过期行为。
- 采集线程接线 14 项属于源码断言，明确区分于编译执行的 reader 测试，不等于全应用线程实机验收。
- 既有内存原生 19/消费 31，GPU 原生 17/消费 14，详细证据 36，日志边界 48、IPC 8、接线 12，数据链路 31，生命周期 13，类型检查通过。
- AMD CSV 专用/共享及稀疏编号回归 47 项、消费 40 项；Win5/ROG 334 条原始快照回放兼容。
- 历史源消费优化回归 2071 次完整解析、2500 次快照服务、24 次脉冲对比通过。历史移动/扫描收益不归为本轮新增收益。

## 中途发现与修正

测试构建器最初把 size_t 与 unsigned 放在同一句 auto 多变量声明中，造成编译错误，已拆开；伪映射名的转义也按原 reader 字符串对齐。

扩展夹具后，同一测试 main 同时持有数十份原生包和缓存，触及默认栈限。将夹具缓存所有者放在测试堆上，保持生产 parser、单个生产线程所有者及默认栈不变；计数窗口在夹具所有者创建之后才开启。没有提高栈限或改生产包大小。

首次接线测试截取空闲代码的终点误取了前面的变量初始化，已从分支起点后寻找；首次消费者比较误把未经协议归一化的数据与协议输出做形状完全相等，已改为比对既有 boundedHudData 的正式契约。原生前后完整输出比对没有放宽，生产数据未为夹具更改。WIRING-FIRST.json 保留首次接线结果。

## 局限与交付

共享内存读取仍采用现有有界复制加前后印记一致性检查，不宣称获得生产者原子快照；同秒实际内容变化有独立失效验证。源身份表在复用路径被更严格复核，无法核验的布局不进入缓存。

本轮仅源码与隔离测试，没有安装、重启程序、切换游戏、真正打开硬件映射或测量整机 CPU。显存容量/百分比仍需要与所选 GPU/同一内存池相对应的有效容量来源，本轮没有在每秒监控里增加独立设置查询。
