# 监控按已选字段登记采集需求（2026-10-16）

本轮修复自定义 HUD 无条件登记 top:true、fps:true 的问题。改动位于现有统一数据消费链：monitorHudModel、monitorHudSampleSource、monitorHudHost。没有增加数据采集入口，monitorData.ts、原生采集、输出协议与 RTSS 所有权保持本轮冻结基线。

## 实际改变

- FPS、1% Low、帧时间及曲线需要 FPS 通道。帧率上限还需要 top 通道提供 RTSS Global 的限制值，并保留 FPS 家族显隐依赖。
- 已就绪的其他硬件项目需要 top 通道。时钟、YMCC 实际生效 TDP 上限及图片不需要原生传感器通道。未就绪的最高核心负载图形不触发需求。
- 按用户保存的字段开关计算需求。无数据、自动隐藏或 FPS 入场门不参与关闭采集，避免字段因暂时缺数停掉自身数据源。
- 同一 HUD 的多个显示承载仍共享一份快照订阅、一份 TDP 订阅和一次初始读取。实时改选先替换同一 owner 的需求，再释放旧令牌；其他 owner 的需求继续取并集。
- 修改采集需求复用正在运行的 HUD 绘制时钟，真实 host 集成验证其 HWND、nonce 和初始读取次数不因字段切换增加。

## 验证结果

- 新需求测试 55 项：冻结版本 CPU-only 仍登记两路，新版只登记 top。覆盖每项字段依赖、空选择、相同选择无工作、双承载、其他消费者、缺数不自停、TDP 独立快照、失败替换保留旧租约与恢复。
- 新真实 host 集成 10 项：实际 host、coordinator、router、desktop owner、sample、clock 和 unified hub，只有外部 IPC/进程/文件等边界模拟。覆盖加载设置、实时切换、帧率上限、软件数据、其他 owner、100 次相同设置、关闭与完整释放。
- 现有消费生命周期 13 项、数据链健壮性 31 项与 vue-tsc --noEmit 通过。
- 两项新测试记录实际生产依赖 SHA256。补丁仅含本轮文件，并对冻结基线做 apply --check 与空白检查。

测试中修正了两项错误假设：原需求测试把原有重试定时器设为直接抛错，导致切换在停止后被测试替身中断；已改为可清理的虚拟定时器。既有 hub 的原生协议为先停后开，允许短暂原生双关；测试明确验证逻辑需求连续及最后收敛，没有更改协议来满足测试。真实 host 初始化还会用时钟完成可用性探测，不能假设初始化总共只有一次 clock.start；已验证字段切换不增加初始化后时钟启动数，且最终无残留租约/计时器。

## 上游边界

这是向 HWiNFO 上游裁剪推进前的消费者需求修复。关闭 HUD 的 FPS 请求不等于已经关闭 HWiNFO 的 PresentMon；top=false、fps=false 也不等于可以停止整个 HWiNFO。RTSS 尚未通过该 HUD 注册需求，不能据此全局停进程或禁用它仍需的数据。

本轮没有部署、操作游戏、改变 HWiNFO 进程或注册表，也没有测量 CPU 百分比。结论仅为不必要的 YMCC 采集请求已在实际消费链上被移除，不能据此声称上游 CPU 已降低。
