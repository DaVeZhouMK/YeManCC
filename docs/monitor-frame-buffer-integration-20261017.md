# RTSS 帧输出缓冲复用接入

日期：2026-10-17，Asia/Hong_Kong。本轮修改了主线源码，未链接发布、未部署本机，也没有重启 YMCC、HWiNFO 或游戏。

## 这轮改动

监控帧输出类已经有可复用的 `packetTextView()`，但两个生产调用点仍把完整 JSON 树复制出来，再调用 `dump()` 生成文本。本轮把它接入现有统一数据链：

- 1 Hz 普通 FPS 输出直接使用可复用序列化缓冲。
- 100 ms RTSS 曲线输出使用同一缓冲，并通过借用发布函数交接给快照缓存。
- 借用发布通过 `swap` 把旧缓存字符串交还给 `Output`，下一帧复用容量。
- 旧发布函数仍保留作兼容入口；代际、停止、有效性、HWiNFO 健康时间戳、FPS/LOW 证明和 16/24 KiB 上限保持。
- 序列化器采用与旧 `json::dump()` 相同的严格 UTF-8 行为，非法字符串不会从报错变成静默替换。

## 验证

- 帧输出接入测试：**15,978 项检查、2,080 组比较通过**，覆盖 Presented FPS 优先、RTSS 救援、1% LOW、帧时间曲线、硬件失效、时钟回退、PID 复用、无效 UTF-8、生成代际、停止屏障和容量上限。
- 普通输出和快速输出的完整数据包、类型、时间戳、健康证明与缓存状态均保持一致。
- 实际当前 `Output` 回归：34 项、1,942 个数据包通过。
- 快速发布接线：8 项通过；快通道仍只在 RTSS 样本前进时发布，不增加详细日志，也没有降低原有刷新频率。
- 发布边界：21 个场景通过；快照边界：13 项通过。
- 之前的高频快照 envelope 优化重新回归：51,373 项断言、4,497 组响应、2,432 组推送，G3E/ROG/Win5/本机共 192 份真实快照回放通过。
- 当前整份 `native/main.cpp` 翻译单元编译通过。

## 分配工作量

在实际生产调用点和当前 `Output` 上预热后测量：

- 普通 1 Hz 路径 500 次：48,000 → 17,000 次分配；10,389,000 → 1,977,856 字节分配请求。
- 快速 100 ms 路径 5,000 次：315,000 → **0** 次分配；92,450,000 → **0** 字节分配请求。

这些是构造、序列化和缓存交接的分配计数，不是整进程 CPU 百分比。没有通过降低刷新频率换取结果。
