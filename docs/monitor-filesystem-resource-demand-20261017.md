# 统一数据层按需采集文件系统速率 · 2026-10-17

## 最终行为

内部顶部栏和自动功耗明确登记 `fileSystem:false`。只有它们需要 top 数据时，唯一 native 采集循环保持现有 CPU、温度、电池等数据，关闭并跳过文件系统 PDH 查询。自定义监控或真实预览选中 diskRead/diskWrite 时，通过原有统一需求登记取并集恢复查询；最后一个磁盘消费者退出后，只关闭该补充采集，不停止其他 top/fps 消费者。

该项改变的是是否需要执行补充工作，保持已有采集节拍、Windows FileSystem 计数器来源和传感器有效性。CPU 核心图块的进一步按需构造不属于本轮实现。

## 原有接口的可选提示

仍使用 `monitor.start` / `monitor.stop` / `monitor.snapshot`。`monitor.start` 对 top 请求可带布尔 `fileSystem`；未指定保持完整旧行为。新调用不关闭 HWiNFO Presented FPS，不新增入口、线程或硬件读取器。

`fileSystemActive` 为可选的原生模式读回，仅表示该补充采集已被配置请求，不能当作速率数据有效。实际数据仍以 `fileSystemTs`、来源和速率值证明。未经提示的旧调用保留原有快照字段形状。

统一 hub 合并所有 owner 的需求，记录已确认和结果未知的配置；需求改变、回执丢失、读回延迟、新会话及预算退避均沿用当前生命周期。旧 native 忽略新提示时仍提供完整数据，不触发每秒重启。
