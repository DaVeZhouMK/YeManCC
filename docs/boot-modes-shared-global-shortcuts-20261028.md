# 四模式与普通全局快捷键（2026-10-28）

用户澄清：用户一直操作的是普通全局配置。开机模式只有名称直接对应的 Windows／Xbox／Steam 启动准备是固定操作；其他项目未选择独立设置时共用普通全局，模式编辑不能回写全局。模式选择不要求再进入编辑器保存一次。

## 本轮已落地的快捷键链路

普通手柄页的快捷动作编辑器和卡片开关均以 `input.buttonMapping.rules.shortcutRules` 为唯一全局列表，沿用统一配置文件及原输入 CAS。存在独立模式快捷键时，普通页面仍编辑全局列表。

不再把 `extensions.bootModes.global.controller` 当全局来源。普通配置规范化与原生原子写入边界都会移除此旧字段；首次发现时只保存一份 `extensions.bootModeGlobalShortcutsBackup`，后续写入不替换、不累加，也不读取备份作为配置。无旧字段时不会凭设备状态生成旧快照。

模式独立快捷键的已应用输出放入 `input.bootModeShortcuts`，包含模式、Windows 启动标识及规则。它不会替换普通全局列表。原生快捷键解析器与普通页面同步原生默认开关时都使用同一优先关系：本次启动有效的独立覆盖优先，否则使用普通全局。新的 Windows 启动不能沿用旧启动覆盖；跟随全局的模式应用时将覆盖置空。

普通快捷键保存即写全局，不以额外选项决定是否进入全局。空列表有初始化标记，避免主动删除后重新补回旧的默认动作。保存失败或过期 CAS 不修改文件。

## 编辑器边界

跟随全局的模式项目只读，选择“模式单独设置”后才写对应 scene 的 overrides。全局快捷键在普通手柄页编辑，开机编辑器的全局快捷键只读。独立项目切回跟随后把旧独立值保存在 rememberedOverrides，暂停应用；再次选择独立设置或重新打开编辑器后仍可取回。该记忆机制覆盖原有 17 类模块，不作为全局来源。

## 范围与尚未完成的整体工作

本轮实现和新断言针对快捷键共享、旧快捷键全局快照退役、独立覆盖与四模式切换。原生改动只涉及配置写入时退役旧字段和快捷键读取选择；不修改虚拟设备实现。

其他非快捷键模块仍沿用原有 bootModes.global／各功能保存链路，原有 SteamDeck、触摸板及音质推荐场景和历史迁移没有在本轮全部重构。不能把本轮结果描述为“所有普通配置均已完成统一全局重构”。用户最新提出的整体原则对这些模块同样有效；后续必须按各模块明确的普通保存入口接通，不能用实时设备采集回填共享设置，也不能靠另一份冻结快照覆盖用户的普通修改。

Windows 主应用、EarlyStart、注册表与启动 BAT 的固定模式处理保持原有实现；本轮没有操作本机服务、注册表、Steam／Xbox、安装版配置或物理设备，没有制作安装包。
