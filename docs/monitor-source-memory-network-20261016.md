# 统一采集源：内存/网络与按需最大值（2026-10-16）

本轮目标是从统一采集源减少每轮固定工作，并修正合法传感器编号被截断的问题。变化直接位于 native/monitor_memory_network.h 与 native/main.cpp 的现有 HWiNFO 解析器，没有通过日志回放替换实时数据、添加消费者采集或调整显示动画来掩盖成本。

## 证据与阶段状态

上一轮 AMD 专用优先、共享回退、高编号 D3D 与不可变数值载荷复用已经落入主线；本轮启动时已核对当前源码及上一轮 ROUND-RESULT.json。上一目标轮属于 progress。

继续分析同一源解析器发现：

- RAM/网络仍以传感器编号直接索引 256 项表，导致合法编号 256、300、4095 的数据消失；D3D 的修正没有自动覆盖它们。
- 每次解析完整初始化 256 组 RAM/GPU/网络对象，结尾再完整访问 256 组；本机典型输入只需少量组。
- 每一传感器行都读取历史最大值并做有限性校验，实际仅两种温控标志使用最大值。

这些由源码检查与冻结前后实际解析器的故障输入确认，无需等新日志发现。

## 源头改变

### 实际组存储与所有者选择

Readings 改用最多 256 项稀疏存储，原始编号为键；插入时初始化该组，结束时访问实际组数。查找使用固定 512 槽索引、最高 50% 占用及最近组捷径，逐轮只清理 64 字节占用位；索引和数据槽仅在占用位有效后读取。探测有 512 步上限。Group 类型由编译期断言保证平凡默认构造和复制，避免后来又引入隐含整表初始化。编号上限沿用已有 GPU/D3D 规则 0–4095，并受本份 HWiNFO 头部声明的 sensorCount 限制。未声明编号不会生成 RAM、网络或 D3D 读数；计数先以 64 位钳制再转换，避免宽值截断。

所有者选择明确写入 GroupSelection，保持原来升序全表访问的规则：RAM 选最低有效编号；GPU 优先级相同选较低编号；网卡按同组上下行之和选择，流量相同选较低编号。网卡上下行来自同一组，不累加 VPN/物理适配器、不跨组补齐。最后一个合法重复读数仍然生效，无效值不抹掉已知值，真实零保留。

### 容量上限与极端恢复

超过 256 个不同有效 RAM/网络组时保留窗口位图。仅此时，复用当前已经复制的原始行，按实际存在的编号窗口恢复，每个窗口最多 256 个编号，共最多 16 个窗口。重新使用同一固定表，无新硬件读、线程、进程、定时器或动态容器；恢复只处理内存/网络，不改变 D3D 诊断载荷或 GPU 候选集。

常规情况没有恢复遍历。极端夹具包含全部 4096 个有效网络组，当前输出保留最高流量组，并明确验证 16×4096=65536 次恢复行访问。这个路径有额外 CPU 工作，不能称为所有输入都更省；代价用于修正以前静默漏数的极端情况，并保持内存上限。

MSVC x64 下原组槽位为 88 字节，当前含原始键的槽位为 96 字节，256 项槽区增加 2048 字节；另有 1024 字节索引槽、64 字节占用位及固定计数/标志。实测 sizeof(Readings) 从 28704 变为 31864 字节，增加 3160 字节，选择摘要另为固定大小。D3D 仍沿用上一轮固定槽和最多 64 项恢复暂存。没有将表扩大为 4096 份完整元组，也没有无界缓存。源采集大夹具使用默认栈编译运行通过。

### 历史最大值只按用途读取

每行仍读取其当前值。历史最大值的读取及有限性检查移至 Core Thermal Throttling / Thermal Throttling (HTC) 且单位 Yes/No 的分支内。温控历史告警行为保留，包括 0、1、负数、NaN、无穷；其余传感器不再做这次无用的读取/校验。

### 既有节流和有效期

当前 nativeMonitorLoop 的统一硬件读取位于外层普通节奏；RTSS 快帧分支不调用 HWiNFO 全解析。两个消费者都关闭时，现有线程在模式条件变量上等待。本轮保留这些已有机制，生命周期回归确认消费关闭后清除剩余显示/重试计时器。这里的停采指 YMCC 的消费者链，不等于关闭 HWiNFO 软件自身。

未仅凭秒级 pollTime 相等就跳过读取/解析：单一时间戳不能证明原始行、设备身份与布局没有变化。以后若增加源数据复用，必须同时证明内容、身份、代际及原始有效期，不能给旧观测盖上新时间。

## 首次失败及处理

历史完整解析回归在第 41 个比较处出现 physicalMemoryUsedMb 12.5→null。保留了首次编译日志、原生成 C++ 及 PARSER-DIFF.json，确认夹具声明 32 个传感器，却随机生成 0–39 编号；新源码拒绝未声明编号是预期变化。

测试生成器改为声明 40 个传感器，保持全部 2000 组随机数据和值比较断言；独立新夹具明确覆盖未声明编号必须未知。二次遍历计数由替换首个循环更新为覆盖全部同类循环，避免新增恢复路径漏计。修正后历史回归通过，没有把值比较放宽为仅部分字段，也没有恢复非法源数据。

最初编译还指出 64 位头部计数传入 32 位参数的缩窄，已改成先 64 位钳制再转换；源代码 warning 随后消除。没有调高栈或放宽生产数据范围。

## 显存容量仍未闭合

重新对照旧日志确认 Win5/ROG 的 DXGI 适配器容量确实读出，但同名同容量下存在多个不同 LUID；ROG 枚举在另一个 LUID 处失败。设置通道整体失败不表示前面读出的容量无效，但目前没有证明它们与所选 HWiNFO GPU 和内存池的对应关系，也没有可供监控长期复用且带失效边界的容量快照。

本轮没有把独立设置查询塞入每秒监控，也没有制造显存百分比。AMD 专用/共享规则继续生效，容量与占比仍列待解项。
