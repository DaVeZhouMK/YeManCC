# 监控快照高频边界复核与会话交接修复（2026-10-16）

监控继续只消费 YMCC 统一数据层。本轮复核快照高频路由和体积上限，并修复生产读取末端的旧会话返回问题。生产改动仅在 `src/bridge/monitorData.ts`；没有修改采集端、界面、采样周期或原生线程。

## 已复核的高频与体积约束

- 内存快照和 HUD 快速发布保留现有高频路径。`monitor.snapshot` 不进入通用慢异步 IPC 队列；实际提取的路由函数在四种既有模式下共 8 个断言通过。
- 诊断记录进入 `monitor-detail.log`，标记 `lane=high-frequency`，不进入低频生命周期记录。沿用异步日志池；诊断的每秒取样预算不改变 HUD 的快速发布频率。
- top/FPS 各最多 16 KiB，内层文本合计最多 24 KiB。原生缓存、兼容文件提交和前端解析前都有限制；UTF-8 多字节输入也按字节检查。
- 单条诊断记录最多 32 KiB；待写队列最多 256 KiB 且最多 16 条，计入写出中的条目；文件最多 2 MiB，保留当前与一份轮转文件。
- JSON 超限整路丢弃，不截断。快速组合超限优先保留 FPS。被拒绝的大包不能推进会话、代际、序号或确认待启动命令。

原生发布实际执行夹具 21 个当前场景全部通过，并复现冻结旧版本的边界负例；诊断队列/文件实际执行夹具 48 项通过；前端字节预算 21 组通过；快速发布 gate 8 项及高频接线 12 项通过。这些检查不等于已安装程序的实机验收。

## 修复前实际复现

使用原生产模块、mock IPC 与虚拟时钟，在一次读取已经解析/复制而公开 Promise 尚未返回时，投递会话 2：

| 观测 | 修复前 | 修复后 |
| --- | --- | --- |
| 两路显示 | 会话 2 / 45W | 会话 2 / 45W |
| 旧读取返回 | 会话 1 / 30W | null（不可用） |

旧的 publicationVersion 保护了显示端，但没有保护控制返回值。会话切换会清空墙钟 stop floor，因此仅重新执行 stop 过滤仍会放过旧读数。这里的 30W/45W 是刻意区分会话的合成输入，不能当作本机当前测量。

## 最小修正

在现有 stopFloorRevision 中记录最近一次真实会话更换的版本。私有读取回执仍使用原来的源版本：若源早于会话更换，完成函数返回专用的 null 结果，公开读取停止返回旧数据，也不覆盖新会话的显示。

同一检查还在显示回调后执行，覆盖回调中换会话及并发读者。首次发现会话号不算更换；同会话 seq/generation 推进、等价需求替换、额外 owner 均不会误伤有效读取。错误、超限和非法时间/序号的新会话包仍须先通过原有校验，不因携带另一会话号而使旧数据退休。

没有用新读数冒充旧请求结果，没有加重读、定时器、线程或轮询，也没有扩大 public hub 接口。
