# 帧输出基础节点复用与时钟空缓存修复

日期：2026-10-17，Asia/Hong_Kong。本轮修改主线 `native/monitor_frame_output.h`，没有部署本机、重启应用或游戏、修改 HWiNFO 配置或新增采集器。

## 已复现并修复的旧异常

在实际冻结生产 Output 上，只需以下三步即可触发：

1. 生产时间 T 有一个有效 Presented FPS 包，正常读取。
2. 读取时钟回退到 T−1000ms，正确撤回尚在未来的观测，缓存变成 null。
3. 时钟回到 T，没有新的硬件修订；旧代码跳过重建并对 null 调用 `value()`，抛出 `json.exception.type_error.306`。

原始复现见任务证据 `clock-before-probe/RESULT.json`；优化前候选也复现，证明不是此次节点复用造成。本轮将“缓存为空”纳入基础包重建条件。恢复包保持原观测时间、原失效时间和完整类型/数值；原失效边界仍返回不可用，不借修复延长健康或 FPS 证明。

这是受控时钟输入下的生产类复现，不声称已证明用户某次现场闪烁的唯一原因。

## 重复构造优化

旧路径在普通硬件修订、时钟回退和 RTSS 来源切换时，通过整棵 JSON 复制重建基础对象。本轮复用现有有序 map 节点，线性合并键，删除基础包中不存在的键，仅补入缺失节点。相同字符串继续使用原存储，其他值直接复制，保留整数/浮点类型、正负零以及未来复合字段的完整语义。没有新增成员缓存或时间调度，Output 对象大小仍为 2520 字节。

初版候选曾尝试用数值相等跳过所有更新，负零用例证明这会改变序列化字节。该候选未合入，最终仅跳过相同字符串，负零及完整类型回归通过。
