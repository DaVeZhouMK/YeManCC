# GPU 有效前缀复制：统一采集与缓存交接优化（2026-10-16）

本轮开始时核对 gpu-active-slots-20261016/ROUND-RESULT.json 及当前源码，上一目标轮分类为 progress。上一轮已经减少未用 GPU 的默认初始化；本轮继续减少包复制中的固定工作量，长期数据/CPU 优化目标保持 active。

## 源头修改

既有 Readings 默认复制/移动会复制固定的 64 个 Slot。每个 Slot 240 字节，整数组 15360 字节；即使只有两张 GPU 或当前没有有效 GPU，reader 的 out=candidate、源复用的 commit/restore 仍会带上整个数组。

在 native/monitor_gpu_selection.h 中为 Readings 增加明确的 noexcept 复制/移动构造与赋值：只通过平凡 union 赋值复制 count_ 内的有效前缀，同时复制 count_、lastSlot_、lastIndex_ 并按原语义复制/移动 D3D shared_ptr。满 64 张时保留整个数组赋值。没有增加动态容器、硬件读取、日志、线程或定时器。

缩小后的目标可能保留前缀以外的旧平凡值，但它们不再可见。所有查找、选择、诊断和输出依旧受 count_ 限制；后来接纳的新 GPU 仍通过 placement new 完整初始化 Device，不能继承旧槽位的功率/频率/显存等字段。自复制、自移动被显式保护，移动后的源仍可查询、重置和重用。

固定存储容量和包体积没有下降：sizeof(NativeMonitorHw)=15840，sizeof(Readings)=15400，均与本轮冻结旧版本相同。原有 nothrow 包复制约束及 Device/Slot 平凡复制/析构的编译期约束继续成立。D3D 证据本身、引用计数、快照其他字段、源映射/分类/发布仍有原有工作量。

## 复制范围证据

新 tools/monitor_gpu_active_copy_selftest.mjs 复用上一轮的原生生命周期/数值语料，并对旧/新 GPU 头加上同样的仅测试访问方法。方法只允许写未用 Slot 的对象字节、读取未用 Slot 中的指定字节数量，不改变类型布局、复制/移动运算符或 Device 生命周期规则。
