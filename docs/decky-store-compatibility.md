# Decky 商店兼容与 YMCC 整包更新

记录日期：2026-10-18。本轮产物为本地配套测试版，未发布远端，也未替换当前运行中的 YMCC / Steam 界面。

## 已修复的路径

- 真实 v3.2.10 官方目录请求收到 426 纯文本时，旧代码误按 JSON 解析。现在只针对官方默认/测试源的明确版本拒绝协商公开只读目录，保留真实 Loader 版本；自定义源不绕过版本要求。请求、读体、取消、结构与 hash 都有验证，5 分钟后重新协商。
- 商店搜索忽略空白、大小写与 NFKC；六种排序方向一致；版本以名称和 hash 绑定。更新检查采用紧凑 `/plugins/versions`，失败保留可靠的上次结果，拒绝过时的安装/设置快照。
- 同一 `/decky/store` 使用实际 Steam 原生控件和原 Decky 安装后端。单项安装必须收到新的 import 事件，并在插件列表发现目标版本，才确认成功；正常请求回执不等于安装完成。取消、超时、失败可见，安装不自动重放。
- 旧插件设置中的“重新安装”保留了旧函数引用。新增 `deckyLegacyStore.ts`，只适配真实 3.2 Loader 发往匹配官方源的两个只读目录请求，恢复原 tuple 字典；无关请求、显式自定义源、其他 fetch 所有者均保留。

## 更新入口现在实际执行什么

`deckyLoaderUpdate.tsx` 的实际 `LoaderUpdateRow` 已连接 YMCC 整包更新，不再把上游发行版本查询作为更新功能。原“通用 → 更新”的位置使用 Steam Field / 按钮显示：

1. 检查兼容更新：调用现有 `updateManager.checkForUpdate(APP_VERSION)`。
2. 下载兼容更新：调用现有 `prepareUpdate()`，采用 YMCC 自身正式 version.json / YeManCC.zip、hash 校验和续传能力。
3. 安装并重启 YMCC：弹出独立确认框，绑定具体版本和 SHA256；确认后调用现有 `downloadAndInstall()`。没有重新实现安装器。

桥接通过原有认证回环镜像，新增 `updater.status` / `updater.request` 和 `updaterProtocol:1`。主端 `deckyUpdaterHost.ts` 是现有更新管理器的适配层；`deckyUpdaterService.ts` 验证连接、请求 ID、目标版本/hash、下载完成状态、游戏与电源状态。重复请求只重发回执；断线/渲染器重建只刷新状态，不重放下载安装。

旧主端未声明能力时明确提示需要新版 YMCC，不假装可以更新。游戏运行时允许下载，安装需退出游戏并通过现有主端复核。原版 Loader 直接上游覆盖入口在插件接管期间保持停用，以保留 Windows 修复。原位 Field 的原生 Focus Context、退役节点导航屏蔽、A/B 及卸载所有权恢复沿用原实现。

`LoaderVersionInformation` 只保留为版本信息解析回归对象，不是实际更新行。Loader 本身仍为锁定的 Windows 修复二进制：`714444cdcf385c478e69124724a5573c2f1759078b496c3e20e6e04e525e2518`。
