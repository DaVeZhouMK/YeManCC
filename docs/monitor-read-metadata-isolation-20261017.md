## 已复现的问题

真实生产单例会合并在途 `monitor.snapshot` 读取，并为各控制读取者复制快照、top、FPS 外壳，继续共享解析器拥有的冻结核心及帧时间数组。六个历史兼容字段允许保留非常规对象或数组。它们虽然不能进入解析模板缓存，却仍会通过浅复制在同一批读取者和显示源之间共享。修改一个读取结果的嵌套字段，会污染其他读取结果和监控预览。

冻结前置源码 SHA-256：`7251cdeff9deb561f672c05b3f25e06f3f34b0b166177ab27a369cf1e992d6ca`。原始复现 `BEFORE-REPRO.json` 中只有一次原生读取，第二读取者却看到了第一个读取者写入的 99。

## 修复方式和开销边界

解析时沿用原有六字段检查，仅为含对象的异常旧格式包保存一个弱键到原始 JSON 的关联。缓存准入沿用“异常包不缓存”的规则。生产读取复制时，正常包保留冻结数组共享；异常包才重新解析已准入的原始 JSON，替换六字段中实际为对象的部分。这样各控制读取者与显示源互不污染，外壳上已经应用的停止/硬件失效处理仍保留。

关联由 WeakMap 持有，键失去引用即可回收，不增加常驻强缓存、轮询、定时器、硬件读取或其他 EXE。异常包按既有准入体积受限。正常路径新增弱表查询，没有增加深复制和数组复制；不能把操作计数称为整机 CPU 降幅。

不用 structuredClone 深复制异常 FPS 的原因是：准入的 JSON 可以在 16KiB 范围内达到数千层。回归覆盖 2500 层、15656 字节的输入，隔离后仍可读；保留历史字段值和类型，不为了优化擅自丢弃旧字段。
