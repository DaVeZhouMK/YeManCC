# YeManCC 核心安装器（2026-11-12）

## 独立卸载与维护（试验版）

- 安装成功后登记 Windows「已安装的应用」，卸载器放在 `%ProgramFiles%\YeManCC Maintenance`，不依赖 `C:\SOFT\YeMan` 仍存在。绿色版不强行注册。保留个人数据、共享驱动和运行库，不增删 Defender 排除项。
- 程序清单和原值记录分开。单项记录损坏、当前值被改过、旧版未记录原值，均只报告该项。清单损坏时仍用卸载器内的固定包清单清除可确认的程序文件。先验证系统已切到平衡，再删除固定野蛮电源方案；失败不挡住程序卸载。
- 微星原任务 XML、Steam `.earlystart`、`EarlyStartService` 原启动类型、Xbox 大屏、Game Bar、OEM 外形与 GPU 调度按已知所有权还原。没有实际原值证据时不猜测；微星已重建的任务不覆盖。更新保留同一项的首个原值。还原项可由新版卸载器扩展，但只接纳受保护的本机证据，不接受带任意路径、命令或伪造原值的包内数据。
- 可用 `-MaintenancePublicKey` 在安装器预置发布公钥（仅公钥，RSA 最少 2048 位）。更新核心 ZIP 可选附加 `YeManCC/YeManCC-Maintenance-Update.zip`；不要放在 ZIP 顶层，也不会复制到运行目录。附件必须恰好包含 `release.json`、`release.sig`、`YeManCC-Uninstall.exe`。清单为 `Schema:1`、`Product:"YeManCC.Uninstaller"`、四段 `Version`、`Sha256`；签名覆盖清单原始 UTF-8 字节，RSA PKCS#1 SHA-256。YMCC 主程序提交成功后才交给独立维护程序，后者只更新到更高版本，且 EXE 版本须与签名清单一致。普通便携目录不能提供执行信任；没预置公钥、不通过验证、或维护操作冲突时保留原入口。

目标、管理员授权、包内身份、关键文件写入和事务恢复仍校验。不绕过安全策略、不强行写入失效的卷或链接目标、不忽略损坏的安装记录。`--preview` 和 `--preview-offline` 分别检查界面，均不能安装；`--validate` 只展开真实资源。真正的断网实装和设备行为仍需在 VM 或目标机确认。

## 固定目录、Defender 与事务保护

YMCC / PowerControl 并列。经源码盘点，启动、输入、风扇、调度和资料仍有多处固定路径依赖，因此当前明确锁定 `C:\SOFT\YeMan`，不提供浏览或地址编辑，不创建自定义位置联接。H5 消息、提权接续计划及执行器均拒绝其他根目录；原来可自定义目录的版本保留在历史证据中。固定位置已有可识别版本时允许更新；Demo、视频等不在包内的既有文件可共存，按文件保留。HWiNFO/RTSS 使用标准 Program Files 位置。

默认安装通过 Windows 官方 `root\Microsoft\Windows\Defender:MSFT_MpPreference` 的 Add/Remove 接口处理 ExclusionPath，并使用微软签名的 MpCmdRun -CheckExclusion 核验有效性。仅保留 7 个明确的完整文件路径：YMCC 主程序、恢复服务、风扇宿主、输入宿主、灯效宿主、功耗控制器和绿色启动器。为防止安装展开时先被处理，同一批包内 6 个核心文件的展开路径与 7 个原子复制路径仅在安装期间临时加入，结束/失败撤销。临时复制名由操作目录与目标路径共同派生，写入器与排除项共用同一函数，不扩大为目录排除。不排除文件夹、磁盘、通用进程、扩展名或第三方程序，不改实时防护或防篡改。

资源 ZIP 身份核验在排除项修改前完成；先读完基线、持久记录意图，再执行每项添加。原有精确/广义排除项保留，仅撤销本次记录的新项；失败或中断恢复也会处理排除项日志。策略、权限、有效性失败明确记录为 warning 或 cleanup-required，不能声称已排除。第三方杀软不自动管理；未选择该选项时完全不调用 Defender。完成页显示本次 Defender 结果。后续可在 Windows 安全中心按记录移除新增项。

安装器及 YMCC 尚未签名，排除项只能在安装器获准运行并获得管理员权限后设置，不能处理安装器运行前的启动信誉拦截。不会解除阻止标记、关闭 SmartScreen、恢复隔离文件或绕过组织策略。首次安装保留用户确认/UAC；本机开发只验证实现和真实 UI，不执行白名单修改。

`build.ps1` 只读指定本地资源和本机 HWiNFO EXE，先固定安装器源码，再生成资源清单并调用 `Compile-Setup.ps1`。WebView2 SDK 使用仓库已有的必要三个二进制及许可。已压缩资源的外层 ZIP 使用 NoCompression，避免重复压缩导致体积膨胀。构建记录包含所有源字节、资源/安装器身份和 HWiNFO 来源。

`--validate <新隔离目录>` 实际展开并校验八项资源，不运行它们。构建输出及证据均在仓库外；历史 EXE、预览和失败证据保持原样。

## 安装链健壮性（核心 2026.11.12.4）

实际执行器增加内部 OS 边界 `InstallPlatform`，公开产品始终使用默认实现。仅诊断程序集可显式提供隔离根与惰性系统接口，不新增产品参数、安装位置入口或全局发布夹具。

完成前通过 `FileTransaction.VerifyApplied` 重核所有写入/同字节复用文件的 SHA256，辅助 DLL、宿主或启动器缺失均不能算完成。完成标记最后写入。微软运行库前后仍按实际检测判断可用性；非零返回但已满足环境的并发安装结果可复用，返回 3010 但未可用时写 `blocked-reboot`，提示用户重启后重开，不伪报 YMCC 完成。WebView2 用实际 SDK Runtime Discovery 探测，并在启动补装前再查一次，避免只信注册表或重复补装；界面创建失败仍保留真实错误，不能宣称发现版本就等于界面可用。

资源展开前与系统改动前检查空间，运行库准备后复核目录/进程占用。首次安装拒绝同名根文件、已有设置/完成记录及未识别安装记录；根目录中的非交付文件保留，不因已有 Demo 或视频而禁用安装。正常回滚后留下的空目录允许重试。文件枚举在进入子目录前拒绝重解析点。恢复预先核对每个目标只能属于本安装目录、HW/RTSS 或本快捷方式；某个文件冲突不会阻止其他文件恢复和排除项清理，冲突保留为 repair-required。

进度接收异常不再破坏事务；运行库仍在执行时，进度/日志异常不会让主程序提前离开等待。失败清理不再依赖可成功写日志，无法保存最终记录时明确为 repair-required。原子 JSON 记录使用 Flush(true)，且写失败时清理自有临时记录文件。成功回滚后的大临时资源及时清理，备份/结果日志保留。进程崩溃只留下空操作目录可自动回收；非空且缺状态仍拒绝并保留现场。

本轮以旧版实际消费者复现 3 项失败，并用实际 Engine/文件事务配合显式惰性运行库/Defender 接口执行 55 个隔离场景，再用 3 个单一语义回退证明测试会拒绝坏实现。公开问题只作场景来源，不冒称 YMCC 用户现场或实机通过；原始失败、来源、工具身份和范围见 `Testing/YMCC/Evidence/Installer-Core-20261107/Robustness-20261112`。

## 中断恢复与文件事务后继

检测到受保护的未完成事务时，第二页可“恢复并继续”，不再由残留目录的首次安装检查提前拦住。普通权限无法读取受保护的旧记录时，只允许进入管理员检查；执行器仍核对记录、目标、备份和事务日志。恢复使版本变化时，回到同一确认页显示实际恢复后的版本，用户确认后才开始新的安装。缺失文件事务日志不能记为恢复成功。

备份和写入暂存先 Flush(true)，回滚复用记录中的同目录暂存文件，经校验后原子替换，不原地截断旧程序。提交前再次比较目标和备份散列，拒绝复制期间发生的外部改动。只对当前事务明确管理的只读目标暂时解除只读；原属性进入日志，回滚恢复属性。用户配置保留规则继续有效。

环境读取分项隔离异常。某项权限/注册表读取出错时显示“检测失败”，保留其他真实检测结果和界面导航；管理员安装阶段仍重新检查必要环境，未知不能当作已就绪。

## 运行库就绪检查后继

.NET 检测核对最新稳定 10.x 桌面框架声明、配套 .NETCore、hostfxr 和 dotnet 主机；核心原生文件必须为 x64，关键托管组件必须有有效 PE 头。最高补丁目录不完整时不把较低补丁冒报为就绪。

关键托管组件额外通过 AssemblyName.GetAssemblyName 只读取得程序集身份，名称必须与所需组件一致，处理器架构只接受 MSIL 或 AMD64；原生 DLL、其他托管程序集及要求 x86 的同名程序集均不能冒充就绪。这个元数据检查不执行被检查的程序集。

手柄读取检查 XInput 的四个槽位，优先选择有 A/B/X 或方向键输入的手柄，再选择左摇杆超出原 18000 阈值的手柄；全部空闲时保留第一个已连接状态。空闲的首槽位不再遮挡后续手柄。每次最多读取四个槽位，首个有效按键仍立即返回，不合并不同手柄的状态；缺 WebView2 的引导窗与 H5 向导共用该逻辑。

VC++ 就绪检查使用实际系统 DLL 的 PE 架构与版本，x64/x86 分别核对；过期或损坏的安装注册表不再遮蔽已经满足要求的 DLL。注册表保留用于选择安装或修复，不作为已就绪的唯一依据。

同包版本已有残留或损坏时选择 `/repair /quiet /norestart`，新装或较低版本选择安装；较高版本损坏则明确要求修复对应版本，不用较低包覆盖。执行后的实际就绪检查和重启等待规则继续保持。以上软件检测/参数选择验证不等于已在干净机器实际执行了运行库修复。
